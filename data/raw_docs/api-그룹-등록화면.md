# API 그룹(SPC) 등록 화면

"API 그룹"은 이 시스템에서 **SPC(Specification, 규격)** 라고 부르는 단위입니다. 개별
API(Method+Path) 여러 개를 묶는 상자이고, 호스트·기본경로·버전 같은 공통 정보를
이 단위에서 한 번만 정합니다.

## 화면 주소

| 기능 | URL |
|---|---|
| 그룹 등록 화면 | `/apidev/api/spcreg/mvSpcReg.do` |
| 시스템-그룹 트리 조회 | `/apidev/api/spcreg/selSysSpcTreeAjax.do` |
| 그룹 저장 | `/apidev/api/spcreg/savSpcRegAjax.do` |

## 화면 구성

화면은 좌우 2단입니다.

- **왼쪽 트리** — 내가 접근할 수 있는 **시스템(System)** 과 그 아래 **그룹(SPC)** 이
  트리로 표시됩니다. 시스템을 펼치면 그 시스템에 등록된 그룹들이 나오고, 그룹을 클릭하면
  오른쪽 폼에 그 그룹의 값이 채워지며 수정 모드로 바뀝니다.
- **오른쪽 입력 폼** — 그룹의 기본 정보를 입력합니다.

트리는 화면을 열 때 한 번, 그리고 저장에 성공할 때마다 다시 그려집니다. 방금 만든
그룹이 트리에 바로 보이지 않으면 저장이 실패했을 가능성이 큽니다.

## 입력 항목

| 항목 | 필드 | 필수 | 설명 |
|---|---|---|---|
| 시스템 | `sysId` | O | 이 그룹이 속할 시스템. 내 권한 범위 안의 시스템만 선택됩니다 |
| 그룹 ID | `apiSpcId` | O | 영문·숫자 조합의 식별자. 중복 불가 |
| 그룹 이름 | `apiNm` | O | 목록과 규격서에 노출되는 이름 |
| 버전 | `ver` | O | 예: `v1.0`. 같은 그룹의 다른 버전은 별도 그룹으로 관리 |
| 설명 | `apiDesc` | X | 그룹 소개 문구 |
| 호스트 | `host` | O | 예: `api.kt.com` |
| 기본 경로 | `basPath` | O | 예: `/message/v1.0`. 개별 API의 Path는 이 뒤에 붙습니다 |
| 권한그룹 | `autId` | O | 이 그룹의 API를 호출할 수 있는 권한그룹 |
| 참조 WSDL | `rfrnWsdlUrl` | X | SOAP 규격을 참조해 만들 때만 |
| 템플릿 여부 | `tmpltYn` | X | `Y`면 이 그룹을 템플릿으로도 쓸 수 있습니다 |

**호스트 + 기본경로 + Path** 가 합쳐져 최종 호출 주소가 됩니다. 예를 들어 호스트가
`api.kt.com`, 기본경로가 `/message/v1.0`, API Path가 `/send` 라면 실제 주소는
`https://api.kt.com/message/v1.0/send` 입니다.

## 저장 이후 흐름

그룹을 저장하면 **자동으로 API 등록 화면으로 넘어갑니다.** 새로 만들어진 그룹번호
(`apiSpcNo`)가 주소에 실려서 `/apidev/api/spcreg/def/mvApiDefReg.do?apiSpcNo={그룹번호}`
로 이동합니다. 즉 "그룹을 만들었으면 이제 그 안에 API를 넣으라"는 흐름입니다.

기존 그룹을 수정한 경우엔 화면에 남아 있고, 트리의 그룹명만 갱신됩니다.

## 등록 상태 코드

그룹과 API는 공통코드 체계의 등록상태(`REG_STTUS_CD`)를 갖습니다.

| 코드 | 의미 |
|---|---|
| `APIREG1000` | 작성 중(임시 저장) |
| `APIREG1010` | 등록 완료(검토 대기) |
| `APIREG1020` | 검토/승인 진행 |
| `APIREG1030` | 공개(서비스 중) |

검색 화면이나 규격서 조회에 노출되는 것은 **`APIREG1030` 상태뿐**입니다. 등록했는데
검색에 안 나온다면 상태가 아직 공개 전인 경우가 대부분입니다.

## 자주 묻는 질문

**Q. 그룹과 API의 차이가 무엇인가요?**
A. 그룹은 상자, API는 그 안에 담기는 개별 호출입니다. `POST /messages`, `GET /messages`
처럼 같은 서비스의 여러 호출을 그룹 하나로 묶습니다. 호스트·기본경로처럼 공통인 값은
그룹에만 적고, API마다 반복 입력하지 않습니다.

**Q. 그룹 ID를 나중에 바꿀 수 있나요?**
A. 이미 API가 등록되었거나 배포된 그룹은 ID 변경을 권하지 않습니다. 규격서 주소와
게이트웨이 라우팅이 그 ID를 참조하기 때문입니다. 꼭 필요하면 새 그룹을 만들어
이관하세요.

**Q. 버전을 올리고 싶습니다.**
A. 같은 그룹의 값을 고치는 대신 새 버전 그룹을 만듭니다. `v1.0` 과 `v2.0` 은 별개
그룹으로 관리하고, 기본경로에 버전을 포함시키는 방식이 일반적입니다.

**Q. 시스템 목록에 우리 시스템이 안 보입니다.**
A. 계정에 그 시스템에 대한 권한이 없기 때문입니다. 마이페이지에서 해당 시스템의
권한그룹을 신청하고 승인을 받아야 트리에 나타납니다.

**Q. 그룹을 삭제하고 싶습니다.**
A. 화면에는 그룹 자체를 지우는 버튼이 없습니다. 사용하지 않는 그룹은 사용여부를 `N`
으로 내리거나, 운영자에게 정리를 요청합니다. 이미 배포된 그룹은 게이트웨이에서 먼저
내려야 합니다.
