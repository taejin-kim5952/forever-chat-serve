# API 등록 화면 - 입력 항목 하나하나 상세 설명

이 문서는 "API 등록" 화면([[api-등록]] 참고)에서 입력하는 각 항목을 하나씩 자세히
설명합니다. (테스트용 문서이며 일부 수치·예시는 실제 값과 다를 수 있습니다.)

## 기본 정보 항목

### API 이름
- **설명**: 이 API를 대표하는 이름으로, API 목록과 규격서(스펙 문서)에 그대로 노출됩니다.
- **입력 형식**: 한글/영문 최대 100자.
- **예시**: `사용자 메시지 조회`, `getUserMessage`
- **주의사항**: 같은 그룹 안에서는 이름이 중복되지 않아야 하며, 중복 시 저장 시점에 경고
  팝업이 뜹니다.

### 권한그룹 (API 호출 권한그룹 / Auth Group)

> ⚠️ **이름이 같은 다른 항목과 혼동하지 마세요.**
> 여기서 고르는 권한그룹은 **"이 API를 누가 호출할 수 있는가"**를 정하는 값입니다.
> MY 페이지 > [권한요청] 화면에서 고르는 권한그룹(개발자그룹/관리자그룹/운영자그룹)은
> **"내가 이 시스템에서 무슨 역할인가"**를 뜻하는 전혀 다른 항목입니다
> ([[API등록-기능별상세가이드]]의 "서비스 사용 권한 신청하기" 참고).
> 이 화면에서는 **개발자그룹 같은 사용자 역할 그룹을 고르는 것이 아닙니다.**

- **설명**: 이 API를 호출할 수 있는 권한그룹(Auth Group)을 선택합니다. 선택한 권한그룹에
  속한 사용자/시스템만 이 API를 호출할 수 있습니다.
- **입력 형식**: 드롭다운 선택. 미리 등록된 권한그룹 목록에서 고릅니다.
- **기본값**: 없음(필수 선택).
- **선택 기준**: 이 API를 호출할 주체(연동 대상 시스템·서비스)를 기준으로 고릅니다.
  본인의 직무나 역할과는 관계가 없습니다.
- **주의사항**: 권한그룹을 잘못 선택하면 실제 호출 시 인가 오류(403)가 발생할 수 있습니다.

### Path
- **설명**: API의 요청 경로입니다. 그룹(SPC)에서 정한 기본경로 뒤에 붙는 부분만 입력합니다.
- **입력 형식**: `/`로 시작하는 문자열. 예: `/messages`, `/messages/{id}`
- **경로 변수**: `{}`로 감싸면 경로 변수로 인식됩니다 (예: `{id}`).
- **주의사항**: 그룹의 기본경로와 조합했을 때 전체 경로가 같은 그룹 내 다른 API와 겹치면
  안 됩니다(Method가 다르면 겹쳐도 무방).

### Method
- **설명**: HTTP 메서드입니다.
- **선택 가능 값**: GET, POST, PUT, DELETE, PATCH
- **선택 기준**:
  - 조회만 하는 API → GET
  - 새로 생성하는 API → POST
  - 전체 수정 → PUT
  - 부분 수정 → PATCH
  - 삭제 → DELETE

### 설명
- **설명**: 이 API가 어떤 기능을 하는지 자유 텍스트로 서술합니다.
- **입력 형식**: 최대 500자, 줄바꿈 허용.
- **필수 여부**: 선택 입력이지만, 규격서 품질을 위해 작성을 권장합니다.

### API 구분
- **설명**: 이 API의 공개 범위를 정합니다.
- **선택 가능 값**:
  - **Public**: 외부 개발자에게 공개되는 API. 규격서 포털에 자동 노출됩니다.
  - **Private**: 사내/제휴사 전용 API. Handler/Provider 연동 정보 입력이 추가로 필요합니다.
  - **Internal**: 내부 시스템 간 호출 전용. 규격서에는 노출되지 않습니다.

### Handler
- **설명**: API 구분이 "Private"일 때만 나타나는 항목으로, 이 API 요청을 실제로 처리할
  백엔드 핸들러(서비스 모듈)를 지정합니다.
- **입력 형식**: 사전 등록된 핸들러 목록에서 선택.
- **예시**: `MessagingServiceHandler`

### Provider
- **설명**: API 구분이 "Private"일 때만 나타나는 항목으로, 이 API가 실제로 연동되는
  제공기관/시스템(Provider)을 지정합니다.
- **입력 형식**: 사전 등록된 Provider 목록에서 선택.
- **예시**: `내부메시징시스템`, `제휴사A`

## 고급 설정 (기본은 접혀 있음)

### 엔드포인트/게이트웨이
- **설명**: 실제 요청이 전달될 백엔드 서버 주소(엔드포인트)와 게이트웨이 경유 여부를
  설정합니다.
- **기본값**: 그룹에서 설정한 테스트 BASEURL을 그대로 사용.
- **BEAST G/W 사용여부**: 사용 시 BEAST 게이트웨이를 경유해 트래픽 제어(속도 제한, 로깅
  등)가 적용됩니다.

### 응답 매핑
- **설명**: 백엔드 응답 필드를 이 API의 공식 응답 스키마 필드로 매핑하는 규칙입니다.
- **입력 형식**: `백엔드필드명 → 응답필드명` 쌍을 여러 개 추가 가능.
- **예시**: `resultCd → returncode`, `resultMsg → returndescription`

### HDP 연동 관련 필드
- **설명**: 이 API 호출 이력을 HDP(빅데이터 플랫폼)로 전송할지 여부와 전송 대상 필드를
  설정합니다.
- **HDP 전송 여부**: 사용/사용 안함 토글.
- **전송 필드 선택**: request/response 파라미터 중 HDP로 보낼 필드를 체크박스로 선택.

## 파라미터(요청/응답) 기본 항목 상세

### request 하위 기본 항목

| 필드명 | 설명 | 타입 | 필수 |
|---|---|---|---|
| TRANSACTIONID | 시스템에서 자동 발급하는 거래 고유 식별자. 로그 추적에 사용 | string | O |
| SEQUENCENO | 하나의 트랜잭션 내에서 여러 시스템을 거칠 때의 내부 처리 순서 번호 | string | O |
| USERID | 이 API를 호출하는 CP(Content Provider)가 사용하는 사용자 ID | string | X |
| SCREENID | 이 API를 호출한 화면을 식별하는 ID (CP 내부 화면 코드) | string | X |

### response 하위 기본 항목

| 필드명 | 설명 | 타입 | 비고 |
|---|---|---|---|
| sequenceno | 요청의 SEQUENCENO를 그대로 반환하여 요청-응답을 짝짓는 데 사용 | string | request 값과 동일하게 echo |
| returncode | 처리 결과 코드. `0`=성공, `1`=실패, 그 외 코드는 세부 오류 유형 | string | 예: `0`, `1`, `E001` |
| returndescription | returncode에 대한 사람이 읽을 수 있는 설명 | string | 예: "정상 처리되었습니다" |
| errorcode | 시스템 내부 오류 코드(예외 발생 시에만 값이 채워짐) | string | 예: `SYS-500` |
| errordescription | errorcode에 대한 상세 설명 | string | 예: "내부 서버 오류" |

## 저장 시 검증 규칙 (참고)

1. API 이름/권한그룹/Path/Method/API 구분은 필수이며, 비어 있으면 저장이 차단됩니다.
2. Path는 같은 그룹 내에서 Method 조합 기준으로 중복될 수 없습니다.
3. API 구분이 Private인 경우 Handler와 Provider가 모두 채워져야 저장됩니다.
4. 파라미터의 기본 항목(TRANSACTIONID, returncode 등)은 삭제할 수 없고, 이름 변경도 불가합니다.
