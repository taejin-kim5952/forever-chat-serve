# API 빠른 등록과 템플릿 관리

같은 형태의 API를 여러 건 만들 때, 매번 처음부터 입력하지 않도록 **템플릿**을 미리
만들어 두고 그 템플릿으로 한 번에 등록하는 기능입니다.

## 빠른 등록 화면

| 기능 | URL |
|---|---|
| 빠른 등록 화면 | `/apidev/api/quickreg/mvApiQuickReg.do` |
| 시스템-API 트리 조회 | `/apidev/api/quickreg/selSysApiTreeAjax.do` |
| 템플릿 상세 조회 | `/apidev/api/quickreg/selTmpltDetailAjax.do` |
| 저장 | `/apidev/api/quickreg/savApiQuickRegAjax.do` |

화면은 왼쪽에 시스템·API 트리, 오른쪽에 입력 폼이 있는 구조입니다. 템플릿을 고르면
기본 정보와 파라미터가 한꺼번에 채워지고, 다른 부분만 고쳐서 저장하면 됩니다.

## 템플릿 관리 화면

| 기능 | URL |
|---|---|
| 템플릿 목록 | `/apidev/api/quickreg/tmplt/mvTmpltMng.do` |
| 템플릿 등록/수정 폼 | `/apidev/api/quickreg/tmplt/mvTmpltForm.do` |
| 템플릿 저장 | `/apidev/api/quickreg/tmplt/savTmpltAjax.do` |
| 템플릿 삭제 | `/apidev/api/quickreg/tmplt/delTmpltAjax.do` |

템플릿에는 다음이 저장됩니다.

- API 기본 정보의 기본값(구분, 권한그룹, 핸들러 등)
- request/response 파라미터 트리 전체
- 엔드포인트 설정의 기본값

즉 "우리 팀이 만드는 API는 대체로 이런 모양"을 통째로 저장해 두는 것입니다.

## 템플릿을 만드는 두 가지 방법

1. **처음부터 작성** — 템플릿 등록 폼에서 직접 항목을 입력합니다.
2. **기존 API를 템플릿으로 승격** — 잘 만들어진 API를 골라 템플릿으로 저장합니다.
   그룹 등록 시 `템플릿 여부(tmpltYn)` 를 `Y` 로 두는 것과 같은 맥락입니다.

## 빠른 등록으로 여러 건 만들기

빠른 등록 화면은 저장 후 폼을 유지하도록 만들어져 있어서, 이름과 Path만 바꿔가며
연달아 저장하는 사용법을 전제로 합니다. 예를 들어 조회/등록/수정/삭제 4종 API를
같은 파라미터 규칙으로 만들 때 유용합니다.

## 자주 묻는 질문

**Q. 템플릿을 고쳤는데 이미 만든 API가 안 바뀝니다.**
A. 템플릿은 **복사본을 찍어내는 도장**이지 연결된 원본이 아닙니다. 템플릿을 고쳐도
과거에 그 템플릿으로 만든 API에는 영향이 없습니다. 반대로 API를 고쳐도 템플릿은
그대로입니다.

**Q. 템플릿을 삭제하면 그걸로 만든 API도 지워지나요?**
A. 아니요. 템플릿만 사라지고 이미 등록된 API는 그대로 남습니다.

**Q. 템플릿 목록에 다른 팀 템플릿도 보이나요?**
A. 권한 범위 안의 시스템에 속한 템플릿만 보입니다. 공용으로 쓰고 싶으면 운영자에게
공용 시스템 아래에 만들어 달라고 요청하세요.

**Q. 빠른 등록과 일반 등록의 결과가 다른가요?**
A. 저장되는 데이터는 같습니다. 입력 단계를 줄여줄 뿐이므로, 빠른 등록으로 만든 API도
일반 등록 화면에서 그대로 열어 수정할 수 있습니다.

**Q. 템플릿으로 채운 값 중 일부만 지우고 싶습니다.**
A. 채워진 뒤에는 일반 입력값과 똑같이 다룰 수 있습니다. 필요 없는 파라미터는 트리에서
삭제하고 저장하면 됩니다.
