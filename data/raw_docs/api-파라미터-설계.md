# API 파라미터 설계

파라미터는 API가 주고받는 항목을 트리 형태로 정의하는 부분입니다. 등록 화면 안의
"파라미터 설계" 영역에서 다루며, 한 건씩 추가할 수도 있고 YAML을 붙여넣어 한 번에
반영할 수도 있습니다.

## 기본 골격 — request / response

이 시스템의 모든 API는 다음 규칙을 따릅니다.

- 요청 항목은 **`request`** 라는 객체 하나로 감쌉니다.
- 응답 항목은 **`response`** 라는 객체 하나로 감쌉니다.

등록 화면에 처음 들어가면 공통 항목이 자동으로 채워집니다.

**request 기본 하위 항목**

| 항목 | 설명 |
|---|---|
| `TRANSACTIONID` | 거래 추적용 고유 ID |
| `SEQUENCENO` | 요청 일련번호 |
| `USERID` | 호출 사용자 ID |
| `SCREENID` | 호출 화면 ID |

**response 기본 하위 항목**

| 항목 | 설명 |
|---|---|
| `sequenceno` | 요청과 짝을 이루는 일련번호 |
| `returncode` | 처리 결과 코드 |
| `returndescription` | 결과 설명 |
| `errorcode` | 오류 코드 |
| `errordescription` | 오류 설명 |

이 공통 항목은 지우지 말고, 그 아래에 실제 이 API만의 항목을 추가하는 방식으로
설계합니다.

## 파라미터 한 건의 속성

| 속성 | 필드 | 설명 |
|---|---|---|
| 이름 | `paramNm` | 항목명 |
| 위치 | `paramLoc` | header / path / query / body |
| 데이터 타입 | `dataTypeCd` | String, Object, Array, Number, Integer, Boolean |
| 필수 여부 | `required` | 필수면 `Y` |
| 설명 | `paramDesc` | |
| 예시 | `Exam` | 규격서에 표시되는 예시값 |
| 상위 항목 | `prntsParamNo` | 중첩 구조에서 부모 파라미터 번호 |
| 정렬 순서 | `objOdrg` | 같은 depth 안에서의 순서 |
| 개인정보 | `personalData` | 개인정보 항목이면 `Y` — 민감정보 관리와 연결됩니다 |
| 마스킹 | `hidden` | 로그·응답에서 가릴지 여부 |
| 미전송 | `doNotSend` | 백엔드로 넘기지 않을 항목 |
| 고정값 | `fixedValue` | 항상 이 값으로 채워 보냄 |
| 매핑 키 | `mappingKey` | 백엔드 필드명이 다를 때 매핑 |
| URL 인코딩 | `hdpUrlEncode` / `hdpUrlDecode` | 전송 전 인코딩/디코딩 |
| 업로드 대상 | `hdpUploadTarget` | 파일 업로드 항목 지정 |
| 샌드박스 노출 | `paramSandboxYn` | 테스트 호출 화면에 노출할지 |

## 데이터 타입

선택 가능한 타입은 다음과 같습니다.

| 타입 | 설명 |
|---|---|
| `String` | 문자열 |
| `Integer` | 정수 |
| `Number` | 실수 포함 숫자 |
| `Boolean` | true/false |
| `Object` | 하위 항목을 갖는 묶음 |
| `Array` | 같은 형태가 여러 개 반복 |

`Object` 나 `Array` 로 지정하면 그 아래에 자식 파라미터를 계속 붙일 수 있습니다.
depth 제한은 두지 않지만, 3단계를 넘어가면 규격서 가독성이 급격히 떨어집니다.

## 트리 편집기 사용법

- 항목을 선택하고 **추가**를 누르면 그 항목의 **자식**으로 들어갑니다. 형제로 넣고
  싶으면 부모를 선택한 상태에서 추가하세요.
- 순서는 드래그로 바꿉니다. 순서가 그대로 규격서 표의 행 순서가 됩니다.
- 삭제하면 그 아래 자식까지 함께 사라집니다. 되돌리기가 없으므로 큰 가지를 지울
  때는 YAML로 한 번 내려받아 두는 편이 안전합니다.

## YAML로 한 번에 반영하기

트리를 하나씩 만드는 대신 Swagger/OpenAPI YAML을 붙여넣으면 파라미터가 자동으로
생성됩니다. 반대로 지금까지 만든 파라미터를 YAML로 내려받아 보관할 수도 있습니다.
자세한 내용은 [[yaml-반입과-반출]] 문서를 보세요.

## 자주 묻는 질문

**Q. request/response 객체를 지워도 되나요?**
A. 권장하지 않습니다. 게이트웨이 핸들러가 이 두 객체를 전제로 변환하기 때문에,
없애면 배포는 되어도 실제 호출에서 형식이 맞지 않습니다.

**Q. 파라미터가 백 개 가까이 됩니다. 하나씩 넣어야 하나요?**
A. YAML 반입을 쓰세요. 백엔드에서 쓰는 스펙 파일이 있으면 붙여넣기 한 번으로
끝납니다.

**Q. 개인정보 항목은 어떻게 표시하나요?**
A. 해당 파라미터의 `개인정보` 속성을 `Y` 로 두면 민감정보 현황 화면 집계에
잡힙니다. 화면에 노출하고 싶지 않으면 마스킹 속성도 함께 켜세요.

**Q. 항목 순서가 규격서에서 뒤죽박죽입니다.**
A. 정렬 순서 값이 비어 있거나 겹친 경우입니다. 트리에서 드래그로 다시 정렬한 뒤
저장하면 순서가 다시 매겨집니다.

**Q. 부모를 Object가 아닌 String으로 두고 자식을 붙였습니다.**
A. 저장은 되지만 규격서와 실제 전문이 어긋납니다. 자식을 가지는 항목은 반드시
`Object` 또는 `Array` 로 지정하세요.
