# API 게이트웨이 연동 구조

포털에 등록한 API 정의는 그대로 게이트웨이에 올라가지 않습니다. 게이트웨이가 이해하는
형식으로 **변환(Convert)** 한 뒤 전송합니다. 이 문서는 그 변환이 무엇을 하는지
설명합니다.

## 전체 흐름

```
포털 API 정의(DB)
      │
      │ ① 엔티티 변환 (Converter)
      ▼
게이트웨이 API 엔티티
      │
      │ ② 배포 요청 전송 (HTTP)
      ▼
게이트웨이 (TB 또는 운영)
      │
      │ ③ 배포 상태 폴링
      ▼
포털 배포 상태 갱신 · LAMP 로그 기록
```

## 변환기(Converter)가 처리하는 항목

포털 파라미터의 속성 하나하나가 게이트웨이 설정으로 번역됩니다.

| 변환 대상 | 포털 쪽 설정 | 게이트웨이에서의 의미 |
|---|---|---|
| 필수 파라미터 | `required = Y` | 값이 없으면 게이트웨이가 거절 |
| 미전송 파라미터 | `doNotSend = Y` | 받되 백엔드로는 넘기지 않음 |
| 고정값 파라미터 | `fixedValue` | 항상 지정한 값으로 채워 전송 |
| 마스킹 파라미터 | `hidden = Y` | 로그·응답에서 값 가림 |
| 헤더 파라미터 | `paramLoc = header` | HTTP 헤더로 매핑 |
| 매핑 규칙 | `mappingKey` | 백엔드 필드명으로 이름 변경 |
| URL 인코딩 | `hdpUrlEncode` / `hdpUrlDecode` | 전송 전후 인코딩 처리 |
| 업로드 대상 | `hdpUploadTarget` | 파일 업로드 경로로 처리 |
| JSON 배열 | 배열 타입 파라미터 | 배열 구조 변환 |
| Null 설정 | 값 없을 때 처리 | 빈 값을 null로 보낼지 |
| 보안 필드 | 민감 항목 | 암호화 대상 지정 |
| KOS 공통 헤더 | KOS 핸들러 사용 시 | KOS 규격 공통 헤더 자동 부착 |

## 게이트웨이에 올라가는 정보

변환 결과로 만들어지는 게이트웨이 API 정의에는 다음이 담깁니다.

- **라우트(Route)** — 어떤 Path·Method 요청을 받을지
- **프록시(Proxy)** — 어느 백엔드로 넘길지 (엔드포인트 URL, 스킴, 타임아웃)
- **스테이지(Stage)** — TB/운영 등 배포 단계
- **요청 정의(Request)** — 파라미터 목록과 규칙
- **결과 매핑(Result Mapping)** — 백엔드 응답에서 성공/실패를 판정하는 규칙

## URL 스킴

엔드포인트는 `HTTP` 또는 `HTTPS` 를 지정합니다. 운영 환경은 원칙적으로 `HTTPS` 를
씁니다. 포털 서버 자체도 TLS 1.2/1.3 만 허용하도록 기동 옵션이 걸려 있습니다.

## 비동기 배포와 재시도

배포 요청은 오래 걸릴 수 있어 별도 스레드 풀에서 비동기로 처리합니다. 일시적인
네트워크 오류에 대비해 재시도 로직도 들어 있습니다. 그래서 화면에서 배포 버튼을 누른
직후에는 "진행 중" 상태만 보이고, 최종 결과는 잠시 뒤에 갱신됩니다.

## CP API 연동

일부 API는 CP(Content Provider) 규격으로 별도 관리됩니다. CP API 엔티티는 요청/응답
/헤더 구조가 따로 있고, 조회는 `/apidev/adptran_api/{버전}/apigw_cpApiGet` 로 합니다.

## 게이트웨이 관련 REST 호출

| 기능 | URL |
|---|---|
| 배포 실행 | `/apidev/adptran_api/{버전}/apigw_deploy` (POST) |
| 배포 상태 조회 | `/apidev/adptran_api/{버전}/apigw_deployStatus` (POST) |
| 배포 삭제 | `/apidev/adptran_api/{버전}/apigw_deployDelete` (POST) |
| CP API 조회 | `/apidev/adptran_api/{버전}/apigw_cpApiGet` (POST) |
| LAMP 로그 조회 | `/apidev/adptran_api/{버전}/apigw_LampLog` (POST) |

## 자주 묻는 질문

**Q. 포털에서 파라미터를 고쳤는데 게이트웨이 동작이 그대로입니다.**
A. 정의만 바꾸고 재배포를 하지 않았기 때문입니다. 게이트웨이는 배포된 시점의 정의로
동작합니다. 변경 배포를 다시 신청·실행해야 반영됩니다.

**Q. 파라미터를 보냈는데 백엔드가 못 받습니다.**
A. `미전송(doNotSend)` 속성이 켜져 있거나, `매핑 키` 가 백엔드 필드명과 다르게
지정된 경우입니다. 파라미터 속성을 먼저 확인하세요.

**Q. 응답에 값이 `null` 로만 옵니다.**
A. 결과 매핑 설정에서 응답 필드 경로가 실제 응답 구조와 다를 때 자주 발생합니다.
LAMP 로그로 백엔드 원본 응답을 보고 경로를 맞추세요.

**Q. 배포 삭제를 하면 포털의 API도 지워지나요?**
A. 아니요. 게이트웨이에서 내려갈 뿐이고 포털의 API 정의는 남습니다. 다시 배포하면
동일한 정의로 올라갑니다.

**Q. 타임아웃 값은 어디에 적용되나요?**
A. 게이트웨이가 백엔드를 기다리는 시간입니다. 이 값이 짧으면 백엔드가 정상 응답해도
게이트웨이가 먼저 끊어 버립니다.
