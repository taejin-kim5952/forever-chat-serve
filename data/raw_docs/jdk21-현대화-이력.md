# JDK 21 / Spring Boot 현대화 이력

포털은 레거시 프레임워크 기반이던 것을 순수 Spring Boot 구조로 바꾸는 대규모 개편을
거쳤습니다. 지금 코드에서 보이는 여러 선택은 그 과정의 결과입니다.

## 최종 목표 두 가지

1. **레거시 프레임워크 완전 탈피** — 상속 기반 DAO/Service, 전용 Map 타입, 자체
   유틸 의존을 전부 걷어내고 순수 Spring 빈으로 전환
2. **설정 XML 제거** — Java Config와 YAML만 남기기

## 단계별로 한 일

### 1단계 — 빌드·실행 환경

- Maven 부모를 Spring Boot 스타터로 교체
- `javax.*` 의존성을 `jakarta.*` 로 교체
- 메인 애플리케이션 클래스 생성
- 설정을 `config/{common,local,tb,prod}/` 계층으로 재편

### 2단계 — 코드 현대화

- Java 소스 전체 `javax` → `jakarta` 치환
- 프레임워크 공통 패키지(`fwk`) 신설
- 서비스 계층에서 상속 제거, 생성자 주입과 `@Transactional` 로 전환
- Java Config 클래스로 XML 설정 이관
- 세션 체크 인터셉터, 전역 예외 처리, 페이징 유틸 정비
- 스케줄러를 `@Scheduled` 기반으로 전환
- 기동 자가 진단 로직 추가

### 3단계 — 데이터 접근 계층

- iBatis SQL XML을 MyBatis로 이식(21개)
- DAO 클래스를 `@Mapper` 인터페이스로 전환, 네임스페이스를 인터페이스 전체 경로로 통일
- 느슨한 Map 대신 업무별 전용 VO 도입
- ID 채번을 DB IDENTITY / `<selectKey>` 로 전환
- 페이징을 `OFFSET/FETCH` 표준으로 통일

### 4단계 — 화면 계층

- Tiles 레이아웃 제거
- JSP 커스텀 태그 레이아웃 도입 → 이후 Thymeleaf로 완전 전환
- 공통 페이징 스크립트 적용
- `dispatcher-servlet.xml`, `web.xml` 제거

### 5단계 — 로깅

- Log4j2 설정을 Logback으로 이식

### 6단계 — 빌드 오류 정리

업그레이드 직후 컴파일 오류 85건이 한꺼번에 발생했고, 이를 정리한 기록이 남아
있습니다. 대표적인 것만 보면:

| 문제 | 원인 | 해결 |
|---|---|---|
| SSL/타임아웃 설정 컴파일 실패 | HttpClient 4 → 5 API 변경 | HC5 빌더 패턴으로 재작성 |
| 빈 이름 충돌 | 같은 이름의 설정 클래스 2개 | 한쪽에 고유 빈 이름 부여 |
| 매퍼 스캔 오류 | 스캔 범위가 너무 넓어 서비스 인터페이스까지 매퍼로 인식 | `@Mapper` 어노테이션 기준으로 제한 |
| 순환 참조 | 설정 클래스가 서비스를 필드 주입하면서 직접 생성도 함 | 생성자 주입으로 정리 |
| 매퍼 XML 파싱 실패 | 닫는 태그 뒤 여분 문자, 레거시 iBatis 설정 파일 스캔 | 문자 제거, 레거시 파일 삭제 |
| 속성 주입 실패 | YAML에 없는 설정 키 참조 | 환경별 설정에 키 추가 |
| 기동 실패 | 암호화 모듈 초기화 오류가 `Error` 로 던져져 잡히지 않음 | `Throwable` 까지 잡아 경고만 남기고 진행 |
| DataSource 미생성 | 프로파일 변수가 import 시점에 해석되지 않음 | 경로를 명시적으로 지정 |

### 7단계 — 명칭 정리

레거시 프레임워크 이름이 클래스명·변수명·설정에 42개 파일에 걸쳐 남아 있어 전부
이름을 바꾸고, 사용하지 않는 XML 설정과 샘플 코드를 삭제했습니다. 이 과정에서
PowerShell로 파일을 고치다 UTF-8 BOM이 붙는 문제가 생겨 별도로 걷어냈습니다.

## Spring Boot 4로 올리면서 바뀐 것

| 항목 | 변화 |
|---|---|
| AOP 스타터 | `spring-boot-starter-aop` → `spring-boot-starter-aspectj` |
| spring-retry | BOM 관리에서 빠져 버전 명시 필요 |
| springdoc | Boot 4 대응 버전으로 상향 |
| 콘텐츠 협상 | 확장자 기반 추론 옵션이 제거됨(기본값이 이미 비활성이라 동작 변화 없음) |
| JSP | 완전 제거, Thymeleaf 단일 체계 |

## 지금 코드에서 그 흔적을 보는 법

- 소스에 `[마이그레이션]`, `[Boot4 마이그레이션]`, `[PostgreSQL 마이그레이션]` 같은
  주석 태그가 달려 있습니다. 왜 그렇게 바뀌었는지가 그 자리에 적혀 있습니다.
- Thymeleaf 뷰 리졸버의 허용 뷰 이름 목록은 JSP 폴백이 사라진 흔적입니다.
- Security 설정이 "모든 경로 허용"인 이유는 원래 `web.xml` 에도 실질 제약이 없었던
  동작을 그대로 옮겼기 때문입니다.

## 자주 묻는 질문

**Q. 왜 Spring Security를 켜 놓고 전부 허용하나요?**
A. 이전 구조와 동작을 똑같이 유지하려는 선택입니다. 실제 인증은 세션 체크
인터셉터가 담당합니다.

**Q. JSP 파일을 다시 넣어도 되나요?**
A. 안 됩니다. JSP 리졸버가 없어 렌더링되지 않습니다. Thymeleaf 템플릿으로 만드세요.

**Q. 새 화면을 만들었는데 뜨지 않습니다.**
A. 뷰 리졸버의 허용 뷰 이름 목록에 추가했는지 확인하세요. 이 목록 관리가 현대화의
부작용 중 하나입니다.

**Q. 매퍼를 만들었는데 인식이 안 됩니다.**
A. 인터페이스에 `@Mapper` 를 붙여야 스캔됩니다. 스캔 범위가 어노테이션 기준으로
좁혀져 있습니다.
