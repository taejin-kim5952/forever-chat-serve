# 설정 파일 구조와 환경 분리

설정은 하나의 큰 파일이 아니라 **환경별 폴더 + 주제별 파일**로 쪼개져 있습니다.
어떤 값이 어디 있는지 알면 문제를 훨씬 빨리 찾을 수 있습니다.

## 폴더 구조

```
src/main/resources/
├── application.yml                  루트 설정 (프로파일·포트·컨텍스트 경로)
├── logback-spring.xml               로깅
├── SafeDBMap_config.xml             DB 암호화 매핑
└── config/
    ├── common/
    │   ├── application-profile.yml  공통 설정 (MyBatis·메시지·스케줄러·업로드)
    │   └── beast.yml                BEAST 공통
    ├── local/                       로컬 개발
    ├── tb/                          검증계
    │   ├── application-tb.yml       DataSource
    │   ├── common.yml               업무 공통 값
    │   ├── apigw.yml                게이트웨이 연동
    │   └── adptran.yml              개발자 도구
    └── prod/                        운영 (파일 구성 동일)
```

`application.yml` 이 활성 프로파일에 맞는 폴더의 파일들을 import 하는 방식입니다.

## 루트 설정에서 정하는 것

| 항목 | 값 |
|---|---|
| 활성 프로파일 | `spring.profiles.active` |
| 포트 | 8081 |
| 컨텍스트 경로 | `/apidev` |
| 인코딩 | UTF-8 강제 |
| 세션 타임아웃 | 120분 |
| 세션 추적 | 쿠키만 (URL에 세션 ID 노출 안 함) |
| 에러 경로 | `/error` (기본 화이트라벨 비활성) |

## 공통 설정에서 정하는 것

| 항목 | 값 |
|---|---|
| 페이지 단위 | 목록 10건, 공지 5건 |
| 메시지 번들 | `kt/message/message-common` |
| 정적 리소스 경로 | `/resources/**` |
| 업로드 제한 | 파일 10MB, 요청 10MB |
| MyBatis 매퍼 위치 | `classpath:/kt/sqlmap/**/*.xml` |
| 언더스코어→카멜케이스 | 켜짐 |
| 스케줄러 풀 크기 | 10 |
| SafeDB 모의 모드 | 기본 꺼짐(`SAFEDB_MOCK_ENABLED`) |

## 환경별 공통 값(`common.yml`)에서 정하는 것

| 묶음 | 내용 |
|---|---|
| 파일 서버 경로 | 이미지·YAML·apidoc·WSDL 저장 위치 |
| 업로드 경로 | 요청/마스터 업로드 디렉터리 |
| 에디터 | API 에디터 호스트 |
| PSSO | 로그인·SMS·회원 API 주소와 키 |
| 메일 | 발송 대상, 배포 신청 알림 수신자 |
| 권한 | A/G 운영자 그룹 ID, 옵저버 사용자 목록 |
| SHUB | 인증 API 주소, 2FA 검증 주소 |
| GitLab | Arsenal 저장소 호스트·토큰 |
| 로그 | LAMP 로그 경로, 서비스명, 채널 ID |

## 민감값은 환경변수로

비밀번호·토큰·키는 설정 파일에 직접 쓰지 않고 환경변수 참조로 두었습니다.

| 환경변수 | 쓰임 |
|---|---|
| `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | DB 접속 |
| `SAFEDB_AUTH_PASSWORD` | DB 암호화 모듈 인증 |
| `PSSO_RESET_PW`, `PSSO_AES_KEY` | PSSO 연동 |
| `APILINK_MAIL_KEY` | 메일 발송 키 |
| `REST_AUTHORIZATION_SB` | 외부 REST 인증 |
| `NEW_PSSO_API_CLIENTKEY` | PSSO 클라이언트 키 |
| `DEPLOYAPPLY_MAIL_LIST` | 배포 알림 수신자 |
| `APISYSTEM_OBSERVER_*` | 옵저버 사용자 목록 |

컨테이너 기동 시 진입 스크립트가 이 값들을 설정 파일의 자리표시자에 채워 넣습니다.

## 런타임 설정과 기동 설정의 차이

| 구분 | 바꾸는 곳 | 반영 시점 |
|---|---|---|
| 기동 설정 | YAML 파일 | 재시작해야 반영 |
| 데이터 설정 | DB 공통코드 | 즉시 반영 |

임계값이나 선택 목록처럼 자주 바뀌는 값은 YAML이 아니라 공통코드로 관리합니다.

## 자주 묻는 질문

**Q. 설정값을 바꿨는데 반영이 안 됩니다.**
A. YAML은 기동 시점에 읽습니다. 재시작해야 반영됩니다.

**Q. 어느 프로파일로 떠 있는지 어떻게 아나요?**
A. 기동 로그의 활성 프로파일 표시로 확인합니다. 컨테이너는 기동 인자로
프로파일을 받습니다.

**Q. 로컬에서 SafeDB 때문에 기동이 안 됩니다.**
A. 모의 모드를 켜세요. VM 옵션 `-Dsafedb.mock.enabled=true` 또는 환경변수
`SAFEDB_MOCK_ENABLED=true` 입니다. 운영·검증계에는 영향이 없습니다.

**Q. 업로드 크기 제한을 늘릴 수 있나요?**
A. 공통 설정의 멀티파트 최대 크기를 조정하면 됩니다. 다만 앞단 프록시에도 같은
제한이 있을 수 있으니 함께 확인해야 합니다.

**Q. 설정 파일에 비밀번호가 그대로 보입니다.**
A. 로컬 개발용 파일에는 테스트 계정이 남아 있을 수 있습니다. 검증계·운영은
환경변수로 주입합니다.
