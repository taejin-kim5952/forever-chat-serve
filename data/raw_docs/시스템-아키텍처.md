# 시스템 아키텍처와 기술 스택

포털은 Spring Boot 기반 서버 렌더링 웹 애플리케이션입니다. 화면 대부분은 Thymeleaf
템플릿으로 그리고, 개발자 도구 일부만 Vue 단일 페이지로 만들어져 있습니다.

## 기술 스택

| 영역 | 사용 기술 |
|---|---|
| 런타임 | Java 21 |
| 프레임워크 | Spring Boot 4.x (Spring Framework 6/7 계열) |
| 표준 | Jakarta EE 10 (`jakarta.*` 패키지) |
| 빌드 | Maven |
| 화면 | Thymeleaf + Layout Dialect |
| 데이터 접근 | MyBatis (XML 매퍼) |
| 데이터베이스 | PostgreSQL |
| 커넥션 풀 | HikariCP |
| 보안 | Spring Security(세션 기반 인증은 자체 인터셉터) |
| 로깅 | Logback (`logback-spring.xml`) |
| API 문서 | springdoc-openapi (Swagger UI) |
| 스펙 파싱 | Swagger Core / Parser (레거시 YAML) |
| HTTP 클라이언트 | Apache HttpClient 5 |
| 문서/엑셀 | Apache POI |
| 유틸 | commons-lang3, commons-text, Guava, Gson, Jsoup |
| 프런트 일부 | Vue + Webpack 번들 |
| 암호화 | INISAFE 계열, SafeDB SDK |
| 모니터링 | Azure Application Insights 에이전트 |

## 패키지 구조

```
com.kt.openapi
├── fwk                     프레임워크 공통
│   ├── cmm.config          Java Config (Web/MyBatis/Security/Async/Transaction)
│   └── online
│       ├── checker         기동 자가진단 (SafeDBChecker)
│       ├── exception       전역 예외 처리, 에러 컨트롤러
│       ├── filter          세션 체크 인터셉터
│       └── page            페이징 유틸
└── web                     업무 코드
    ├── api                 API 등록·조회·민감정보
    ├── apiDeploy           배포
    ├── apigw               게이트웨이 연동(변환기·엔티티·타입)
    ├── beast               BEAST 게이트웨이
    ├── adptran             개발자 도구(Vue용 REST)
    ├── spcreg              규격/정의 등록
    ├── login, userJoin     인증·회원
    ├── mypage              마이페이지
    ├── bbs, faq, qna       게시판
    ├── devsupport          개발지원
    ├── guide, main, agree  가이드·메인·약관
    ├── rest                외부 연동 REST
    ├── cmm, cmmn, util     공통 유틸·파일·로그
    └── Entity              공통 응답 객체
```

업무 패키지는 대체로 `controller / service / service.impl / dao / vo` 5층 구조를
따릅니다.

## 요청 처리 흐름

```
브라우저
  │
  ▼
Spring Security 필터 체인 (모든 경로 permitAll, CSRF 비활성)
  │
  ▼
SessionCheckInterceptor  ── 세션 없음 → /apidev/main/index.do 로 리다이렉트
  │
  ▼
Controller (@Controller 또는 @RestController)
  │
  ▼
Service (@Transactional)
  │
  ▼
DAO (@Mapper 인터페이스) ── MyBatis XML ── PostgreSQL
  │
  ▼
Thymeleaf 뷰 또는 JSON 응답
```

## 인증 구조

Spring Security는 켜져 있지만 **모든 경로를 허용**하도록 설정되어 있습니다. 실제
인증은 `SessionCheckInterceptor` 가 세션(`ssUserVo`)을 확인해 처리합니다. 레거시
`web.xml` 에 BASIC 인증 선언은 있었으나 실제 제약이 없었던 동작을 그대로 재현한
구조입니다.

인터셉터는 `/**` 전 경로에 걸리고 `/resources/**` 만 제외합니다. 비로그인 허용
경로는 인터셉터 내부의 예외 목록으로 관리합니다.

## 뷰 리졸버

Thymeleaf 뷰 리졸버는 **허용 뷰 이름 목록**을 명시적으로 갖고 있습니다. 목록에 없는
뷰 이름은 이 리졸버가 처리하지 않습니다. `jsonView`, `redirect:`, `forward:` 같은
특수 이름을 가로채지 않게 하려는 장치입니다.

**새 화면을 추가할 때 이 목록에 뷰 이름을 넣지 않으면 화면이 뜨지 않습니다.**
JSP는 완전히 제거되어 폴백 리졸버가 없기 때문입니다.

## 비동기와 스케줄러

- 게이트웨이 배포처럼 오래 걸리는 작업은 별도 스레드 풀에서 비동기 처리합니다.
- 스케줄러는 `@Scheduled` 기반이고 주기는 설정 파일로 외부화되어 있습니다.
  기본 풀 크기는 10입니다.

| 스케줄 | 주기 |
|---|---|
| 정리 작업 | 30분마다 |
| 시스템별 배치 | 새벽 시간대(1시~6시) 각각 |

## 기동 자가 진단

애플리케이션이 뜰 때 `SafeDBChecker` 가 필수 리소스를 점검합니다. 배포 폴더, DB
연결, SafeDB 암호화 모듈을 확인하고, 로컬처럼 SafeDB가 없는 환경에서는 경고만 남기고
계속 기동합니다.

## 자주 묻는 질문

**Q. 새 화면을 만들었는데 404가 납니다.**
A. Thymeleaf 뷰 리졸버의 허용 뷰 이름 목록에 추가했는지 확인하세요. 목록에 없으면
템플릿 파일이 있어도 화면이 뜨지 않습니다.

**Q. JSP를 쓸 수 있나요?**
A. 없습니다. JSP는 완전히 제거되었고 Thymeleaf만 남았습니다.

**Q. Swagger UI는 어디에 있나요?**
A. springdoc이 붙어 있어 표준 경로에서 API 문서를 볼 수 있습니다. 다만 이 포털의
주 용도는 화면이므로 문서 노출 범위는 환경별로 다릅니다.

**Q. 세션 대신 토큰을 쓸 수 없나요?**
A. 현재 구조는 세션 기반입니다. 외부 연동용 REST(`/api.json` 등)는 별도 인증 키를
씁니다.
