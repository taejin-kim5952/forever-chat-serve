# 자주 겪는 오류와 문제 해결

증상별로 어디를 먼저 봐야 하는지 정리했습니다.

## 화면이 안 뜨거나 되돌아갑니다

| 증상 | 원인 | 조치 |
|---|---|---|
| 메뉴를 눌러도 메인으로 돌아감 | 세션 만료 또는 중복 로그인 | 다시 로그인 |
| 특정 화면만 안 열림 | 권한 없음 | 마이페이지에서 권한 신청 |
| 흰 화면 | 정적 리소스/번들 로드 실패 | 캐시 삭제 후 새로고침 |
| 404 | 화면 뷰가 리졸버 목록에 없음 | 개발지원 문의 |

## 등록했는데 안 보입니다

이 문의가 가장 많습니다. 확인 순서는 다음과 같습니다.

1. **등록 상태** — 공개(`APIREG1030`)인가?
2. **사용여부** — `USE_YN` 이 `Y` 인가?
3. **삭제 여부** — 삭제 처리(`DEL_DT`)되지 않았는가?
4. **공개 구분** — Private/Internal이라 감춰진 것은 아닌가?
5. **권한** — 조회하는 계정이 그 시스템에 권한이 있는가?

## 저장이 안 됩니다

| 메시지 | 원인 |
|---|---|
| 이미 등록된 ID입니다 | API ID 중복 |
| 이미 등록된 Path입니다 | 같은 그룹에 Method+Path 중복 |
| 필수 항목을 입력하세요 | 빨간 표시 항목 미입력 |
| 세션이 만료되었습니다 | 120분 초과 |
| 422 (설정 저장 시) | 값이 허용 범위를 벗어남 |

긴 폼을 오래 열어 두면 세션이 끊겨 저장 순간에 로그인 화면으로 튕깁니다. 큰 작업은
중간에 한 번 저장해 두세요.

## 검증이 실패합니다

| 증상 | 확인할 곳 |
|---|---|
| 타임아웃 | 엔드포인트 타임아웃 값, 백엔드 기동 여부 |
| 연결 거부 | TB 엔드포인트 URL, 방화벽/IP 허용 |
| 성공인데 실패로 판정 | 응답 코드 필드명과 성공 값 설정 |
| 파라미터 누락 | 필수 여부, 미전송 설정, 매핑 키 |
| 인증 실패 | 테스트케이스의 헤더 값(토큰) |

가장 확실한 단서는 **LAMP 로그**입니다. 실제로 나간 요청과 받은 응답 원문을 볼 수
있어 추측 없이 원인을 좁힐 수 있습니다.

## 배포가 안 끝납니다

| 상태 | 의미 | 조치 |
|---|---|---|
| `DEPLOYING` 지속 | 게이트웨이 응답 대기 | LAMP 로그 확인, 장시간이면 운영자 문의 |
| `ROLLING_BACK` | 실패해 되돌리는 중 | 완료 후 원인 수정하고 재배포 |
| `FAIL` | 배포 실패 | 오류 메시지 확인 |
| 운영 버튼 비활성 | TB 배포 미완료 | TB 배포부터 성공시키기 |

## 배포는 됐는데 호출이 안 됩니다

| 증상 | 원인 |
|---|---|
| 404 | 호스트/기본경로/Path 조합 불일치, 재배포 누락 |
| 403 | IP 접근 권한 목록에 호출자 IP 없음 |
| 401 | 인증 키/토큰 문제 |
| 429 | 유량 제한(SLA) 초과 |
| 502/504 | 백엔드 무응답 또는 타임아웃 |
| 응답 필드가 비어 있음 | 결과 매핑 경로가 실제 응답 구조와 다름 |

## 파일 관련

| 증상 | 원인 |
|---|---|
| 업로드 실패 | 10MB 초과(여러 개면 합계 기준) |
| 파일명 깨짐 | 브라우저/프록시 인코딩 |
| 첨부가 목록에 없음 | 파일은 올라갔지만 글 저장 실패 |

## YAML 반입 실패

| 증상 | 원인 |
|---|---|
| 파라미터가 안 생김 | 구문 오류(탭/스페이스 혼용이 흔함) |
| 일부만 반영됨 | `$ref` 외부 참조를 풀지 못함 |
| 엉뚱한 구조 | 지원 범위를 벗어난 스펙 문법 |

## 기동/운영 쪽 오류 (관리자용)

| 증상 | 원인 |
|---|---|
| DataSource 생성 실패 | 접속 정보 환경변수 미주입(자리표시자가 그대로 남음) |
| 속성 주입 실패 | 코드가 참조하는 설정 키가 YAML에 없음 |
| 빈 이름 충돌 | 같은 이름의 설정 클래스 중복 |
| 매퍼 XML 파싱 실패 | XML 문법 오류, 레거시 설정 파일 잔존 |
| 암호화 모듈 초기화 실패 | 로컬에 SafeDB 에이전트 없음 → 모의 모드로 우회 |

## 문의할 때 같이 알려주면 좋은 것

- 화면 주소(URL)와 시각
- 대상 API의 그룹/ID/Path
- 화면에 뜬 오류 메시지 전문
- 재현 방법
- 로그인 계정(아이디)

이 다섯 가지가 있으면 대부분 한 번에 원인을 좁힐 수 있습니다.

## 자주 묻는 질문

**Q. 오류 메시지가 "시스템 오류가 발생했습니다"뿐입니다.**
A. 서버 내부 예외가 공통 에러 화면으로 처리된 경우입니다. 발생 시각과 화면 주소를
알려주면 서버 로그에서 원인을 찾을 수 있습니다.

**Q. 어제는 됐는데 오늘 안 됩니다.**
A. 배포 이력을 먼저 확인하세요. 그 사이 재배포나 설정 변경이 있었을 가능성이 큽니다.

**Q. 특정 브라우저에서만 문제가 생깁니다.**
A. 캐시된 옛 스크립트가 원인인 경우가 많습니다. 강력 새로고침 후 재시도하세요.
