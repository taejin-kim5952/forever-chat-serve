# 템플릿 관리

API를 등록할 때 자주 쓰는 값(이름/설명/API 구분/Method/Path/파라미터)을 미리 저장해두고,
API 등록 화면에서 한 번에 불러다 쓸 수 있게 해주는 화면입니다. 상단 메뉴 "API 등록(NEW)"
아래 "템플릿 관리"에서 들어갑니다.

## 템플릿은 어디서 쓰이나요

"API 등록" 화면([[api-등록]] 참고)의 **"템플릿으로 시작"** 버튼을 누르면 여기서 등록한
템플릿 목록이 나타나고, 하나를 선택하면 API 이름/Method/Path/파라미터가 자동으로
채워집니다. 특히 회사 공통 규칙(요청은 `request` 객체, 응답은 `response` 객체로 감싸고
그 안에 트랜잭션ID·결과코드 같은 공통 항목을 포함)을 담은 템플릿을 만들어두면, API를
새로 등록할 때마다 매번 같은 값을 반복 입력하지 않아도 됩니다.

## 템플릿 목록 화면

목록에는 각 템플릿의 이름/설명/API 구분/Method/사용여부가 표시됩니다. 이름이나 설명으로
검색할 수 있고, "사용 안 함"으로 바꾼 템플릿은 "API 등록" 화면의 선택 목록에 나타나지
않습니다. 각 행의 "수정"/"삭제" 버튼으로 관리합니다.

## 새 템플릿 만들기

"+ 새 템플릿" 버튼을 누르면 등록 폼으로 이동합니다. 입력 항목은 다음과 같습니다.

| 항목 | 필수 | 설명 |
|---|---|---|
| 템플릿 이름 | O | 목록에 표시되는 이름 |
| API 구분 | X | Public/Private/Internal (기본값 Public) |
| 설명 | X | 이 템플릿이 어떤 상황에 쓰이는지 |
| YAML(OAS 3.0) | O | 이 템플릿이 채워줄 API의 형태를 YAML로 작성 |

**Path나 Method, 파라미터를 별도 입력칸에 직접 입력하는 게 아니라, OAS 3.0 YAML을
붙여넣으면 그 안에서 자동으로 추출됩니다.** [미리보기] 버튼을 누르면 YAML을 해석해서
API 이름/Method/Path/파라미터 목록을 화면에서 확인할 수 있고, [저장]을 누르면 그 미리보기
결과가 그대로 템플릿 데이터로 저장됩니다.

> YAML에 여러 Path/Method가 들어있어도 템플릿에는 **첫 번째 것만** 반영됩니다(템플릿은
> API 한 건을 채우는 용도라서). 그룹 전체(API 여러 건)를 한 번에 등록하고 싶다면 템플릿이
> 아니라 "API 그룹(스펙) 등록" 화면의 "YAML 등록" 기능을 씁니다([[spc-등록]] 참고).

## 자주 묻는 질문

**Q. 템플릿을 만들었는데 "API 등록" 화면의 "템플릿으로 시작"에 안 보여요.**
A. 템플릿의 "사용여부"가 "사용"으로 되어 있는지 확인하세요. "중지" 상태인 템플릿은 목록에
나타나지 않습니다. 또한 YAML 미리보기 없이 저장을 시도하면 저장되지 않으니, 저장 전에
[미리보기]로 정상 해석되는지 먼저 확인하는 것이 좋습니다.

**Q. Path를 직접 입력하는 칸이 없는데 어떻게 정하나요?**
A. 이 화면은 값을 최소한만 직접 입력받고 나머지(Path/Method/파라미터)는 붙여넣은 YAML에서
자동으로 뽑아내는 방식입니다. YAML의 `paths` 항목에 원하는 경로와 Method를 적어주면 됩니다.

**Q. 템플릿과 "API 그룹(스펙) 등록"의 YAML 등록은 같은 기능인가요?**
A. 아닙니다. 템플릿은 API **한 건**을 채우는 용도(API 등록 화면에서 사용)이고, 그룹 등록의
YAML 등록은 그룹과 그 안의 **여러 API**를 한 번에 만드는 용도입니다.
