# 01. 시작하기

개발 PC에 올려 첫 질문에 답이 나오는 것까지 확인하는 문서입니다.

## 준비물

| 항목 | 버전 | 비고 |
| --- | --- | --- |
| Python | **3.11** | 3.12 이상에서는 `chroma-hnswlib` 휠이 없어 설치가 실패합니다 |
| Ollama | 최신 | 임베딩 모델을 돌립니다 |
| 임베딩 모델 | `bge-m3` | 약 1.1GB |
| LLM (studio만) | `gemma4:latest` 등 | 약 9GB. QA를 직접 생성할 때만 필요합니다 |

운영은 GPU가 없는 환경이라 **serve 모드에서는 LLM을 받지 않아도 됩니다.**

---

## 설치

```bash
cd forever-chat-serve

python -m venv .venv
.venv\Scripts\activate                 # Linux/macOS: source .venv/bin/activate

pip install -r requirements.txt

copy .env.example .env                 # Linux/macOS: cp .env.example .env
ollama pull bge-m3
```

`.env` 에서 최소한 이 값을 확인하세요.

```
APP_MODE=serve            # QA를 직접 생성하려면 studio
ADMIN_PASSWORD=change-me  # 반드시 바꾸세요. 기본값이면 기동 로그에 경고가 남습니다
```

전체 항목 설명 → [06. 설정](06-설정.md)

## 초기 데이터 심기

**이 단계를 건너뛰면 모든 질문이 `unresolved` 로 떨어집니다.** 버그가 아니라 벡터 저장소가
비어 있어서입니다.

```bash
python scripts/seed_categories.py       # 카테고리 48개 (대분류 5). 1회용
python scripts/seed_demo_qa.py --force  # 문서 색인 + 데모 QA 3건
```

| 스크립트 | 하는 일 | 다시 돌려도 되나 |
| --- | --- | --- |
| `seed_categories.py` | `data/categories.json` 생성 | 덮어씁니다. 카테고리를 편집했다면 주의 |
| `seed_demo_qa.py --force` | `data/raw_docs/*.md` 색인 + 데모 QA 3건 승인 상태로 삽입 | `--force` 는 기존 색인을 다시 만듭니다 |

## 실행

```bash
python -m uvicorn app.main:app --reload --port 18100
```

Windows에서는 **`실행.bat` 더블클릭**이 위 과정을 대신합니다. 가상환경과 벡터 저장소가 없으면
만들고, 서버를 띄운 뒤 브라우저를 엽니다. 종료는 `stop.bat` (18100 포트를 잡고 있는 프로세스만
종료합니다).

판단과 안내 문구는 `scripts/launch.py` · `scripts/stop.py` 에 있습니다.

> **`.bat` 에는 한글을 쓰지 마세요 — 주석에도.** cmd 가 배치 파일을 콘솔 코드페이지(949)로
> 읽어서 UTF-8 한글이 섞이면 파서가 어긋나고 단어 조각이 명령으로 실행됩니다.

## 첫 확인

### 1) 준비 상태

```bash
curl http://localhost:18100/health/ready
```

```json
{"mode":"serve","ollama":"ok","embed_model":"ok","qa_serving":3,"status":"ok"}
```

| 필드 | 봐야 할 것 |
| --- | --- |
| `ollama` | `ok` 가 아니면 Ollama 가 안 떠 있습니다 |
| `embed_model` | `missing` 이면 `ollama pull bge-m3` 를 안 했습니다 |
| `qa_serving` | **0이면 답할 QA가 없습니다.** 시드를 안 돌렸거나 전부 `pending` 입니다 |
| `status` | 위 둘이 충족돼야 `ok`, 아니면 `degraded` |

프로세스가 떠 있는 것과 답할 수 있는 것은 다릅니다. `/health` 는 프로세스만, `/health/ready`
는 답할 준비까지 봅니다.

### 2) 챗봇 화면

http://localhost:18100/ 에서 "API 등록은 어떻게 하나요?" 를 물어봅니다.

| 나온 것 | 뜻 |
| --- | --- |
| 답변 + 출처 | 정상 (`result_type=answer`) |
| 관련 문서 카드 | QA는 못 찾고 문서만 찾음 (`related_docs`) |
| 접수번호 | 둘 다 못 찾음 (`unresolved`) |

입력창 위에 **`주제 선택` 버튼**이 보여야 합니다. 안 보이면 카테고리가 비어 있다는 뜻입니다.

### 3) 관리자 화면

http://localhost:18100/admin — 로그인 모달이 뜹니다. `.env` 의 `ADMIN_USERNAME` /
`ADMIN_PASSWORD` 로 들어갑니다.

챗봇 화면 헤더의 **[관리자]** 버튼으로도 들어갈 수 있습니다.

## 문제 해결

### 모든 질문이 `unresolved` 로 떨어집니다

`data/chroma/` 가 없거나 비어 있습니다. 가장 흔한 경우입니다.

```bash
python scripts/seed_demo_qa.py --force
```

이미 QA를 넣었다면 상태를 확인하세요. **`approved` 인 QA만** 벡터 인덱스에 올라갑니다.
`pending` 으로만 쌓여 있으면 검색되지 않습니다 → [08. QA 생성과 검수](08-QA-생성과-검수.md)

### `pip install` 이 `chroma-hnswlib` 에서 실패합니다

Python 3.12 이상입니다. **3.11로 가상환경을 다시 만드세요.**

```bash
py -3.11 -m venv .venv
```

### `ollama` 연결 오류

Ollama 데몬이 떠 있는지 확인합니다.

```bash
ollama list                 # 설치된 모델 목록
curl http://localhost:11434/api/tags
```

`.env` 의 `OLLAMA_HOST` 가 실제 주소와 같은지도 봅니다.

### 첫 질문만 느립니다 (3초 안팎)

임베딩 모델을 처음 메모리에 올리는 비용입니다. 두 번째부터는 0.6~0.9초입니다.

### 화면은 뜨는데 카테고리가 비어 있습니다

```bash
curl http://localhost:18100/api/categories
```

`groups` 가 비었으면 `python scripts/seed_categories.py` 를 돌리세요.

### 관리자 화면에서 QA 편집이 안 됩니다

**serve 모드에서는 `QA 인덱스` 의 편집이 읽기 전용입니다.** 검수는 스튜디오에서 하고 결과
파일을 배포한다는 전제이기 때문입니다.

다만 **`검수` 화면의 승인은 serve 에서도 됩니다** — 운영에 쌓인 질문에서 만든 QA를 그
자리에서 승인해야 하는 경우가 있습니다. 항목 자체를 크게 고쳐야 하면 `.env` 에
`APP_MODE=studio` 로 띄웁니다.

### QA 생성 API가 403을 냅니다

`APP_MODE=serve` 입니다. 생성·평가·문서편집은 studio 전용입니다.

### 임베딩 모델을 바꿨더니 검색이 이상합니다

**반드시 재색인해야 합니다.** 차원이 다릅니다(bge-m3 1024 ↔ embeddinggemma 768).

```bash
curl -u admin:비밀번호 -X POST "http://localhost:18100/api/admin/qa/reindex?include_docs=true"
```

### 포트가 이미 사용 중입니다

```bash
stop.bat                                    # Windows
netstat -ano | findstr :18100               # 잡고 있는 PID 확인
```

## 로그 보는 법

애플리케이션 로그는 **JSON 한 줄에 한 건**이고 위치는 `.env` 의 `LOG_FILE` 이 정합니다.
5MB씩 5개까지 회전합니다 — 상한이 없으면 지우는 사람이 없어 파일 하나가 수 GB가 됩니다.

```
LOG_FILE=C:/chatapp/logs/app.jsonl     # 개발 PC 예시. 저장소 밖에 두면 다시 받아도 로그가 남습니다
```

기본값은 `./data/logs/app.jsonl` 입니다. **코드 기본값은 그대로 두세요** — 운영은 Linux라
절대경로를 박으면 배포가 깨집니다.

`data/question_log.jsonl`(질문 이력)은 로그가 아니라 **데이터**입니다. 관리자 화면이
읽어가므로 `data/` 에 그대로 둡니다.
