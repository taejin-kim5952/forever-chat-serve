## 1. 전제 — 운영에 GPU가 없습니다

이 저장소의 거의 모든 설계가 이 한 줄에서 나옵니다.

1차 프로젝트(`openapi-chat`)는 질문이 올 때마다 LLM이 답변을 **생성**했습니다. 운영 서버
(Azure AKS)에 GPU가 없어 답변 1건에 **1~3분**이 걸렸고, 그대로는 운영에 올릴 수 없었습니다.

그래서 무거운 작업을 실시간 경로 밖으로 뺐습니다.

```
[사전 · 사내 작업 PC]
  문서 ──LLM──> 질문+답변 초안 ──사람 검수──> qa_index.json

[실시간 · 운영 서버]
  질문 ──임베딩 1회──> 가장 가까운 질문 검색 ──> 그 답변을 그대로 반환
```

| | 1차 (`openapi-chat`) | 지금 (`openapi-chat-serve`) |
| --- | --- | --- |
| 답변 생성 시점 | 질문할 때마다 | 미리, 사람 검수까지 |
| 운영에 필요한 모델 | 임베딩 + 답변 LLM (13GB) | **임베딩 하나** (1.1GB) |
| 응답 시간 | 1~3분 | **0.6~0.9초** |
| 답변 품질 보증 | 없음 (매번 새로 생성) | **사람 검수** |

> **운영 경로(`app/pipeline/retrieve.py`)에서 LLM을 호출하는 코드를 다시 넣는 것은 이
> 프로젝트의 전제를 뒤집는 일입니다.** `app/studio/` 를 import 하면 안 됩니다.

## 2. 질문 하나가 지나가는 경로

`app/pipeline/retrieve.py` — 운영에서 실제로 도는 유일한 경로입니다.

```
질문 ──임베딩(1회)──┬─→ QA 인덱스 검색 ── ≥ qa_match_threshold(0.90) ─→ answer
                    │
                    └─→ 문서 인덱스 검색 ── ≥ related_docs_floor(0.55) ─→ related_docs (최대 3)
                                          └─ 그 미만 ──────────────────→ unresolved (접수번호)
```

### 임베딩은 질문당 한 번만 계산합니다

가장 비싼 단계입니다. 여기서 두 번 돌리면 응답 시간이 그대로 두 배가 됩니다. 한 번 계산한
벡터를 **세 곳**에서 돌려 씁니다.

1. QA 인덱스 검색
2. 문서 인덱스 검색
3. 질문 이력 저장 (`data/question_embeddings.jsonl`, base64 float32)

3번에 남긴 벡터는 나중에 **질문 군집 분석**이 재사용합니다. 그래서 분석도 LLM 없이,
재임베딩 없이 돌아갑니다 — GPU 없는 운영에서는 이게 필수입니다.

### 판단은 서버가 합니다

`result_type` 은 서버가 정하고 화면(`app/static/chat.js`)은 그대로 그립니다.

**화면이 유사도를 보고 다시 판단하면 관리자 설정과 실제 동작이 조용히 어긋납니다.**
관리자가 임계값을 0.85로 내렸는데 화면이 0.90으로 판단하면, 설정 화면은 0.85를 보여주면서
실제로는 0.90처럼 동작합니다. 아무도 눈치채지 못합니다.

### 두 임계값의 관계

```
유사도 1.00 ─┐
             │  ≥ qa_match_threshold (0.90)   → answer      검수된 답변
      0.90 ─┤
             │  ≥ related_docs_floor (0.55)   → related_docs 관련 문서 카드
      0.55 ─┤
             │  < related_docs_floor          → unresolved   접수번호
      0.00 ─┘
```

**`related_docs_floor < qa_match_threshold` 를 서버가 강제합니다.** 역전되면 `related_docs`
구간이 사라져 답을 못 찾은 질문이 전부 `unresolved` 로 떨어집니다.

## 3. 데이터 소유 방향 — 파일이 원본, 벡터는 파생물

```
data/qa_index.json      ★ 사용자에게 나가는 답변 전부. 가장 중요한 파일
data/categories.json      질문 주제 (대분류 5 / 카테고리 48)
data/raw_docs/*.md        원본 문서
data/chroma/            ← 위 셋에서 파생. 지워도 reindex 로 복구. 저장소에 없음
```

이렇게 한 이유가 둘입니다.

1. **폐쇄망 배포가 파일 3개 복사로 끝납니다.** DB를 세울 필요가 없습니다.
2. **검수 결과를 사람이 diff 로 볼 수 있습니다.** 누가 무슨 답변을 고쳤는지 git 으로 봅니다.

### 저장 순서는 항상 파일 먼저, 벡터 다음

`app/api/admin_qa.py` 를 보면 파일을 먼저 쓰고 벡터를 나중에 씁니다.

**벡터를 먼저 쓰면 파일 저장이 실패했을 때 검색은 새 답변을, 화면은 옛 답변을 보여주는
상태가 됩니다.** 반대 순서면 최악이라도 "저장은 됐는데 검색에 아직 안 걸림"이고, 재색인으로
복구됩니다.

### `approved` 만 서비스됩니다

```python
# app/qa/store.py
QaStatus = Literal["pending", "approved", "hold", "disabled"]
SERVING_STATUSES = {"approved"}
```

AI 초안이 검수 없이 사용자에게 새어 나가는 경로를 **구조적으로** 없앤 것입니다. 화면에서
막는 게 아니라 인덱스에 아예 올리지 않습니다.

| 상태 | 뜻 | 인덱스에 올라가나 |
| --- | --- | --- |
| `pending` | 검수 대기 (생성 직후 기본값) | ✕ |
| `approved` | 승인 — 사용자에게 나갑니다 | **○** |
| `hold` | 보류 | ✕ |
| `disabled` | 미사용 | ✕ |

## 4. 두 가지 모드 — `APP_MODE`

| 모드 | 위치 | 하는 일 |
| --- | --- | --- |
| `serve` | 운영 서버 | 검색·응답 + 질문 이력/분석 + QA 조회. **LLM 없음** |
| `studio` | 사내 작업 PC | 위 전부 + QA 사전 생성 · 품질 평가 · 문서 편집 |

같은 코드가 모드만 바꿔 뜹니다. studio 전용 기능은 `_require_studio()` 패턴으로 **403**을
냅니다 (`app/api/admin_docs.py` · `app/api/studio_generate.py`).

**LLM을 부르는 코드는 `app/studio/` 안에만 있습니다.**

### 화면의 모드 처리

`/admin` HTML은 서버가 `<body data-mode>` 를 **직접 치환**해 내려줍니다 (`app/main.py`).

화면이 켜진 뒤 API로 모드를 물어보면 **운영에서 동작하지 않는 탭이 잠깐 보였다 사라집니다.**
사용자에게는 버그로 보입니다.

## 5. 설정이 두 겹인 이유

| 종류 | 파일 | 언제 반영되나 |
| --- | --- | --- |
| 기동 설정 | `app/core/config.py` (`Settings`) — 환경변수/`.env` | **재시작해야** 반영. `@lru_cache` |
| 런타임 설정 | `app/core/runtime_config.py` — `data/runtime_config.json` | **매 요청마다 파일을 다시 읽어** 즉시 반영 |

임계값처럼 운영 중에 조정하는 값은 관리자 화면(탭 ⑧)에서 바꾸고 재시작 없이 적용돼야
합니다. 그래서 두 겹입니다 → [06. 설정](06-설정.md)

## 6. 요청이 지나가는 계층

```
브라우저
  │
  ▼
FastAPI 라우터                app/api/*.py
  │  ├─ 공개    /api/*         인증 없음
  │  ├─ 관리자  /api/admin/*   require_admin (세션 쿠키 또는 Basic)
  │  └─ 스튜디오 /api/studio/*  require_admin + studio 모드
  ▼
파이프라인 / 저장소            app/pipeline/ · app/qa/ · app/core/
  ▼
Chroma (벡터)  ·  JSON 파일 (원본)
```

### 인증

관리자 인증은 **세션 쿠키**입니다. 로그인 모달에서 아이디·비밀번호를 보내면 서버가 서명된
토큰을 `httponly` 쿠키로 심습니다. 스크립트용 **Basic 인증도 그대로 살아 있습니다** —
배포·점검 절차가 `curl -u` 방식으로 적혀 있기 때문입니다.

**401 응답에 `WWW-Authenticate` 를 붙이지 않습니다.** 붙이면 브라우저 기본 로그인 창이 우리
모달과 겹쳐 뜨고, 그 창으로 로그인하면 화면은 로그인 사실을 모릅니다.

로그인 실패는 **서버에서도** 막습니다 — 5회 실패 시 30초 잠금(IP 단위, 메모리에만 기록).
화면 코드는 사용자가 얼마든지 건너뛸 수 있기 때문입니다.

## 7. 벡터 인덱스 두 벌

| 컬렉션 | 무엇이 들어가나 | 무엇에 쓰나 |
| --- | --- | --- |
| `qa_index` | 검수된 QA의 **대표 질문 + 변형 질문** | `answer` 판정 |
| `doc_chunks` | 문서를 `##` · `###` 단위로 자른 청크 | `related_docs` 판정 |

### 적중률은 사실상 변형 질문 목록이 정합니다

실측 예시입니다.

| 질문 | 유사도 | 결과 |
| --- | --- | --- |
| "API 등록은 어떻게 하나요?" (대표 질문) | 1.000 | answer |
| "API 등록하는 방법 알려줘" (변형에서 걸림) | 0.974 | answer |
| "API 그룹 코드 규칙이 있나요?" | 0.657 | related_docs |
| "점심 메뉴 추천해 주세요" | 0.503 | unresolved |

변형 질문이 없으면 표현이 조금만 달라도 못 찾습니다. 그래서 생성 단계에서 항목당 8~15개를
따로 만듭니다.

### 변형 질문은 "먼저 지우고 다시 넣습니다"

`app/qa/index.py` 는 upsert 만 하지 않고 해당 QA의 벡터를 **전부 지운 뒤** 다시 넣습니다.
upsert 만 하면 삭제한 변형 질문의 벡터가 인덱스에 남아 계속 걸립니다.

## 8. 이 구조에서 지켜야 할 선

| 하지 말 것 | 왜 |
| --- | --- |
| `retrieve.py` 에서 `app/studio/` import | 운영에 LLM이 들어옵니다. 프로젝트 전제가 깨집니다 |
| 화면에서 유사도로 재판단 | 관리자 설정과 실제 동작이 어긋납니다 |
| 벡터를 파일보다 먼저 저장 | 실패 시 검색과 화면이 다른 답변을 보여줍니다 |
| `pending` 을 인덱스에 올리기 | 검수 안 된 AI 초안이 사용자에게 나갑니다 |
| 임베딩을 질문당 두 번 계산 | 응답 시간이 두 배가 됩니다 |
| 모델 바꾸고 재색인 안 하기 | 예외가 나거나, 더 나쁘게는 조용히 엉뚱한 결과를 줍니다 |
