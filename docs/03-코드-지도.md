## 처음 읽는 순서

```
① app/pipeline/retrieve.py   질문 하나가 지나가는 전체 경로 — 여기서 시작하세요
② app/qa/store.py            QA가 어떻게 저장되고 어떤 상태만 서비스되는가
③ app/qa/index.py            벡터 인덱스에 어떻게 올라가는가
④ app/core/config.py         조절 가능한 값이 무엇인가
⑤ app/api/ask.py             화면이 부르는 공개 API
```

이 다섯 개면 실시간 경로 전체가 손에 들어옵니다. 나머지는 필요할 때 찾아보면 됩니다.

각 파일 **상단 독스트링에 설계 의도**가 적혀 있습니다. 고치기 전에 먼저 읽으세요.

## 계층별 설명

### `app/api/` — 라우터

**얇게 유지합니다.** 요청을 받아 검증하고 파이프라인/저장소를 부르고 응답을 만드는 것까지만
합니다. 비즈니스 로직은 `pipeline/` · `qa/` · `studio/` 에 둡니다.

라우터는 세 종류입니다.

| 접두사 | 인증 | 비고 |
| --- | --- | --- |
| `/api/*` | 없음 | 챗봇이 씁니다 |
| `/api/admin/*` | `require_admin` (라우터 단위 `dependencies`) | `admin_auth` 만 예외 |
| `/api/studio/*` | `require_admin` + studio 모드 | serve 에서 403 |

`admin_auth.py` 에만 인증이 안 걸려 있습니다 — 로그인하기 전에 부르는 경로이기 때문입니다.

### `app/core/` — 공통 기반

| 파일 | 알아둘 점 |
| --- | --- |
| `config.py` | `@lru_cache` 라 기동 후 바뀌지 않습니다. 테스트는 `cache_clear()` 로 갈아끼웁니다 |
| `runtime_config.py` | 매 요청 파일을 다시 읽습니다. 재시작 없이 반영되어야 하기 때문입니다 |
| `jsonstore.py` | 임시파일에 쓰고 rename 합니다. 쓰다가 죽어도 반쪽 파일이 남지 않습니다 |
| `question_log.py` | 질문 이력(JSONL) + 질문 임베딩(base64 float32) + 접수번호 채번 |
| `session.py` | `session_secret` 이 비면 기동할 때마다 새 키를 만듭니다 (파드 여러 개면 반드시 지정) |

### `app/ingestion/` — 문서를 벡터로

**청킹 규칙**: `##` 뿐 아니라 `###` 까지 자릅니다. 한 절에 항목이 여러 개면 청크가 3천 자에
달하고, 그러면 (1) 벡터가 뭉개져 검색이 흐려지고 (2) 카드에 보여줄 발췌를 고를 수 없습니다.
`###` 청크는 부모 제목을 잃기 쉬우므로 `section_path` 에 `부모 > 자식` 으로 남깁니다.

**태스크 접두어**: 모델마다 규칙이 다릅니다. `bge-m3` 는 접두어를 붙이면 손해고,
`embeddinggemma` 는 붙여야 합니다. **색인할 때와 검색할 때 같은 규칙을 써야 합니다** —
어긋나도 예외는 안 나고 검색 품질만 조용히 무너집니다. 표는 `embedder.py` 에 있습니다.

**모델 불일치 검사**: 컬렉션 메타데이터에 색인에 쓴 모델을 적어 두고, 다르면
`EmbedModelMismatch` 를 던집니다.

### `app/qa/` — QA 저장소와 색인

`store.py` 가 파일(원본), `index.py` 가 벡터(파생)를 담당합니다. **순서는 항상 store 먼저,
index 다음입니다** → [02. 아키텍처](02-아키텍처.md#저장-순서는-항상-파일-먼저-벡터-다음)

`index.py` 의 변형 질문 처리는 **먼저 지우고 다시 넣습니다.** upsert 만 하면 삭제한 변형
질문의 벡터가 남습니다.

### `app/pipeline/` — 실시간 경로

`retrieve.py` 는 `Retriever` 객체로 인덱스 핸들을 들고 있습니다. 요청마다 Chroma 컬렉션을
새로 여는 비용이 응답 시간에서 무시할 수 없기 때문입니다.

`analytics.py` 는 질문 이력을 군집으로 묶습니다. **LLM을 쓰지 않습니다** — 대표 질문은 군집
중심에 가장 가까운 실제 질문이고, 요약은 묶인 표현 가짓수를 셉니다. 답변할 때 저장해 둔 질문
임베딩을 재사용하므로 재임베딩도 없습니다. 그래서 운영에서도 돌아갑니다.

사람이 지정한 상태·주제는 `overrides` 로 따로 보관해 **다시 분석해도 남습니다.**
군집 상태는 `new` · `reviewed` · `generated` · `applied` · `excluded` 입니다.

### `app/studio/` — LLM을 부르는 유일한 곳

```
generate.py   문서 청크 ─[LLM]─> 질문+답변 ─[LLM]─> 변형 질문 8~15개
              질문 목록 ─검색─> 발췌 ─[LLM]─> 근거 있음? ─> 답변 / 없으면 버림
runner.py     위를 백그라운드로 돌리고 진행률·중지·반영을 관리
evaluate.py   검수된 QA의 변형 질문으로 검색 품질 측정 (LLM 안 씀)
korean.py     한국어 판별 — 모델이 영어를 섞는 것을 막습니다
```

자세히 → [08. QA 생성과 검수](08-QA-생성과-검수.md)

## 새 기능은 어디에 붙이나

| 만들고 싶은 것 | 어디에 |
| --- | --- |
| 챗봇이 쓰는 새 조회 | `app/api/ask.py` + `app/models/schemas.py` |
| 관리자 화면의 새 탭 | `app/api/admin_*.py` 새 파일 + 라우터 등록(`main.py`) |
| LLM을 쓰는 기능 | **반드시 `app/studio/`** + `_require_studio()` 게이팅 |
| 검색 로직 변경 | `app/pipeline/retrieve.py` |
| 새 저장 파일 | `app/core/config.py` 에 경로 추가 → **`tests/conftest.py` 의 `overrides` 에도 추가** |
| 새 화면 | `app/static/` + `main.py` 라우트. **컨트롤러·서비스도 새로 만듭니다** |

> **경로 설정을 새로 추가하면 `tests/conftest.py` 의 `overrides` 에 반드시 넣으세요.**
> 빠뜨리면 그 파일만 실제 `data/` 를 가리켜 테스트가 운영 데이터를 덮어씁니다. 실제로 겪은
> 일이라, 지금은 임시 폴더 밖을 가리키는 경로가 있으면 테스트가 그 자리에서 멈춥니다.

## 새 모듈이 `get_settings` 를 쓸 때

`tests/conftest.py` 의 모듈 목록에 추가해야 격리가 걸립니다.

```python
for module in [
    "app.core.categories", "app.core.question_log", ...
    "여기에 새 모듈 추가",
]:
```

`OllamaEmbedder` 를 import 하는 모듈도 마찬가지입니다 (`fake_embedder` 픽스처).

## 화면 코드

| 파일 | 역할 |
| --- | --- |
| `chat.*` | 사용자 챗봇 |
| `admin.*` | 관리자 화면 — 사이드바 10항목(진행 현황 · 검수 포함) + 로그인 모달 |

**`chat.js` 의 마크다운 렌더를 고치면 `admin.js` 도 같이 고쳐야 합니다.** 검수 미리보기와
사용자 말풍선이 달라지면 검수가 의미를 잃습니다. 공용 파일로 못 빼는 이유는 인수인계 문서
5-13에 있습니다.
