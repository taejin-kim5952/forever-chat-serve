## 챗봇 화면 (`chat.*`)

### 구성

```
헤더        브랜드 · 설명 · [관리자] · [새 대화]
대화 영역   인트로(자주 찾는 주제) → 말풍선들
입력 영역   [주제 선택 ▾] [추천 질문 ▾]
            [질문 입력................] [전송]
            "AI가 만든 답변을 담당자가 검수한 내용입니다."
```

### 응답 세 가지를 그리는 템플릿

`<template>` 태그로 정의돼 있고 `chat.js` 가 복제해 씁니다.

| 템플릿 | 언제 |
| --- | --- |
| `tpl_user` | 사용자 말풍선 |
| `tpl_answer` | `result_type=answer` — 답변 + 출처 배지 + 검수 표시 + 복사 |
| `tpl_related` / `tpl_related_item` | `related_docs` — 문서 카드 + "담당자에게 문의하기" |
| `tpl_unresolved` | `unresolved` — 접수번호 + 복사 |
| `tpl_loading` | 응답 대기 점 3개 |
| `tpl_error` | 통신 실패 + 다시 시도 |

> **화면은 `result_type` 을 그대로 따릅니다.** 유사도를 보고 다시 판단하지 않습니다 —
> 그러면 관리자 설정과 실제 동작이 조용히 어긋납니다.

### 모달

| 모달 | 용도 |
| --- | --- |
| `#chatDocModal` | 출처·관련 문서 원문 보기 |
| `#chatResetModal` | 새 대화 확인 — **접수번호가 포함된 대화일 때만** 뜹니다 |
| `#chatAdminModal` | 관리자 로그인 |

새 대화 확인이 조건부인 이유: 접수번호는 사용자가 담당자에게 불러 줘야 하는 값이라 지우면
다시 볼 수 없습니다.

### 관리자 로그인 모달

헤더의 **[관리자]** 버튼으로 엽니다.

```
[관리자] 클릭
   ├─ GET /api/admin/session → 이미 로그인 상태면 팝업 없이 바로 /admin
   └─ 아니면 팝업 → POST /api/admin/login → 성공 시 location.href = '/admin'
```

`admin.html` 의 로그인 모달과 다른 점: **이 모달은 ESC · 배경 클릭 · ✕ 로 닫힙니다.**
저쪽은 관리자만 들어오는 화면이라 로그인 외에 할 일이 없지만, 챗봇 화면은 질문하러 온
사람이 대부분이라 실수로 열었을 때 빠져나갈 길이 필요합니다.

로그인 API는 `admin.js` 와 **같은 `/api/admin/login`** 을 씁니다. 화면이 다르다고 로그인
API를 따로 만들면 실패 잠금(서버가 IP 단위로 셈)이 두 벌로 갈라져, 한쪽이 잠겨도 다른
쪽으로 계속 찔러 볼 수 있게 됩니다.

아이디·비밀번호는 `localStorage` 포함 **어디에도 저장하지 않습니다.**

## 관리자 화면 (`admin.*`)

### 좌측 사이드바 10항목 — 순서가 곧 일하는 순서

그룹(`콘텐츠` · `운영` · `품질·설정`)은 **클릭할 수 없는 라벨**입니다. 접히지 않습니다 —
접으면 매일 하는 검수가 클릭 두 번이 됩니다.

| 그룹 | 항목 | `data-tab` | API | 모드 |
| --- | --- | --- | --- | --- |
| — | **진행 현황**(홈) | `flow` | `GET /api/admin/pipeline/status` | 공통 |
| 콘텐츠 | RAG 문서 | `docs` | `GET/POST/PUT/DELETE /api/admin/docs` | 편집은 **studio** |
| 콘텐츠 | 질문 카테고리 | `categories` | `GET/PUT /api/admin/categories` | 공통 |
| 콘텐츠 | QA 생성 ✳ | `generate` | `POST /api/studio/generate` … | **studio** |
| 콘텐츠 | **검수** | `review` | `POST /api/admin/qa` | 공통 (승인은 serve 에서도) |
| 콘텐츠 | QA 인덱스 | `qa` | `GET/POST /api/admin/qa` `/bulk` `/reindex` | 편집은 **studio** |
| 운영 | 질문 이력 | `history` | `GET /api/admin/questions` `/export` | 공통 |
| 운영 | 질문 분석 | `analytics` | `GET/POST /api/admin/analytics` … | 공통 |
| 품질·설정 | 품질 평가 ✳ | `eval` | `POST /api/studio/eval` … | **studio** |
| 품질·설정 | 설정 | `settings` | `GET/PUT /api/admin/settings` `/profile` | 공통 |

- 검수 항목에는 **대기 건수 배지**가 붙습니다(0이면 숨김, 100 이상은 `99+`).
  다른 항목에는 배지를 달지 않습니다 — 여럿이 빨가면 아무것도 안 읽힙니다
- 그룹의 항목이 **전부** 숨겨지면 그룹 라벨도 같이 숨깁니다
- 설정 안에는 하위 탭이 있습니다 — `매칭` / `생성`✳ / `납품처`

### 모드 처리 — `<body data-mode>`

`/admin` HTML은 서버가 `<body data-mode="serve">` 를 **직접 치환**해 내려줍니다
(`app/main.py`).

> 화면이 켜진 뒤 API로 모드를 물어보면 **운영에서 동작하지 않는 탭이 잠깐 보였다
> 사라집니다.** 사용자에게는 버그로 보입니다.

CSS가 `data-mode` 를 보고 studio 전용 탭을 감춥니다.

### 로그인 모달

`#authModal` 입니다. **ESC · 배경 클릭 · ✕ 로 닫히지 않습니다** (닫기 버튼 자체가 없습니다).
관리자 화면은 로그인 없이 할 수 있는 일이 없기 때문입니다.

`data-auth-reason="initial | expired"` 로 안내 문구만 달라집니다. 만료로 다시 로그인한
경우에는 배경 내용을 지우지 않고 **하던 작업을 이어서** 할 수 있게 합니다.

세션이 끊기면(401) 자동으로 다시 뜹니다.

```js
$(document).ajaxError(function(_, xhr, settings){
  if(xhr.status !== 401) return;
  if(String(settings.url).indexOf('/api/admin/login') > -1) return;
  $(document).trigger('admin:unauthorized');
});
```

### 검수와 QA 인덱스는 역할이 다릅니다 ★

둘 다 QA를 고칠 수 있어서 헷갈리기 쉽습니다.

| | `검수` | `QA 인덱스` |
| --- | --- | --- |
| 보는 것 | 검수대기(pending)**만** | 전체 4개 상태 |
| 주된 화면 | **한 건 상세** | 목록 |
| 핵심 조작 | `승인하고 다음 건` | 검색 · 필터 · 일괄 |
| 비유 | 결재함 | 자료실 |

**편집 폼은 같은 컴포넌트입니다** — `.admin_editor` 에 `tpl_qa_editor` 를 심고
`mountEditor('qa'|'rev')` 로 두 곳에서 씁니다. 두 벌로 두면 한쪽만 고쳐지고, 검수자가 본
모습과 사용자가 보는 모습이 갈립니다.

> 2026-08-16 까지 `/admin/review` 라는 별도 임시 화면이 있었습니다. 관리자 화면에 검수
> 항목이 생기면서 걷어냈습니다(`app/static/review.*` 삭제).

## ★ `chat.js` 와 `admin.js` 는 함께 고칩니다

**마크다운 렌더 규칙이 같아야 합니다.** 검수 미리보기와 사용자 말풍선이 달라지면 검수가
의미를 잃습니다 — 검수자가 본 모습과 사용자가 보는 모습이 다르면 무엇을 검수한 것인지
알 수 없습니다.

두 파일 모두 `renderMarkdown()` 을 각자 가지고 있습니다. 공용 파일로 못 빼는 이유는
인수인계 문서 5-13에 있습니다.

> 2026-08-16 까지는 `review.js` 가 세 번째 사본이었습니다. 검수가 관리자 화면 안으로
> 들어오면서 그 파일은 걷어냈고, 지금 사본은 **둘**입니다.

렌더하는 것: **굵게 · 목록 · 코드 · 문단**. 그 외 마크다운 문법은 그대로 글자로 보입니다.

## 퍼블 산출물 이식 규칙

화면은 퍼블리싱 담당자가 만든 산출물을 이식한 것입니다. 다시 받았을 때 덮어쓸 수 있도록
**구조·클래스·템플릿을 산출물 그대로 둡니다.**

이식할 때 하는 일:

1. 더미 데이터 제거 (`CATEGORY_GROUPS` · `DOC_FIXTURES` · `MOCK_ANSWER`)
2. 목업 바 제거
3. `setTimeout` 목업을 실제 API 호출로 교체
4. 서버 응답 필드명에 맞추기

우리가 추가한 블록은 **파일 맨 뒤에 따로** 둡니다. 퍼블이 다시 내려주면 그 블록만 아래에
다시 붙이면 되게 하려는 것입니다 (`chat.css` 의 관리자 로그인 블록이 그 예).

### 필드명 주의

`퍼블/admin.*` 과 `퍼블/chat.*` 중 일부는 **이전 프로젝트 것**입니다.

| | 이전 프로젝트 | 현재 (정본) |
| --- | --- | --- |
| 대분류 | `group_label` | `group_name` |
| 카테고리 ID | `id` | `category_id` |
| 카테고리 이름 | `label` | `name` |

**이식이 끝난 정본은 `app/static/` 입니다.**

## 화면을 새로 만들 때

- **컨트롤러·서비스도 새로 만듭니다.** 기존 엔드포인트를 재사용하지 않습니다
- 정적 파일은 `app/static/` 에 두고 `app/main.py` 에 라우트를 추가합니다
- `app/main.py` 의 `_render()` 로 내려보냅니다. `<body data-mode>` 와 브랜드 문자열을
  서버가 치환합니다
- 조직 이름·서비스 이름이 들어가는 자리는 **하드코딩하지 않고** `data-brand="{service_name}"`
  같은 속성을 붙입니다 (`app/core/profile.py`). 기본 텍스트는 그대로 두어 파일을 직접 열어도
  화면이 성립하게 합니다
- 외부 라이브러리를 추가하지 않습니다 — 폐쇄망입니다
