## 조용히 망가지는 것들

예외도 안 나고 로그도 안 남는데 결과만 나빠지는 것들입니다. **가장 위험합니다.**

### 1. 임베딩 모델을 바꾸고 재색인을 안 함

차원이 달라집니다 — `bge-m3` 1024, `embeddinggemma` 768.

컬렉션 메타데이터에 색인에 쓴 모델을 적어 두고 다르면 `EmbedModelMismatch` 를 던지게
해 뒀지만, **바꾼 뒤에는 반드시 재색인해야 합니다.**

```bash
curl -u admin:비밀번호 -X POST "http://localhost:18100/api/admin/qa/reindex?include_docs=true"
```

### 2. 태스크 접두어가 색인과 검색에서 어긋남

모델마다 규칙이 다릅니다.

| 모델 | 접두어 |
| --- | --- |
| `bge-m3` | **붙이면 손해** |
| `embeddinggemma` | **붙여야 함** |

색인할 때와 검색할 때 같은 규칙을 써야 합니다. **어긋나도 예외는 안 나고 검색 품질만
조용히 무너집니다.** 표는 `app/ingestion/embedder.py` 에 있습니다.

### 3. 변형 질문을 upsert 만 함

`app/qa/index.py` 는 **먼저 지우고 다시 넣습니다.** upsert 만 하면 삭제한 변형 질문의
벡터가 인덱스에 남아 계속 걸립니다. 화면에서는 지워졌는데 검색은 여전히 그 표현에 반응합니다.

### 4. 화면이 유사도를 보고 다시 판단함

`result_type` 은 서버가 정하고 화면은 그대로 그립니다.

화면이 다시 판단하면, 관리자가 임계값을 0.85로 내려도 화면은 0.90처럼 동작합니다. **설정
화면은 0.85를 보여주면서 실제로는 다르게 도는 상태**가 되고 아무도 눈치채지 못합니다.

### 5. `related_docs_floor` ≥ `qa_match_threshold`

역전되면 `related_docs` 구간이 사라져 답을 못 찾은 질문이 **전부 `unresolved`** 로
떨어집니다. 서버가 강제하지만, 직접 파일을 고칠 때는 주의하세요.

### 6. 임베딩을 질문당 두 번 계산

가장 비싼 단계입니다. 두 번 돌리면 **응답 시간이 그대로 두 배**가 됩니다. 한 번 계산해
QA 검색 / 문서 검색 / 질문 이력 세 곳에서 돌려 씁니다.

## 데이터가 날아가는 것들

### 7. ★ 새 경로 설정을 `conftest.py` 에 안 넣음

**테스트가 실제 `data/` 를 덮어씁니다.** 실제로 `generated_qa_file` 을 빠뜨려 테스트가 생성
초안 파일을 덮어쓴 적이 있습니다.

지금은 안전장치가 있습니다 — 이름이 `_file` · `_dir` 로 끝나는 설정 중 하나라도 임시 폴더
밖을 가리키면 **테스트가 그 자리에서 멈춥니다.**

경로 설정을 추가하면 `tests/conftest.py` 의 `overrides` 에 반드시 넣으세요.
→ [07. 테스트](07-테스트.md)

### 8. 벡터를 파일보다 먼저 저장

저장 순서는 **항상 파일 먼저, 벡터 다음**입니다 (`app/api/admin_qa.py`).

벡터를 먼저 쓰면 파일 저장이 실패했을 때 **검색은 새 답변을, 화면은 옛 답변을** 보여주는
상태가 됩니다. 반대 순서면 최악이라도 "저장은 됐는데 검색에 아직 안 걸림"이고 재색인으로
복구됩니다.

### 9. 테스트 로그가 실제 로그 파일에 섞임

`setup_logging()` 은 `app.main` 을 import 하는 순간(= 테스트 수집 시점) **실제 설정으로**
한 번 돕니다. conftest 가 핸들러를 다시 걸어 막습니다.

**실제 데이터를 건드리지 않는다는 규칙은 `data/` 뿐 아니라 로그 파일에도 적용됩니다.**

## 기동이 안 되는 것들

### 10. Python 3.12 이상

`chroma-hnswlib` 휠이 없어 `pip install` 이 실패합니다. **3.11** 을 쓰세요.

```bash
py -3.11 -m venv .venv
```

### 11. clone 직후 모든 질문이 `unresolved`

버그가 아닙니다. `data/chroma/` 가 없어서입니다.

```bash
python scripts/seed_demo_qa.py --force
```

### 12. `.bat` 파일에 한글

**주석에도 쓰지 마세요.** cmd 가 배치 파일을 콘솔 코드페이지(949)로 읽어서 UTF-8 한글이
섞이면 파서가 어긋나고, **단어 조각이 명령으로 실행됩니다.**

판단과 안내 문구는 `scripts/launch.py` · `scripts/stop.py` 에 두고 `.bat` 은 얇게 유지합니다.

### 13. 파드마다 로그인이 풀림

`SESSION_SECRET` 이 비어 있으면 기동할 때마다 새 서명 키를 만듭니다. 파드가 여러 개면
한 파드에서 로그인하고 다른 파드로 요청이 가면 **로그인이 풀립니다.**

파드를 늘릴 때는 반드시 값을 주세요.

## LLM 관련 (studio)

이 항목들은 1차 프로젝트(`openapi-chat`)에서 겪은 것이 많습니다. 원본 기록은
`forever-chat/작업내용.md` 3번에 있습니다.

### 14. 추론(thinking) 모델이 빈 응답을 냄

사고 과정만 내보내고 본문을 비웁니다 — **답변이 통째로 사라집니다.**

```
OLLAMA_THINK=false
```

### 15. 컨텍스트 창 초과로 조용히 잘림

프롬프트가 `OLLAMA_NUM_CTX` 를 넘으면 초과분이 **경고 없이** 잘립니다. 발췌를 미리 자르는
기준이기도 합니다.

답변이 늘 같은 지점에서 끊기면 `OLLAMA_NUM_PREDICT` 를, 참고 문서가 잘리는 것 같으면
`OLLAMA_NUM_CTX` 를 올립니다.

### 16. 프롬프트를 고치고 테스트만 돌림

> **테스트의 LLM은 가짜입니다.** 형식 이탈·문서 베끼기가 잡히지 않습니다.

실제로 겪은 것:

- 문서 도입부에서 **메타 질문**이 나옴 — "이 문서는 무엇을 설명하나요"
- 답변에 **문서 내부 표기**가 새어 나옴 — `[[api-등록]]`

둘 다 막아 뒀지만(`_is_document_lead`, `clean_answer`), 프롬프트를 고쳤으면 **반드시 소량으로
실제 모델을 돌려 눈으로 보세요.**

```bash
python scripts/generate_qa.py --max 2
```

### 17. 근거 없는 질문에 답을 지어냄

모델이 `근거: 없음` 을 선언하면 그 질문은 **버립니다.** 답을 만들면 검수자가 사실 여부를
문서와 대조하지 못한 채 승인하게 되고, 이 서비스의 유일한 품질 보증인 검수가 무력해집니다.

1차에서 유사도 숫자만으로 판단했다가 **"점심 메뉴 추천"에 억지 답변이 나간 적**이 있습니다.

### 18. 벤치마크 순위를 믿음

**MTEB 순위가 이 프로젝트 문서에서 뒤집힌 적이 있습니다.** 모델 비교는 반드시 품질 평가
기능(탭 ⑦)으로 자기 데이터에서 재세요.

### 19. 답변 품질이 나쁠 때 모델부터 의심함

**모델이 아니라 문서가 원인이던 경우**가 있었습니다. 검수 화면에서 출처 문서를 열어 원문을
먼저 확인하는 편이 빠릅니다.

## 화면 관련

### 20. `chat.js` 만 고치고 `admin.js` 를 안 고침

마크다운 렌더 규칙이 달라지면 **검수자가 본 모습과 사용자가 보는 모습이 달라집니다.**
검수가 의미를 잃습니다. `renderMarkdown()` 이 두 파일에 각각 있습니다
(검수 화면과 QA 인덱스 모달은 `admin.js` 안에서 편집 컴포넌트를 공용으로 쓰므로 한 곳입니다).

### 21. 새 화면을 만들었는데 뜨지 않음

화면은 `app/main.py` 의 `_render()` 를 거쳐야 합니다. `<body data-mode>` 와 브랜드 문자열을
여기서 치환합니다. 화면이 켜진 뒤 API로 물어보면 **동작하지 않는 탭이나 기본 조직 이름이
잠깐 보였다 바뀝니다.**

### 21-1. 조직 이름을 화면에 그대로 적음

`KT`·`API Manager 도우미` 를 마크업에 직접 쓰면 다른 조직에 설치할 때 소스를 고쳐야 합니다.
`data-brand="{organization}"` 속성을 쓰세요 → [`app/core/profile.py`](../app/core/profile.py)

### 22. 퍼블 산출물 필드명이 다름

`퍼블/` 안에 **이전 프로젝트 산출물**이 섞여 있습니다.

| 이전 | 현재 |
| --- | --- |
| `group_label` | `group_name` |
| `id` | `category_id` |
| `label` | `name` |

정본은 `app/static/` 입니다.

### 23. `참고/이전프로젝트/` 에서 import

**그 폴더는 실행되지 않습니다.** 구조가 바뀌었고 설정 이름도 다릅니다.

| 이전 | 현재 |
| --- | --- |
| `rag_retrieval_floor` | `qa_match_threshold` |
| `answered_by` | `result_type` |

## 설계 전제를 깨는 것

### 24. ★ 운영 경로에서 LLM 호출

`app/pipeline/retrieve.py` 에서 `app/studio/` 를 import 하면 **이 프로젝트의 전제가
무너집니다.** 운영 서버에 GPU가 없습니다.

LLM을 부르는 코드는 `app/studio/` 안에만 두고, `_require_studio()` 로 게이팅합니다.

### 25. `pending` 을 인덱스에 올림

`SERVING_STATUSES = {"approved"}` 입니다. 검수 안 된 AI 초안이 사용자에게 새어 나가는
경로를 **구조적으로** 막아 둔 것입니다. 화면에서 막는 게 아니라 인덱스에 아예 올리지
않습니다.
