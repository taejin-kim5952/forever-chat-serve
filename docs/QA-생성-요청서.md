# QA 생성 요청서 (외부 AI용)

> **이 파일을 쓰는 법**
>
> 1. **문서와 카테고리를 먼저 확정하세요.** QA는 그 둘을 근거로 만듭니다
>    ([RAG문서-작성-요청서.md](RAG문서-작성-요청서.md) → [카테고리-작성-요청서.md](카테고리-작성-요청서.md))
> 2. 아래 `---` **다음 줄부터 파일 끝까지** 복사해 AI에게 줍니다
> 3. 마지막 세 칸(**카테고리 목록** · **문서 목록** · **문서 본문**)을 실제 내용으로 채웁니다
>    — 카테고리 목록을 비워 두면 AI가 `category_id` 를 전부 비워 보냅니다(실제로 겪음)
> 4. 받은 JSON을 **⑥ QA 생성 → 외부 QA 가져오기** 에 붙여넣습니다
> 5. 미리보기로 확인하고 반영합니다. 들어온 항목은 **전부 검수 대기**이고,
>    **④ 검수** 에서 승인해야 챗봇이 답합니다
>
> 카테고리 목록은 관리자 **③ 질문 카테고리** 화면에서 `ID | 이름` 형태로 옮겨 적으면 됩니다.
>
> 같은 내용이 ⑥ 탭의 `QA 등록 규격` 버튼에도 있습니다. 둘 중 하나를 고치면 다른 하나도
> 함께 고쳐야 합니다 — `app/qa/importer.py` 가 실제로 받는 모양이 기준입니다.

---

사내 FAQ 챗봇에 등록할 **질문-답변 세트(QA)** 를 JSON 으로 만들어 주세요.

## 출력 형식

아래 구조를 그대로 지킵니다. **순수 JSON 만** 출력하고 설명·주석·코드 울타리를 붙이지 않습니다.

```json
{
  "items": [
    {
      "question": "API 등록은 어떻게 하나요?",
      "answer": "API 그룹(SPC)을 먼저 만든 뒤 등록 화면에서 API 명과 Path, Method 를 입력하고 저장합니다. 저장한 API는 검증 대기 상태가 되며, 검증을 통과해야 배포를 신청할 수 있습니다.",
      "variants": [
        "API 등록 절차 알려주세요",
        "api 어떻게 올려요?",
        "API 등록 방법",
        "새 API 추가하려면 뭐부터 해야 하나요",
        "API 만드는 순서가 어떻게 되나요",
        "API 신규 등록",
        "api 등록하려면요?",
        "API 올리는 방법 알려줘"
      ],
      "category_id": "api_reg_flow",
      "source_doc_ids": ["api-register-process"]
    }
  ]
}
```

| 항목 | 필수 | 설명 |
| --- | --- | --- |
| `question` | **필수** | 대표 질문. 사용자가 검색창에 칠 법한 한 문장 |
| `answer` | **필수** | 문서 내용만 근거로 한 답변. 3~6문장 또는 번호 목록 |
| `variants` | **필수** | 같은 뜻의 다른 표현 **8~15개** |
| `category_id` | **필수** | 아래 **카테고리 목록의 ID 중 하나.** 비워 두지 않습니다 |
| `source_doc_ids` | **필수** | 근거 문서의 **파일 이름**(확장자 없이). 예: `api-register-process` |

## 규칙

### 카테고리 — 비우지 마세요

- 아래 **카테고리 목록에 있는 ID만** 씁니다. 새로 만들지 않습니다
- 마땅한 것이 없으면 **가장 가까운 상위 주제**를 고릅니다
- 그래도 없으면 **그 QA를 만들지 않습니다.** 주제 없는 QA는 사용자가 주제를 골라도 안 걸립니다

### 근거 문서

- `source_doc_ids` 는 **파일 이름**입니다. `api-register-process.md` → `api-register-process`
- 앞머리의 `doc_id` 나 문서 제목이 아닙니다
- 두 문서에 걸친 답이면 둘 다 적습니다

### 답변

1. **문서에 적혀 있는 내용으로만** 답합니다. 없는 기능·수치·정책·화면을 지어내지 않습니다
2. 문서로 답할 수 없는 질문은 **아예 만들지 않습니다.** 개수를 채우려고 억지로 만들지 않습니다
3. **문서 문장을 그대로 베끼지 않습니다.** 질문에 답하는 형태로 다시 씁니다
4. 말투는 **`~합니다`** 체로 통일합니다
5. 화면명 · 경로 · 필드명 · 코드 · 버전 표기는 **문서에 적힌 그대로** 씁니다
6. `[[문서ID]]` 같은 내부 표기를 답변에 옮겨 쓰지 않습니다
7. "이 문서는 ~를 설명합니다" 같은 **문서 소개형 답변을 쓰지 않습니다**
8. 확실하지 않은 부분은 지어내지 말고 `(확인 필요)` 로 표시합니다. 사람이 검수할 때 채웁니다

### 변형 질문 — 적중률이 여기서 갈립니다

챗봇은 사용자의 질문이 등록된 질문과 **유사도 0.90 이상**일 때만 이 답변을 내보냅니다.
실측에서 `"API 등록은 어떻게 하나요?"` 는 1.000 이었지만 같은 뜻인
`"등록하는 방법 알려줘"` 는 0.974 였습니다. **변형이 좁으면 답이 있는데도 못 찾습니다.**

1. **8~15개**를 만듭니다
2. 표현을 섞습니다 — 정중한 문장, 짧은 구어체, 명사만 나열, 줄임말
   - 예: `"권한그룹은 무엇을 선택해야 하나요?"` · `"권한그룹 뭐 골라요?"` · `"권한그룹 선택 기준"`
3. **뜻이 달라지면 안 됩니다.** 범위를 넓히거나 좁히지 않습니다
   - 나쁜 예: `"API 등록은?"` 의 변형으로 `"API 삭제는?"`
4. 대표 질문의 어순만 바꾼 것으로 채우지 않습니다

### 몇 건을 만드나

- **문서 한 건당 5~8개**가 적당합니다. 소제목 하나에 1~2개로 보시면 됩니다
- 같은 것을 묻는 QA를 여러 개 만들지 않습니다. 서로 다른 것을 묻게 나눕니다
- 문서를 본 사람만 할 수 있는 질문은 만들지 않습니다
  (`"위 발췌에 따르면…"` · `"3번 항목은 무엇인가요?"`)

## 내보내기 전에 확인

- [ ] 모든 항목에 `category_id` 가 **채워져** 있습니까? 목록에 있는 ID 입니까?
- [ ] `source_doc_ids` 가 **파일 이름**입니까? (제목이나 `doc_id` 가 아닌지)
- [ ] 모든 `answer` 의 내용이 문서 안에 실제로 있습니까?
- [ ] `variants` 가 항목마다 8개 이상입니까?
- [ ] 같은 `question` 이 두 번 나오지 않습니까?
- [ ] 설명이나 코드 울타리 없이 JSON 만 출력합니까?

