# 질문 카테고리 작성 요청서 (외부 AI용)

> **이 파일을 쓰는 법**
>
> 1. **문서를 먼저 올리세요.** 카테고리는 올라간 문서에 맞춰 만듭니다
>    ([RAG문서-작성-요청서.md](RAG문서-작성-요청서.md))
> 2. 아래 `---` **다음 줄부터 파일 끝까지** 복사해 AI에게 줍니다
> 3. 맨 아래 **`문서 목록`** 과 **`문서 본문`** 칸을 채웁니다
> 4. 받은 JSON을 **③ 질문 카테고리 → JSON 가져오기** 에 붙여넣습니다
>    (올리기 전에 화면 위 **프로젝트 선택기**가 맞는지 확인하세요)
> 5. 그다음 [QA-생성-요청서.md](QA-생성-요청서.md) 로 QA를 받습니다 — 거기에 **이 카테고리
>    목록을 붙여넣어야** QA에 주제가 붙습니다
>
> **순서는 문서 → 카테고리 → QA 입니다.** 카테고리는 문서를 보고 만들고, QA는 그 둘을 보고
> 만듭니다. 순서를 바꾸면 문서 없는 빈 주제나 주제 없는 QA가 생깁니다.
>
> 같은 내용이 ③ 탭의 `카테고리등록규격` 버튼에도 있습니다.

---

사내 FAQ 챗봇의 **질문 카테고리**를 JSON 으로 만들어 주세요.

## 카테고리가 무엇에 쓰이는가

사용자가 챗봇 입력창 왼쪽에서 고르는 **주제**입니다. 두 가지 일을 합니다.

- 사용자가 주제를 고르면 그 주제의 **추천 질문**이 떠서, 무엇을 물을 수 있는지 알려 줍니다
- 등록되는 **QA 하나하나가 이 주제 중 하나에 묶입니다.** 그래서 주제가 없으면 QA를 분류할
  수 없습니다

**대분류 → 카테고리** 2단계입니다.

## 출력 형식

아래 구조를 그대로 지킵니다. **순수 JSON 만** 출력하고 설명·주석·코드 울타리를 붙이지 않습니다.

```json
{
  "groups": [
    {
      "group_id": "apiops_guide",
      "group_name": "API등록 및 배포 가이드",
      "categories": [
        {
          "category_id": "apiops_process",
          "name": "등록·배포 절차",
          "questions": [
            "API 등록부터 운영 배포까지 절차가 어떻게 되나요?",
            "운영 배포는 누가 승인하나요?",
            "TB 배포와 운영 배포는 무엇이 다른가요?"
          ]
        },
        {
          "category_id": "apiops_register_fields",
          "name": "등록 화면 입력 항목",
          "questions": [
            "API 등록할 때 필수 입력 항목은 무엇인가요?",
            "Path 는 어떻게 적나요?"
          ]
        }
      ]
    }
  ],
  "quick_category_ids": ["apiops_process", "apiops_register_fields"]
}
```

| 항목 | 필수 | 설명 |
| --- | --- | --- |
| `group_id` | **필수** | 대분류 ID. **공백·따옴표 불가**, 64자 이내, 파일 안에서 유일 |
| `group_name` | **필수** | 화면에 보이는 대분류 이름 |
| `category_id` | **필수** | 카테고리 ID. 규칙은 `group_id` 와 같습니다 |
| `name` | **필수** | 화면에 보이는 이름. **12자 안팎**이 보기 좋습니다 |
| `questions` | **필수** | 추천 질문 **2~4개**. 사용자가 실제로 칠 법한 문장 |
| `quick_category_ids` | 권장 | 챗봇 첫 화면에 띄울 대표 카테고리 ID. **최대 6개** |

`sort` · `enabled` 는 적지 않아도 됩니다. 적힌 순서대로, 모두 사용으로 들어갑니다.

## 규칙

### 문서와 짝을 맞춥니다 — 가장 중요합니다

- **문서가 있는 주제만 만듭니다.** 문서 없는 카테고리는 사용자가 골라도 답이 없는 빈 주제가
  됩니다
- **모든 문서가 어느 카테고리엔가 들어가야 합니다.** 빠진 문서가 있으면 그 내용으로 만든
  QA에 붙일 주제가 없습니다
- 문서 한 건이 카테고리 하나가 되는 것이 기본입니다. 문서가 크면(소제목 8개 이상) 둘로
  나눠도 됩니다

### ID

- **한 번 정하면 바꾸지 마세요.** QA와 질문 이력이 이 ID로 이어집니다. 바꾸면 지난 기록이
  주제를 잃습니다
- 영문 소문자 · 숫자 · `_` 를 씁니다. 대분류 이름을 접두어로 두면 알아보기 쉽습니다
  (`apiops_process` · `apiops_register_fields`)
- 파일 전체에서 유일해야 합니다. 겹치면 **통째로 거부**됩니다

### 이름

- 사용자가 고르는 **주제 이름**입니다. 문서 제목을 그대로 쓰지 말고 짧게 줄입니다
  - 문서 `API 등록 화면 입력 항목` → 카테고리 `등록 화면 입력 항목`
- 12자 안팎. 길면 선택기에서 잘립니다

### 추천 질문

- 그 주제를 고른 사용자에게 **예시로 보여 주는 질문**입니다. 2~4개
- 문서 안의 `질문:` 줄에서 **가장 자주 물을 법한 것**을 골라 쓰면 됩니다
- 완성된 문장으로 씁니다 (`"API 등록 절차"` 보다 `"API 등록 절차가 어떻게 되나요?"`)
- 그 문서로 **실제로 답할 수 있는 질문**만 씁니다

### 개수

- 대분류는 **1~5개**. 문서가 5~10건이면 대분류 하나로 충분합니다
- 카테고리는 대분류마다 **3~10개**. 너무 잘게 나누면 사용자가 어디를 눌러야 할지 모릅니다

## 내보내기 전에 확인

- [ ] 아래 문서 목록의 **모든 문서**가 어느 카테고리엔가 들어갔습니까?
- [ ] 문서가 없는 카테고리를 만들지 않았습니까?
- [ ] 모든 ID 가 파일 전체에서 유일합니까? 공백이 없습니까?
- [ ] 카테고리마다 추천 질문이 2개 이상 있습니까?
- [ ] `quick_category_ids` 가 6개 이하이고, 모두 위에 실제로 있는 ID 입니까?
- [ ] 설명이나 코드 울타리 없이 JSON 만 출력합니까?

## 함께 알려 주세요

JSON 다음 줄에 **카테고리별로 어느 문서를 묶었는지** 표로 적어 주세요. 다음 단계인 QA 작성에서
그 표를 보고 `source_doc_ids` 를 정합니다.

```
category_id | 카테고리 이름 | 문서 파일 이름
```

## 문서 목록

`파일 이름 | 제목 | 소제목 수` 형식입니다.

```
(여기에 올린 문서 목록을 붙여넣으세요.
 예: apiops-usage-1-process | API 등록 · 배포 절차 | 9)
```

## 문서 본문

주제를 뽑을 근거입니다. 이 안에 있는 내용으로만 만듭니다.

```
(여기에 문서 본문을 붙여넣으세요. 소제목과 `질문:` 줄만 모아 주셔도 됩니다)
```
