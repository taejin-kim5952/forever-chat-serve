# API Manager 도우미 — 사용자 챗봇 화면 퍼블리싱 요청서

> **프로젝트**: `openapi-chat-serve` (신규)
> **범위**: 사용자용 챗봇 화면 1개. 관리자 화면은 별도 요청서(`02_관리자화면_퍼블요청서.md`)로 나갑니다.
> **참고**: 이전 프로젝트(`openapi-chat`)의 산출물이 있으나 **답변 방식이 근본적으로 달라져**
> 새로 요청드립니다. 재사용할 부분은 6번에 정리했습니다.

---

## 1. 배경 — 이전과 무엇이 달라졌나

KT OpenAPI Portal "API Manager" 사용법을 안내하는 사내 챗봇입니다. 이전 버전은 질문이 올 때마다
AI가 답변을 **생성**했는데, 서버에 GPU가 없어 **답변 1건에 1~3분**이 걸렸습니다.

그래서 방식을 바꿉니다.

```
이전:  질문 → 문서 검색 → AI가 그 자리에서 답변 생성        1~3분
지금:  [사전] 문서 → AI가 답변을 미리 만들고 사람이 검수
       [실시간] 질문 → 의미가 가장 가까운 질문을 찾아 그 답변을 보여줌   1~3초
```

퍼블 관점에서 중요한 결과는 셋입니다.

1. **답변이 빠릅니다(1~3초).** 긴 로딩 연출이 필요 없습니다.
2. **답변을 못 찾는 경우가 생깁니다.** 미리 만들어둔 것 중에 맞는 게 없으면 답을 지어내지 않습니다.
   이때 **"관련 문서만 보여주는" 새로운 응답 상태**가 필요합니다 — 이번 요청의 핵심입니다.
3. **답변은 사람이 검수한 것**입니다. 매번 달라지지 않고 항상 같은 답이 나옵니다.

## 4. 응답 상태 — **5가지 마크업이 필요합니다**

서버 응답의 `result_type` 값에 따라 말풍선이 달라집니다. 여기가 이번 요청의 핵심입니다.

### 4-1. `answer` — 답변을 찾은 경우 (가장 흔함)

```
(봇) **API 그룹(SPC)** 을 먼저 만든 뒤 'API 등록' 화면에서…
     ┌ 출처 ─────────────────────────────┐
     │ 📄 API 등록   📄 API 등록 항목 설명 │
     └────────────────────────────────┘
     ✓ 담당자 검수 완료 · AI가 작성한 답변입니다
```

- 답변 본문은 **마크다운**으로 옵니다. 아래 문법만 렌더링하면 됩니다.
  - 번호 목록 `1. ` / 불릿 `- ` / `**굵게**` / `` `코드` `` / 빈 줄 문단 구분
  - 표·이미지·링크·제목(`#`)은 오지 않습니다
- 출처 배지 클릭 → 문서 상세 모달(4-6)
- 하단 메타: **검수 완료 표시 + AI 고지**를 함께 둡니다. 신뢰를 주되 AI 산출물임을 숨기지 않습니다

### 4-2. `related_docs` — 답변은 없고 관련 문서만 찾은 경우 ★ 신규

미리 만들어둔 답변 중 맞는 것이 없을 때입니다. **빈손으로 돌려보내지 않는 것**이 목적입니다.

```
(봇) ⓘ 이 질문에 딱 맞는 답변이 아직 준비되지 않았습니다.
     대신 관련 있어 보이는 문서를 찾았습니다.

     ┌────────────────────────────────────────┐
     │ 📄 API 등록 - 입력 항목 상세 설명          │
     │    권한그룹 · 이 API를 호출할 수 있는…     │  ← 발췌 2~3줄
     │                              [문서 열기 ›] │
     ├────────────────────────────────────────┤
     │ 📄 API 등록                               │
     │    API 그룹(SPC)이 먼저 만들어져 있어야…   │
     │                              [문서 열기 ›] │
     └────────────────────────────────────────┘

     찾으시는 내용이 없나요?  [담당자에게 문의하기]
```

- 문서 카드 **최대 3개**. 각 카드 = 문서 제목 + 섹션명 + **발췌 2~3줄(말줄임)** + 열기 버튼
- 일반 답변과 **시각적으로 명확히 구분**되어야 합니다(예: 점선 테두리, 옅은 배경, ⓘ 아이콘)
- 실패가 아니라 **"차선책을 제공한다"**는 톤. 부정적으로 보이지 않게 해주세요
- 하단 `담당자에게 문의하기` → 4-3 상태로 전환

### 4-3. `unresolved` — 관련 문서도 없는 경우 / 문의 접수됨

```
(봇) 문의가 담당자에게 접수되었습니다.
     접수번호 TCK-20260814-A3F91
     확인 후 등록된 이메일로 회신드립니다.
```

- 옅은 회색 배경 + 안내 아이콘. 접수번호는 복사 가능하면 좋습니다

### 4-4. `loading` — 로딩

답변이 1~3초라 **가벼운 표시로 충분**합니다. 이전처럼 오래 도는 연출은 필요 없습니다.

- 봇 말풍선 자리에 점 3개 애니메이션 또는 스켈레톤 한 줄
- 입력창·전송 버튼·주제 선택 비활성(`.is_waiting`)

### 4-5. `error` — 서버 오류

- 간단한 에러 말풍선 + `[다시 시도]` 버튼(원래 질문을 다시 보냅니다)

### 4-6. 출처 문서 상세 모달

- `.qr_modal_backdrop` + `.qr_modal` 패턴
- 내용: 문서 제목 / 섹션명 / **본문 발췌(스크롤)** / `[문서로 이동]`(경로가 있을 때만)
- 배경 클릭·`✕`·ESC 로 닫힘

## 5. 주제 선택 (카테고리)

카테고리는 **가변·다수**입니다(현재 48개, 늘어납니다). 2단계 구조입니다.

```
대분류(group)  →  카테고리(category)
API 등록        →  API 등록 절차 / 항목 설명 / 등록 오류 …
```

### 5-1. 주제 선택 트리거 — 상시 노출은 이것뿐

입력창 바로 위 좌측 버튼 1개입니다.

- 미선택: `＃ 주제 선택 ▾` (연한 톤)
- 선택됨: `＃ <카테고리명> ✕` (`--qr-teal-bg` 배경). 안의 `✕`는 **선택만 해제**하고 팝오버를 열지 않습니다
  (버튼 안의 버튼이므로 중첩 `<button>` 을 피해 주세요)
- 이름이 길면 말줄임 + `title` 속성. 트리거 최대 폭은 입력 영역의 50% 이내
- 답변 대기 중에는 `disabled`

### 5-2. 주제 선택 팝오버

트리거 클릭 시 **입력창 위쪽으로** 펼쳐집니다. 대화 영역 레이아웃을 밀지 않아야 합니다
(`position: absolute`).

```
┌ 주제 선택 ─────────────────────── [✕] ┐
│ [🔍 주제 검색.......................] │  ← 자동 포커스
├────────────────────────────────────┤
│ ▾ API 등록                      (12) │  ← 대분류 아코디언(기본 접힘)
│    · API 등록 절차                   │
│    · API 등록 항목 설명               │
│ ▸ API 그룹(스펙)                 (9) │
│ ▸ 템플릿 관리                    (11)│
├────────────────────────────────────┤
│ 결과 없음: "일치하는 주제가 없습니다.   │
│  그냥 질문을 입력해 주세요."           │
└────────────────────────────────────┘
```

- **목록 영역 고정 높이 + 스크롤**(`max-height: 320px` 권장). 카테고리가 80개여도 팝오버 크기 불변
- 검색: 부분일치(대소문자 무시), 일치 구간 `<mark>` 하이라이트, 검색 중에는 대분류 자동 펼침
- 항목 클릭 = 선택 후 **팝오버 자동 닫힘** (질문이 바로 전송되지는 않습니다)
- 닫기: `✕` / 바깥 클릭 / ESC / 입력창 클릭
- 키보드: 검색창에서 `↓` 목록 진입, `↑↓` 이동, `Enter` 선택, `ESC` 닫기
- 접근성: 트리거 `aria-expanded`·`aria-controls`, 팝오버 `role="dialog"`,
  목록 `role="listbox"` / 항목 `role="option"` + `aria-selected`

### 5-3. 추천 질문

카테고리를 고르면 트리거 옆에 `추천 질문 N ▾` 토글이 나타납니다(추천 질문이 없으면 표시 안 함).

- 클릭 시 입력창 위로 펼침. **최대 높이 160px + 스크롤**
- 항목 클릭 = **즉시 전송** 후 목록 접힘
- 문구가 길면 2줄까지 허용, 그 이상 말줄임
- 펼침/접힘 전환 150~200ms

### 5-4. 인트로 — 자주 찾는 주제

- `자주 찾는 주제` 소제목 + **작은 칩 최대 6개** + `전체 주제 보기` 텍스트 버튼
- 칩 클릭 = 카테고리 **선택만**(전송 아님)
- 대화가 시작되면 인트로 전체가 사라집니다(개발에서 처리)

### 5-5. 사용자 말풍선의 주제 배지

주제를 선택하고 보낸 질문은 말풍선 위에 작은 필 배지로 주제를 표시합니다.
미선택이면 배지가 없어야 하므로 **선택적으로 제거 가능한 구조**로 만들어 주세요.

## 6. 이전 산출물에서 재사용 가능한 것

`openapi-chat` 프로젝트의 `퍼블/chat.*` 을 그대로 가져다 쓰실 수 있는 부분입니다.
**새로 만드시는 편이 빠르면 그렇게 하셔도 됩니다.** 참고용입니다.

| 재사용 가능 | 비고 |
| --- | --- |
| 헤더·대화 영역·입력창 레이아웃 | 그대로 |
| 주제 선택 트리거 + 팝오버 + 추천 질문 | **거의 그대로** (5번 요건과 동일) |
| 인트로 자주 찾는 주제 칩 | 그대로 |
| 사용자/봇 말풍선, 출처 배지, 출처 모달 | 그대로 |
| 로딩(타이핑) 인디케이터 | 더 가볍게 조정 |
| fallback 말풍선 | `unresolved`(4-3)로 이름만 변경 |
| **`related_docs` 말풍선** | **신규 — 없던 것** |
| 마크다운 렌더링 CSS(`p`/`ol`/`ul`/`code`/`strong`) | 그대로 |
