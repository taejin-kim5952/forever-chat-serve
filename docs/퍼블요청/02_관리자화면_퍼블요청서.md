# API Manager 도우미 — 관리자 화면 퍼블리싱 요청서

> **프로젝트**: `openapi-chat-serve` (신규)
> **선행 요청서**: `01_사용자_챗봇화면_퍼블요청서.md`
> **범위**: 로그인 화면 1개 + 관리자 화면 1개(탭 8개)

---

## 1. 배경 — 이 화면이 하는 일

사용자 챗봇은 **미리 만들어둔 질문-답변(QA)** 중에서 가장 비슷한 것을 찾아 보여줍니다.
관리자 화면은 그 **QA를 만들고, 검수하고, 부족한 곳을 찾아내는** 도구입니다.

```
사용자가 물음  →  이력에 쌓임  →  비슷한 질문끼리 묶임(분석)
                                        │
                     "이 질문 47건인데 답변이 없음" 발견
                                        ↓
                        QA 생성 → 사람이 검수 → 반영
```

이 순환이 화면 구성의 뼈대입니다.

### 1-1. **모드가 두 가지입니다** ★ 이번 요청의 가장 중요한 전제

같은 화면이지만 **어디에 설치되느냐에 따라 탭 구성이 달라집니다.**

| 모드 | 설치 위치 | 성격 |
| --- | --- | --- |
| **`serve`** | 운영 서버 | AI가 없습니다. **보는 것 + 데이터 정리**만 가능 |
| **`studio`** | 사내 작업용 PC | AI가 있습니다. **생성·평가까지** 전부 가능 |

운영 서버에는 GPU가 없어 AI 모델을 올리지 않습니다. 그래서 생성 기능이 **동작할 수 없고**,
버튼이 보이면 누르고 에러가 나는 상황이 생깁니다. **탭 자체를 감춰야 합니다.**

- 서버가 `<body data-mode="serve">` 또는 `data-mode="studio"` 를 내려줍니다
- 화면은 이 값을 읽어 **해당 탭 버튼과 패널을 DOM에서 숨김**(`hidden`) 처리
- 헤더에 현재 모드를 **배지로 표시** (`운영` / `스튜디오`)

## 2. 톤앤매너 · 기술 제약

`01_사용자_챗봇화면_퍼블요청서.md` 2번과 동일합니다. 추가 사항만 적습니다.

  (본문 13px 수준, 행 높이 낮게)

- 숫자 컬럼은 우측 정렬 + `tabular-nums`

## 3. 로그인 화면 (`login.html`)

관리자 화면은 아이디·비밀번호로 보호됩니다.

```
┌──────────────────────────────┐
│         [KT]                  │
│    API Manager 도우미          │
│      관리자 로그인              │
│                               │
│  아이디  [                 ]  │
│  비밀번호 [                 ]  │
│                               │
│  ⚠ 아이디 또는 비밀번호가       │  ← 실패 시에만
│    올바르지 않습니다.           │
│                               │
│      [    로그인    ]          │
└──────────────────────────────┘
```

- 화면 가운데 정렬된 카드 하나. 단순하게 만들어 주세요
- 필요한 상태: **기본 / 입력 중 / 로그인 시도 중(버튼 비활성 + 스피너) / 실패(오류 문구)**
- Enter 로 제출
- 아이디 입력에 자동 포커스
- 관리자 화면 헤더에는 `[로그아웃]` 버튼

## 5. 공통 컴포넌트

여러 탭에서 반복되므로 **재사용 단위로** 만들어 주세요. 각각 상태별 마크업이 필요합니다.

| 컴포넌트 | 클래스 | 상태 |
| --- | --- | --- |
| 저장 상태 | `.admin_save_state` | 기본(숨김) / `.is_busy`(스피너) / `.is_ok` / `.is_err` |
| 변경됨 표시 | `.admin_dirty` | 부모 카드에 `.is_dirty` 일 때만 노출 |
| 데이터 테이블 | `.admin_table` (`.admin_table_wrap`) | 헤더 sticky, 행 hover, 정렬 헤더(`.is_asc`/`.is_desc`) |
| 빈 상태 | `.admin_empty` | 아이콘 + 제목 + 설명 + (선택)버튼 |
| 인라인 검색 | `.admin_search` | 기본 / `.is_filled`(✕ 노출) / `.is_noresult` |
| 필터 칩 | `.admin_chip` | 기본 / `.is_active` / `disabled` |
| 토글 스위치 | `.admin_switch` | on / off / disabled |
| 필 태그(제거 가능) | `.admin_tag` + `.admin_tag_x` | 기본 / ✕ hover |
| 진행바 | `.admin_progress` | 퍼센트 / `.is_indeterminate` |
| 확인 모달 | `#confirmModal` | 일반 / 위험(삭제) |
| 와이드 모달 | `.qr_modal_wide` (940px+) | 편집용 |
| 로딩 | `.admin_loading` + `.admin_skel` | 스켈레톤 |
| 토스트 | `.admin_toast` (`#adminToasts`) | `.is_ok` / `.is_err`, 3초 후 사라짐 |
| 드롭다운 메뉴 | `.admin_menu` | 열림 `.is_open`, 항목 hover/disabled |
| 페이지네이션 | `.admin_pager` | 페이지 번호 + 페이지당 건수(20/50/100) |
| **카테고리 선택 팝오버** | `.admin_cat_popover` | 챗봇의 주제 팝오버와 동일 구조(검색+아코디언+스크롤) |

> **카테고리 팝오버는 여러 탭에서 씁니다** (①②④⑥ 필터, 상세 편집). 챗봇 화면의
> `#chatCatPopover` 를 관리자 톤으로 옮겨 **하나의 공용 컴포넌트**로 만들어 주세요.
> 여는 위치(위/아래)와 특수 항목(`전체`/`미분류`) 유무만 옵션으로 다르게 씁니다.

### 결과 유형 색 — 화면 전체에서 고정

챗봇 응답 유형이 여러 탭에 반복 등장합니다. **같은 색을 쓰세요.**

| 유형 | 클래스 | 색 | 의미 |
| --- | --- | --- | --- |
| `answer` | `.admin_rt.is_answer` | `--qr-teal` 계열 | 답변을 찾음 |
| `related_docs` | `.admin_rt.is_related` | 노랑/주황 계열(중간 톤) | 관련 문서만 |
| `unresolved` | `.admin_rt.is_unresolved` | `--qr-danger` 계열 | 답 못 함 |

## 6. 탭 ① 질문 이력

**실제 사용자가 무엇을 물었는지 그대로 보는 화면**입니다. 가공 없이 원본을 봅니다.

```
┌ 질문 이력 ────────────────────────────────────────────────┐
│ [기간▾][결과유형▾][# 카테고리▾]  [🔍 질문 검색]            │
│ ☐ 테스트 질문 포함                        [CSV 내려받기]   │
├──────────────────────────────────────────────────────────┤
│ 시각        │ 질문              │결과   │매칭된 QA │유사도│주제│
│ 08-14 14:22 │ 권한그룹 뭐 골라요?│answer │권한그룹은…│0.93 │항목│
│ 08-14 14:19 │ 호출 요금이…      │unresol│—        │ —   │ — │
└──────────────────────────────────────────────────────────┘
```

- 컬럼: 시각 / 질문 / **결과 유형**(색 배지) / 매칭된 QA 항목 / **유사도** / 주제 / 채널
- 행 클릭 → **상세 모달**: 질문 전문 / 실제로 반환된 답변(마크다운 렌더) / 관련 문서 / 유사도 / 접수번호
- 필터: 기간(오늘·7일·30일·전체·직접), 결과 유형, 카테고리(팝오버), 검색
- `테스트 질문 포함` 체크박스 — 기본 꺼짐. 켜면 내부 테스트로 던진 질문까지 표시
- 정렬: 시각(기본 최신), 유사도
- **CSV 내려받기** — 폐쇄망에서 오프라인 분석에 씁니다
- 페이지네이션 필수(수천 건까지 쌓입니다)
- 빈 상태: `아직 질문이 없습니다`

## 7. 탭 ② 질문 분석

이력을 **비슷한 질문끼리 묶어** 무엇을 더 만들어야 하는지 보여줍니다.

```
┌ 분석 실행 ────────────────────────────────────────────────┐
│ 기간 [최근 30일▾]  [▶ 분석 실행]  마지막 2026-08-14 09:12  │
│ (진행바)                                                   │
├──────────────────────────────────────────────────────────┤
│ ┌총 질문┐┌고유 질문┐┌ 적중률 ┐┌QA 없음┐┌평균 응답┐        │  KPI 5개
│ │ 1,842 ││   214  ││ 78.4% ││  37   ││ 2.1초 │          │
├──────────────────────────────────────────────────────────┤
│ [결과 유형 분포]   [일자별 추이]   [QA 없는 상위 주제]      │  차트 3개
├──────────────────────────────────────────────────────────┤
│ 질문 묶음                                                  │
│ [# 카테고리▾][전체][QA 없음][신규][반영됨] [정렬▾] [작업▾] │
│ ☐│대표 질문           │건수│적중률│유형 │주제 │상태│작업  │
└──────────────────────────────────────────────────────────┘
```

- **KPI 5개**: 총 질문 / 고유 질문(묶음 수) / **적중률**(`answer` 비율) / **QA 없음**(답변이 없는 묶음 수) / 평균 응답시간
  - `QA 없음` 타일은 **클릭 가능** — 그 조건으로 목록 필터
  - 증감 표시는 `.is_good` / `.is_bad` / `.is_neutral` 3종 클래스로(어느 것을 붙일지는 개발이 판단)
- **차트 3개** — 외부 라이브러리 없이 **CSS 또는 인라인 SVG**로
  1. 결과 유형 분포 — 가로 스택바 + 범례 (5번의 색 고정)
  2. 일자별 추이 — 선/막대. 전체와 미해결을 구분
  3. QA 없는 상위 주제 — 가로 막대 TOP 5, 클릭 시 필터
- **질문 묶음 테이블**
  - 컬럼: ☐ / 대표 질문(+ 한 줄 요약) / 건수 / 적중률 / 결과 유형 / 주제 / 상태 / 작업
  - 행 펼침(`▸`) → 묶인 **원문 질문 목록**(최대 높이 + 스크롤). 각 원문에 `[이 질문 제외]`
  - 상태 배지 5종: `신규` / `검토됨` / `QA 생성됨` / `반영됨` / `제외`
  - 일괄 작업 메뉴(`.admin_menu`): `주제 지정` / `제외 처리` / **`QA 생성 대상으로 표시`**
- **모드 차이**: `studio` 에서는 작업 메뉴에 **`QA 바로 생성`** 항목이 추가로 보입니다
  (`serve` 에서는 `대상으로 표시`까지만 — 실제 생성은 스튜디오에서)
- 분석 실행은 수 분 걸릴 수 있어 **진행바 + 단계 문구**가 필요합니다

## 8. 탭 ③ 질문 카테고리

챗봇에서 사용자가 고르는 주제를 관리합니다. **2단계(대분류 → 카테고리)** 입니다.

```
┌ 자주 찾는 주제                                    4 / 6 ┐
│ 챗봇 첫 화면에 이 순서로 노출됩니다.                      │
│ ⠿[API 등록 절차 ✕] ⠿[항목 설명 ✕] … [+ 주제 추가]        │
│                                    [저장] (상태)          │
└─────────────────────────────────────────────────────┘
┌──────────────────┬──────────────────────────────────┐
│ [🔍 검색]         │  선택한 카테고리 상세               │
│ [+대분류][+카테고리]│  대분류   [API 등록          ▾]    │
│                   │  이름     [API 등록 절차       ]   │
│ ⠿ ▾ API 등록 (12)│  ID       [c_reg_flow    ](읽기)  │
│    ⠿ API 등록 절차│  노출     [●] 사용                 │
│    ⠿ 항목 설명    │  ────────────────────────       │
│ ⠿ ▸ 그룹(스펙)(9)│  추천 질문 (3)          [+ 추가]  │
│ ⠿ ▸ 템플릿  (11) │  ⠿[API 등록은 어떻게…    ] [✕]   │
│                   │  ⠿[그룹 먼저 만들어야?    ] [✕]   │
│ (좌측만 스크롤)    │      [삭제]      [취소] [저장]    │
└──────────────────┴──────────────────────────────────┘
```

- **자주 찾는 주제** 카드가 최상단(별도 `.admin_card`)
  - 칩 = 드래그 핸들 + 이름 + `✕`. **표시 순서 = 챗봇 노출 순서**
  - `4 / 6` 개수 표시. 6개면 `[+ 주제 추가]` 비활성 + 안내 문구
  - `[+ 주제 추가]` → 카테고리 팝오버(공용 컴포넌트). 이미 담긴 항목은 체크 표시
  - 미사용 카테고리가 담기면 경고(`챗봇에는 표시되지 않습니다`)
- **좌측 트리**: 대분류 아코디언(개수 뱃지), 카테고리 목록, 검색(하이라이트), 드래그 핸들
  - 미사용은 흐리게 + `미사용` 뱃지. 좌측만 스크롤(`max-height` 고정)
- **우측 상세**: 대분류(select) / 이름 / ID(수정 시 읽기전용) / 노출 토글 / 추천 질문 목록(행 추가·삭제·드래그)
  - 아무것도 선택 안 됐을 때의 빈 상태 필요
- **대분류 추가·수정**: 소형 모달(이름 / ID / 노출). 삭제 시 하위 카테고리 개수 경고
- **드래그 정렬**: 대분류·카테고리·추천질문·자주찾는주제 칩
  - 드롭 대상에 `data-drop-position="before"|"after"` 부여(마우스 Y가 대상 높이 절반 기준)
  - `drop` 시 커스텀 이벤트 **1회** 발생. **화면 DOM 이동은 하지 않습니다**(저장 실패 시 되돌리기 쉽게)
    ```js
    $(document).trigger('admin:reorder', [{
      kind: 'group'|'category'|'question'|'quick', fromId, toId, position
    }]);
    ```

## 9. 탭 ④ QA 인덱스 ★ 이 프로젝트의 핵심 화면

사용자에게 실제로 나가는 **답변을 검수·관리**하는 화면입니다. 여기 품질이 서비스 품질입니다.

```
┌ QA 인덱스 ─────────────────────────────────────────────────┐
```

### 9-1. 목록

- 상단 **요약 타일 5개**: 전체 / 검수완료 / 검수대기 / 보류 / 변형 질문 총수
- 컬럼: ☐ / 대표 질문 / **답변 미리보기(1줄 말줄임)** / 주제 / 변형 질문 수 / **적중 횟수** / 상태
- 상태 배지 4종: `검수대기`(강조) / `검수완료`(초록) / `보류`(중립) / `미사용`(흐림 + 행 전체 흐리게)
- 필터: 카테고리 팝오버 / 상태 칩 / 검색(대표 질문 + 답변 본문)
- 정렬: 적중 횟수(기본 내림차순), 변형 수, 최근 수정
- 일괄 작업(`.admin_menu`): `검수 완료 처리` / `보류` / `주제 지정` / `사용 안 함` / `삭제`
- 페이지네이션 필수
- **`serve` 모드에서는** 편집·일괄작업이 없고 **목록 + 상세 보기만** 가능합니다

### 9-2. 상세 — 검수 화면 (와이드 모달)

**검수자가 "사용자에게 이렇게 보인다"를 그대로 확인할 수 있어야 합니다.** 좌우 2단으로 나눠주세요.

```
┌ QA 항목 검수 ────────────────────────────────────── [✕] ┐
│ 상태 [검수대기▾]   주제 [# API 등록 항목 설명 ▾]         │
├────────────────────────┬────────────────────────────┤
│ 답변 (마크다운)          │  챗봇 미리보기                │
│ ┌────────────────────┐│  ┌──────────────────────┐ │
│ │**권한그룹(Auth Group)**││  │(봇) 권한그룹(Auth Group)│ │
│ │은 이 API를 호출할…    ││  │   은 이 API를 호출할…   │ │
│ │                      ││  │   📄 API 등록 항목 설명 │ │
│ │(고정폭, 18행+)        ││  │   ✓ 검수 완료          │ │
│ └────────────────────┘│  └──────────────────────┘ │
│                        │  ← 실제 챗봇과 같은 모양      │
├────────────────────────┴────────────────────────────┤
│ 출처 문서  [api-등록-필드설명 ✕] [+ 문서 추가]           │
├──────────────────────────────────────────────────────┤
│ 변형 질문 (12)                    [+ 추가] [자동 생성*]  │
│ ⠿ [권한그룹은 무엇을 선택해야 하나요?          ] [✕]     │
│ ⠿ [권한그룹 뭐 골라요?                        ] [✕]     │
│ ⠿ [권한그룹 선택 기준                         ] [✕]     │
│    … (스크롤)                                           │
├──────────────────────────────────────────────────────┤
│ [폐기]                    [취소] [저장] [저장 후 승인]   │
└──────────────────────────────────────────────────────┘
```

**꼭 지켜주실 것**

- **좌: 마크다운 편집 / 우: 챗봇 미리보기** — 이 화면의 존재 이유입니다.
  미리보기는 **챗봇 답변 말풍선과 같은 스타일**로 렌더해 주세요(`chat.css` 의 말풍선·출처 배지 재사용).
  편집하면 **입력 즉시(또는 0.3초 디바운스) 미리보기 갱신**
- **변형 질문 목록** — 같은 답변을 가리키는 여러 표현입니다. 이게 적중률을 좌우합니다
  - 행 = 드래그 핸들 + 텍스트 입력 + `✕`
  - 12개가 넘으면 스크롤(최대 높이 240px)
  - 중복 문구는 `.is_dup` 표시 + 저장 시 경고
  - `[자동 생성]` 버튼은 **studio 전용**(`serve` 에서는 숨김)
- **출처 문서**: 제거 가능한 필 태그 + `[+ 문서 추가]`(문서 목록에서 선택, 다중)
- 하단 버튼 3종의 의미를 구분해 주세요
  - `[저장]` — 내용만 저장(상태 유지)
  - `[저장 후 승인]` — 저장 + 상태를 `검수완료`로 (강조 버튼)
  - `[폐기]` — 위험 버튼. 확인 모달 경유
- 필요한 상태: 기본 / 편집됨(`.is_dirty`) / 저장중 / 저장성공 / 저장실패 / 읽기전용(`serve`)
