> **프로젝트**: `openapi-chat-serve`
> **선행 요청서**: `01_사용자_챗봇화면_퍼블요청서.md` · `02_관리자화면_퍼블요청서.md`
> **범위**: 관리자 로그인 **모달(팝업) 1개** + 로그아웃 버튼

## 1. 왜 페이지가 아니라 모달인가

지금은 브라우저가 띄우는 기본 인증 창을 씁니다. 동작은 하지만 제품 화면이 아니고,
오류 문구도 로그아웃 버튼도 만들 수 없습니다. 그래서 로그인 화면을 새로 만듭니다.

**모달로 만드는 이유는 세션 만료 때문입니다.**

```
검수자가 QA 답변을 20분째 편집 중  →  세션 만료  →  저장 누름
   ├─ 로그인 '페이지'로 이동시키면  →  편집하던 내용이 사라진다
   └─ 로그인 '모달'을 위에 띄우면    →  로그인 후 그대로 이어서 저장한다
```

검수는 한 항목에 몇 분씩 걸리는 작업입니다. 로그인 때문에 그 내용을 잃으면 검수자는 화면을
믿지 않게 됩니다. 그래서 **로그인은 화면을 갈아 끼우지 않고 위에 덮는 방식**이어야 합니다.

## 2. 톤앤매너 · 기술 제약

`01` 의 2번과 같습니다. 추가로:

- 클래스 접두어는 `login_`. 모달 골격은 `.qr_modal_backdrop` / `.qr_modal` 패턴을 재사용합니다
- 버튼은 `.qr_pill_accent`(로그인) / `.qr_pill_outline`(로그아웃) 재사용
- **jQuery 기반 정적 HTML/CSS/JS.** React/Vue·외부 UI 라이브러리 사용 불가
- 신규 색상 토큰은 만들지 마세요. 이 화면은 기존 토큰만으로 충분합니다
- 화면 폭이 좁을 때도 카드가 잘리지 않아야 합니다(모바일 우선순위는 낮지만 360px 에서 동작)

## 4. 두 가지 상황에서 뜹니다

| 상황 | 배경 | 안내 문구 | 닫기 |
| --- | --- | --- | --- |
| **처음 접속** | 관리자 화면 골격만(데이터 없음) | 없음 | 불가 |
| **세션 만료** | 작업하던 화면 그대로 | `로그인이 만료되었습니다. 다시 로그인해 주세요.` | 불가 |

- 두 경우 모두 **같은 모달**입니다. 안내 문구 한 줄(`#loginNotice`)만 다릅니다
- 세션 만료로 뜬 경우 배경 내용을 **지우지 마세요.** 로그인 후 하던 일을 이어가야 합니다

### 일반 모달과 다른 점 ★

이 모달만 예외입니다. **닫을 수 없습니다.**

- `ESC` 로 닫히지 않습니다
- 배경 클릭으로 닫히지 않습니다
- `✕` 버튼이 없습니다

인증 전에는 갈 곳이 없기 때문입니다. `02` 의 다른 모달과 동작이 다르니 주의해 주세요.

## 5. 상태 5가지

| 상태 | 클래스 | 모습 |
| --- | --- | --- |
| 기본 | — | 아이디 입력에 자동 포커스. 로그인 버튼 활성 |
| 입력 중 | `.is_filled` | 오류 문구가 떠 있었다면 **입력을 시작할 때 지웁니다** |
| 시도 중 | `.is_busy` | 버튼 안에 스피너 + 문구 `확인 중…`, 버튼·입력 모두 `disabled` |
| 실패 | `.is_error` | 오류 문구 노출, 비밀번호 칸만 비우고 **거기에 포커스**. 아이디는 남깁니다 |
| 연속 실패 | `.is_locked` | 5회 실패 시 버튼 비활성 + `잠시 후 다시 시도해 주세요.` (해제는 개발에서 처리) |

- 오류 문구는 **항상 같은 한 문장**입니다 — `아이디 또는 비밀번호가 올바르지 않습니다.`
  "없는 아이디입니다" 처럼 나누면 어떤 아이디가 존재하는지 알려주는 셈이 됩니다
- 실패해도 아이디는 지우지 않습니다. 오타는 대부분 비밀번호 쪽입니다

---

## 6. 동작 규칙

- `Enter` 로 제출. 아이디 칸에서 `Enter` 는 비밀번호 칸으로 이동해도 됩니다
- 비밀번호 표시 토글(`👁`) — 눌러야만 보입니다. 기본은 가림
- **Caps Lock 안내**: 비밀번호 칸에 포커스가 있고 Caps Lock 이 켜져 있을 때만 노출
- 빈 값으로 제출하면 서버에 보내지 말고 해당 칸에 포커스만 줍니다
- 자동완성 속성을 넣어 주세요 — 아이디 `autocomplete="username"`,
  비밀번호 `autocomplete="current-password"`. 브라우저 비밀번호 관리자를 쓰는 사람이 많습니다
- 접근성: 모달 `role="dialog" aria-modal="true"`, 포커스는 모달 안에서만 순환,
  오류 문구는 `role="alert"`, 입력 실패 시 `aria-invalid="true"`

## 7. 로그아웃

관리자 화면 헤더 오른쪽에 `[로그아웃]` 버튼(`#logoutBtn`, `.qr_pill_outline`).

- 누르면 확인 모달 없이 바로 처리합니다
- 저장하지 않은 편집 내용이 있으면(`.is_dirty`) **그때만** 확인 모달을 띄웁니다
  (`02` 5번의 `#confirmModal` 재사용, 문구: `저장하지 않은 변경이 있습니다. 로그아웃할까요?`)
- 처리 후 화면은 그대로 두고 로그인 모달을 다시 띄웁니다

## 8. 서버와 주고받는 것

**아직 개발되지 않은 API입니다.** 퍼블 단계에서는 `login.js` 안에서 더미로 흉내 내 주세요
(아이디 `admin` / 비밀번호 `1234` 면 성공, 아니면 실패 — 실제 값은 개발에서 바꿉니다).

| 동작 | 요청 | 응답 |
| --- | --- | --- |
| 로그인 | `POST /api/admin/login` · `{"username": "...", "password": "..."}` | `200` 성공 / `401` 실패 |
| 로그아웃 | `POST /api/admin/logout` | `200` |
| 세션 만료 | 아무 관리자 API 호출 | `401` → 로그인 모달을 다시 띄웁니다 |

- 성공하면 서버가 세션 쿠키를 내려줍니다. **화면이 아이디·비밀번호를 저장하지 마세요**
  (`localStorage`·`sessionStorage`·전역 변수 모두 금지)
- 성공·실패 판단은 **서버가 합니다.** 화면은 응답 코드만 보고 상태를 바꿉니다

## 10. 산출물

1. `login.html` — 모달 마크업 한 덩어리. `admin.html` 안에 **그대로 붙여 넣을 수 있는 형태**로
   만들어 주세요(별도 페이지가 아니라 조각입니다). 확인용 껍데기 페이지는 함께 주셔도 됩니다
2. `login.css` / `login.js`
3. `login-mapping.md` — 요소 ↔ 상태 매핑, 상태 전환 규칙, 신규 토큰이 있다면 그 사유
4. **확인용 상태 목업 바**(`[data-dev-only]`) — 5번의 상태 5가지와 4번의 두 상황을
   버튼으로 바로 전환해 볼 수 있게 해주세요

## 11. 이번 범위가 아닌 것

- 비밀번호 찾기·변경, 계정 관리, 권한 구분 — **아이디 하나로만 로그인합니다**
- 2단계 인증, SSO
- `로그인 상태 유지` 체크박스 — 세션 유효 기간은 서버가 정합니다
- 사용자 챗봇 화면 로그인 — 챗봇은 로그인 없이 씁니다
