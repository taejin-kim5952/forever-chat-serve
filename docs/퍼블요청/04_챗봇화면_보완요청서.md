# API Manager 도우미 — 챗봇 화면 보완 요청서

> **프로젝트**: `openapi-chat-serve`
> **대상 파일**: `chat.html` · `chat.css` · `chat.js` · `chat-mapping.md`
> **선행 요청서**: `01_사용자_챗봇화면_퍼블요청서.md`
> **범위**: 버튼 3개 추가. 기존 화면 구조·색·컴포넌트는 그대로 둡니다.

관리자 화면 산출물 잘 받았습니다. 로그인 모달(`#authModal`)은 요청서 03의 까다로운 항목까지
그대로 반영해 주셔서 서버 연결만 하고 바로 붙였습니다.

이번은 **챗봇 화면을 실제로 붙여 놓고 써 보니 아쉬웠던 세 가지**입니다. 분량이 적습니다.

> `[다시 시도]`(`.chat_retry`)와 접수번호 복사(`.chat_ticket_copy`)는 **이미 잘 들어와 있어
> 요청 목록에서 뺐습니다.** 오류 말풍선과 접수번호 쪽은 그대로 두시면 됩니다.

## 2. A. 대화 초기화 (`#chatReset`)

### 지금 상태

**동작은 이미 만들어 주셨습니다.** `chat.js` 의 확인용 목업 바(`[data-dev-only]`)에 있습니다.

```js
if(k === 'reset'){ setWaiting(false); $inner.find('.chat_msg').remove();
                   $intro.show(); clearCategory(); closePopover(); closeQuestions(); }
```

개발 이식 때 목업 바 블록을 통째로 걷어내면서 함께 사라졌습니다.
**이 로직을 제품 버튼으로 승격해 주세요.** 새로 만들 것은 버튼 자리와 스타일뿐입니다.

### 요청

```
┌──────────────────────────────────────────────┐
│ [KT] API Manager 도우미        [↻ 새 대화]   │  ← 헤더 우측
│      API 등록 · 그룹 · 템플릿                 │
└──────────────────────────────────────────────┘
```

- 위치는 **헤더 우측**. 라벨은 `새 대화` 를 권합니다(`초기화` 는 데이터가 지워지는 느낌이 큽니다)
- 대화가 **하나도 없을 때는 `disabled`** (인트로 상태에서는 누를 것이 없습니다)
- 누르면: 말풍선 전부 제거 → 인트로(`#chatIntro`) 복귀 → 선택한 주제 해제 → 팝오버·추천 질문 닫기
- 답변 대기 중(`.is_waiting`)에는 `disabled`

### ★ 확인 모달을 붙이지 말아주세요

이 챗봇은 **질문마다 독립적으로 검색**합니다. 서버에 대화 상태가 없어서, 초기화는
**화면에 쌓인 말풍선을 지우는 것이 전부**입니다. 되돌릴 데이터가 없으므로
`정말 초기화할까요?` 같은 확인 단계는 과합니다.

**딱 한 경우만 예외**입니다. 대화 안에 **접수번호(`.chat_ticket`)가 있으면** 그 번호는 사용자가
담당자에게 불러 줘야 하는 값이라 화면에서 사라지면 다시 볼 수 없습니다. 이때만
확인 모달(`.qr_modal` 재사용)을 띄워 주세요.

- 문구: `접수번호가 포함된 대화입니다. 지우면 번호를 다시 볼 수 없습니다.`
- 버튼: `[취소]` / `[새 대화 시작]`

## 3. B. 답변 복사 (`.chat_msg_copy`)

사용자가 답변을 사내 메신저나 결재 문서에 그대로 옮겨 붙입니다. 지금은 드래그로 긁어야 하는데,
마크다운 렌더 결과라 목록·굵게가 섞여 선택이 잘 안 됩니다.

```
┌ 봇 말풍선 ─────────────────────────────┐
│ **API 그룹(SPC)** 을 먼저 만든 뒤…      │
│ 1. API Manager > API 그룹 …             │
│                                         │
│ 📄 api-등록  📄 spc-등록                │  출처 배지(기존)
│ ✓ 담당자 검수 완료 · AI가 작성한 답변  [복사] │  ← 메타 줄 우측에 추가
└─────────────────────────────────────────┘
```

- **`.chat_ticket_copy` 의 동작을 그대로 재사용**해 주세요. 이미 만들어 두신 패턴이 좋습니다
  (클릭 → `복사됨` 1.5초 → 원래 라벨). 새 상호작용을 만들 필요가 없습니다
- 위치는 **하단 메타 줄 우측**. 말풍선 안에 떠 있는 형태는 본문을 가립니다
- **답변 말풍선(`.chat_msg_bot`)에만** 붙습니다. 로딩·오류·관련 문서 카드·인트로에는 없습니다
- 복사되는 내용은 **화면에 보이는 글자 그대로**(마크다운 기호 없이). `**굵게**` 가 그대로
  붙여지면 메신저에서 지저분해집니다. 출처·검수 문구는 포함하지 않습니다
- 접근성: `aria-label="답변 복사"`, 복사 후 `aria-live` 로 `복사됨` 안내
- 실패해도 화면이 멈추지 않게 해주세요(사내 브라우저가 구버전인 경우가 있습니다)

## 4. C. 맨 아래로 (`#chatToBottom`)

답변 하나가 길어서, 이전 대화를 위로 올려 보다가 **마지막 답변으로 돌아오기가 번거롭습니다.**
지금은 새 답변이 올 때 자동 스크롤(`scrollBottom()`)만 있습니다.

```
                              ┌─────────────┐
                              │             │
                              │   대화 …     │
                              │        ( ↓ ) │  ← 입력창 바로 위, 우측
                              ├─────────────┤
                              │ [입력창]     │
                              └─────────────┘
```

- **스크롤이 하단에서 일정 거리(160px 권장) 이상 떨어졌을 때만** 나타납니다. 항상 떠 있으면
  대화를 가립니다. 나타나고 사라질 때 페이드 150~200ms
- 위치는 **입력창 바로 위 우측**. 입력창·주제 트리거를 가리지 않아야 합니다
- 누르면 기존 `scrollBottom()` 과 같은 방식으로 맨 아래로 이동
- **위로 올려본 상태에서 새 답변이 도착하면** 버튼에 점 표시(`.is_new`)를 붙여 주세요.
  새 답변이 온 줄 모르고 계속 위를 보는 경우가 있습니다. 맨 아래로 가면 해제됩니다
- 자동 스크롤 규칙은 **바꾸지 말아주세요**: 사용자가 하단에 있을 때만 자동으로 따라갑니다
  (위를 읽는 중에 끌려 내려가면 읽던 자리를 잃습니다)
- 접근성: `aria-label="맨 아래로"`, 키보드 포커스 가능

## 5. ★ 다음 납품부터 지켜주실 것 (자원 경로)

지난 산출물을 이식하면서 **화면이 아예 뜨지 않아** 개발 쪽에서 고친 부분입니다.
다음부터 이렇게 주시면 이식이 파일 복사로 끝납니다.

| 항목 | 산출물 | 요청 |
| --- | --- | --- |
| jQuery | `https://code.jquery.com/...` | `/static/vendor/jquery-3.7.1.min.js` |
| 폰트 | `https://cdn.jsdelivr.net/.../pretendard.min.css` | 넣지 않기 (CSS의 `font-family` 폴백으로 충분) |
| CSS·JS | `href="admin.css"` (상대경로) | `/static/admin.css` (절대경로) |

두 가지 이유입니다.

1. **운영이 폐쇄망입니다.** CDN에 닿지 않아 jQuery를 못 받으면 화면이 통째로 죽습니다
2. 화면이 `/admin` 처럼 **하위 경로로 서비스**되므로 상대경로는 `/admin.css` 로 잘못 풀립니다

`chat.html` 은 처음부터 이 규칙대로 주셔서 문제가 없었습니다. 같은 방식으로 맞춰 주세요.
