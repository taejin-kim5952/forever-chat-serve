> **선행 요청서**: `02_관리자화면_퍼블요청서.md` · `03_로그인_퍼블요청서.md`
> **범위**: 관리자 화면 1개 — 네비게이션 개편 + 신규 화면 2개(진행 현황 · 검수) + 설정 하위 탭

## 1. 배경 — 왜 개편하나

관리자 화면을 실제로 붙여 보니 **"지금 내가 뭘 해야 하는지"를 화면에서 읽을 수 없습니다.**
원인이 셋입니다.

**① 탭 순서가 일하는 순서와 무관합니다.**

```
지금  질문 이력 · 질문 분석 · 질문 카테고리 · QA 인덱스 · RAG 문서 · QA 생성* · 품질 평가* · 설정
실제  문서 넣기 → QA 생성 → 검수 → 서비스 반영 → 질문 쌓임 → 분석 → 부족한 것 찾기 → 다시 생성
```

**② 매일 하는 일인 '검수'가 메뉴에 없습니다.** 지금은 `/admin/review` 라는 **별도 임시
화면**으로 밖에 나가 있습니다. 이번에 관리자 화면 안으로 들입니다.

**③ 앞으로 10개가 됩니다.** 진행 현황 + 검수가 들어오면 가로 탭이 밀립니다.

그래서 이번에 **좌측 사이드바 + 그룹 라벨**로 바꾸고, 첫 화면에 **진행 현황판**을 놓습니다.

### 1-1. 이 서비스가 하는 일 (요약)

사용자 챗봇은 **미리 만들어 사람이 검수해 둔 답변**만 보여줍니다. 실시간으로 AI가 답을
짓지 않습니다. 그래서 관리자 화면의 목적은 하나입니다 — **검수된 답변을 쌓는 것.**

```
문서 ─▶ QA 초안 생성 ─▶ [사람이 검수] ─▶ 승인 ─▶ 검색에 올라감 ─▶ 사용자에게 나감
                                    │
                            승인 안 하면 아무 일도 일어나지 않음
```

진행 현황판은 **이 흐름의 어디가 막혀 있는지**를 한 화면에 보여주는 것이 전부입니다.

### 1-2. 모드가 두 가지입니다 ★ (요청서 02 와 동일 · 유지)

| 모드 | 설치 위치 | 성격 |
| --- | --- | --- |
| **`serve`** | 운영 서버 | AI가 없습니다. **보는 것 + 검수 + 데이터 정리** |
| **`studio`** | 사내 작업용 PC | AI가 있습니다. **생성·평가까지** 전부 |

`<body data-mode="serve">` 를 서버가 내려줍니다. 값에 따라 **메뉴 항목 자체를 숨깁니다.**
이번 개편에서 규칙이 하나 늘어납니다 → **4-3** 참고.

### 2-1. ★ 조직 이름을 마크업에 직접 쓰지 마세요 (신규 규칙)

이 제품은 **어느 조직에나 설치할 수 있는 형태**를 목표로 합니다. `KT`·`API Manager 도우미`
같은 문자열을 마크업에 박으면 설치할 때마다 소스를 고쳐야 합니다.

그런 자리에는 **`data-brand` 속성**을 붙여 주세요. 서버가 텍스트만 갈아 끼웁니다.

지금 구성에서는 실제로 비는 그룹이 없지만, 항목이 늘어나면 생깁니다. 규칙으로 넣어 주세요.

## 5. 진행 현황 `#panel_flow` ★ 이번 요청의 핵심

로그인 직후 처음 보이는 화면입니다. **여기서는 아무것도 편집하지 않습니다.** 지금 상태를
보여주고 **해당 화면으로 보내는 것**이 전부입니다.

```
┌─ 파이프라인 ────────────────────────────────────────────────────────────────┐
│  ① 문서       ② 초안        ③ 검수 대기 ★  ④ 서비스 중   ⑤ 품질      ⑥ 임계값 │
│  24건         24건          12건           286건         오매칭 4.2%  0.90    │
│  미색인 2     08-15 생성    4점미만 3 포함  최근7일 +18   08-14 측정   문서 0.55│
│  [문서 관리]  [생성 시작]   [검수하기]      [QA 인덱스]   [다시 측정]  [설정]   │
└─────────────────────────────────────────────────────────────────────────────┘

┌─ 지금 할 일 ────────────────────────────────────────────────────────────────┐
│  검수 대기 12건. 승인해야 사용자에게 나갑니다.              [검수 화면 열기]   │
└─────────────────────────────────────────────────────────────────────────────┘

┌─ 흐름 요약 ─────────────────────────────────────────────────────────────────┐
│  문서 24 ─38건 생성─▶ 근거없음 9 · 비한국어 2 · 4점미만 3 제외 ─▶ 대기 24 ─▶ 반영 286 │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 5-1. 6칸 상태판 `.admin_flow_steps` / `.admin_flow_step`

칸마다 필요한 것: **번호 · 제목 · 큰 숫자 · 보조 한 줄 · 이동 버튼 · 상태**

| # | 제목 | 큰 숫자 | 보조 줄 | 이동 |
| --- | --- | --- | --- | --- |
| ① | 문서 | 문서 수 | `미색인 N` (0이면 `모두 색인됨`) | RAG 문서 |
| ② | 초안 | 초안 수 | 마지막 생성 일시 (없으면 `생성 이력 없음`) | QA 생성 ✳ |
| ③ | 검수 대기 | pending 수 | `보류 N` 또는 `4점 미만 N 포함` | 검수 |
| ④ | 서비스 중 | approved 수 | `최근 7일 +N` | QA 인덱스 |
| ⑤ | 품질 | 오매칭률 `%` | 마지막 측정일 (없으면 `측정 이력 없음`) | 품질 평가 ✳ |
| ⑥ | 임계값 | `0.90` | `문서 0.55` | 설정 |

**칸 상태 4가지** — 클래스로 구분해 주세요.

| 상태 | 클래스 | 언제 | 모습 |
| --- | --- | --- | --- |
| 정상 | `.is_ok` | 할 일 없음 | 기본 |
| 주의 | `.is_warn` | 값이 나쁨 (오매칭률 높음, 미색인 있음) | 경고색 테두리 + `⚠` |
| 할 일 | `.is_todo` | **여기가 병목** | 강조 배경 + `★` |
| 잠김 | `.is_off` | studio 전용인데 serve 모드 | 흐리게 + 버튼 `disabled` + 툴팁 `작업용 PC에서 가능합니다` |

> **`.is_todo` 는 한 번에 한 칸에만 붙습니다.** 가장 앞선 병목 하나만 강조합니다.
> 여섯 칸이 다 빨가면 아무것도 안 읽힙니다.

`serve` 모드에서는 ②와 ⑤가 `.is_off` 입니다. **칸을 숨기지는 마세요** — 파이프라인 전체
모양을 보여주는 것이 이 화면의 목적이라, 빠지면 흐름이 끊겨 보입니다.

### 5-2. 지금 할 일 `#flowTodo`

한 문장 + 버튼 하나. 가장 앞선 병목을 그대로 문장으로 씁니다.

| 상황 | 문구 | 버튼 |
| --- | --- | --- |
| 검수 대기 있음 | `검수 대기 N건. 승인해야 사용자에게 나갑니다.` | 검수 화면 열기 |
| 대기 없고 초안 있음 | `초안 N건이 반영을 기다립니다.` | QA 생성 |
| 초안도 없음(studio) | `문서에서 QA를 생성할 수 있습니다.` | QA 생성 |
| 오매칭률 높음 | `검색 오매칭이 N%입니다. 변형 질문이나 임계값을 손봐야 합니다.` | 품질 평가 |
| 문서 없음 | `문서가 없습니다. 먼저 문서를 넣어 주세요.` | RAG 문서 |
| 할 일 없음 | `막힌 곳이 없습니다.` | (버튼 없음) |

마지막 줄(`.is_clear`)은 색을 빼고 담담하게 만들어 주세요.

### 5-3. 흐름 요약 `#flowSummary`

**단계 사이에서 걸러져 나간 것**을 한 줄로 보여줍니다. 지금은 로그에만 남아 아무도 못 보는
값인데, 이게 보여야 "문서를 더 써야 한다"는 판단이 나옵니다.

```
문서 24 ──38건 생성──▶ 근거없음 9 · 비한국어 2 · 4점미만 3 제외 ──▶ 대기 24 ──▶ 반영 286
```

- 가로 한 줄. 좁아지면 두 줄로 접히되 **가로 스크롤은 만들지 마세요**
- 제외 항목은 값이 0이면 그 조각을 뺍니다
- 생성 이력이 없으면 이 블록 전체를 숨깁니다

### 5-4. 데이터가 아직 없을 때

설치 직후에는 전부 0입니다. **빈 상태(`.admin_empty`)로 갈아치우지 말고** 숫자 0을 그대로
보여주세요. 파이프라인 모양이 첫 화면에서 보이는 것이 학습에 도움이 됩니다. 대신 `지금 할 일`
이 `문서가 없습니다...` 를 안내합니다.

## 6. 검수 `#panel_review` ★ 신규

지금 `/admin/review` 에 있는 임시 화면을 관리자 화면 안으로 들입니다. 임시 화면은 폐기됩니다.

### 6-1. QA 인덱스 탭과 무엇이 다른가 ★ 먼저 읽어주세요

**두 화면의 기능이 겹칩니다. 역할을 이렇게 나눠 주세요.**

| | 검수 (`review`) | QA 인덱스 (`qa`) |
| --- | --- | --- |
| 무엇을 보나 | **검수 대기(pending)만** | 전체 (4가지 상태) |
| 주된 화면 | **한 건 상세** | 목록 |
| 하는 일 | 읽고 고치고 **승인 / 보류** | 찾고 고치고 상태 바꾸고 **일괄 처리** |
| 핵심 조작 | **`승인하고 다음 건`** | 검색 · 필터 · 정렬 · 체크박스 |
| 비유 | 결재함 | 자료실 |

**편집 폼은 같은 컴포넌트를 두 곳에서 쓰세요.** 검수 화면에는 여기에 `다음 건` 흐름이
붙는 것뿐입니다. 두 벌로 만들면 한쪽만 고쳐지는 사고가 납니다.

### 6-2. 화면 구성

```
┌───────────────────────────────────────────────────────────────────────┐
│  검수 대기 12건        [주제 전체 ▾] [점수순 ▾]        3 / 12          │  큐 헤더
├───────────────────────────────────────────────────────────────────────┤
│  대표 질문  [                                                    ]     │
│                                                                        │
│  답변 (마크다운)                  │  사용자에게 보이는 모습              │
│  ┌──────────────────────────┐   │  ┌──────────────────────────┐      │
│  │                          │   │  │  (챗봇 말풍선과 같은 렌더)  │      │
│  └──────────────────────────┘   │  └──────────────────────────┘      │
│                                                                        │
│  변형 질문  적중률은 사실상 이 목록이 정합니다      주제  [        ▾]   │
│  [입력하고 Enter          ] [추가]                 출처 문서 · 근거 발췌 │
│  ⊗ 등록하는 방법 알려줘                            채점 4점 · exaone…   │
│  ⊗ API 등록 절차                                  검수 메모 [       ]  │
├───────────────────────────────────────────────────────────────────────┤
│  [◀ 이전]                    [보류] [미사용]   [승인하고 다음 건 ▶]     │  하단 고정
└───────────────────────────────────────────────────────────────────────┘
```

### 6-3. 큐 헤더

- 왼쪽: `검수 대기 N건`
- 가운데: **주제 필터** (공용 카테고리 팝오버 재사용) · **정렬**
  (`점수 낮은순` / `점수 높은순` / `최근 생성순` / `적중 많은순`)
- 오른쪽: `3 / 12` 진행 표시. 얇은 진행바를 같이 두면 좋습니다

### 6-4. 본문 — 요소

| 요소 | 비고 |
| --- | --- |
| 대표 질문 | 한 줄 입력 |
| 답변 + 미리보기 | 좌우 2단. **미리보기는 챗봇 말풍선과 렌더 규칙이 같아야 합니다** ★ |
| 변형 질문 | 입력 + Enter 추가, 목록에서 ⊗ 로 제거. 옆에 `적중률은 사실상 이 목록이 정합니다` |
| 주제 | 카테고리 팝오버(공용) |
| 출처 문서 | 배지. 클릭하면 **근거 발췌를 접었다 펼침** — 검수자가 원문과 대조하는 자리 |
| 채점 | `4점` + 판정 모델명 + 판정 이유 한 줄. **채점이 없으면 `채점 없음`** (0점이라고 쓰지 마세요) |
| 검수 메모 | 여러 줄. placeholder `보류한 이유를 남기지 않으면 다음 사람이 같은 판단을 반복합니다` |

> **미리보기가 챗봇과 다르면 검수가 의미를 잃습니다.** 검수자는 "사용자에게 이렇게 나간다"를
> 보고 승인합니다. 굵게·목록·코드·문단만 렌더하는 규칙을 챗봇 화면과 똑같이 맞춰 주세요.

### 6-5. 하단 액션 (스크롤해도 항상 보이게 고정)

| 버튼 | 동작 | 스타일 |
| --- | --- | --- |
| `◀ 이전` | 앞 건으로 | 보조 |
| `보류` | hold 로 바꾸고 다음 건 | 외곽선 |
| `미사용` | disabled 로 바꾸고 다음 건 | 외곽선 |
| **`승인하고 다음 건 ▶`** | approved 로 바꾸고 다음 건 | **주 버튼(강조)** |

- 저장 중에는 버튼 전체 `disabled` + 주 버튼에 스피너
- **확인 모달을 붙이지 마세요.** 되돌릴 수 있는 조작입니다(QA 인덱스에서 상태를 다시 바꿀
  수 있습니다). 매 건 확인창이 뜨면 검수가 불가능해집니다
- 저장 실패는 토스트 `.is_err` + 그 자리에 머무름. **다음 건으로 넘어가면 안 됩니다**

## 부록. 진행 현황 응답 (서버 준비 완료)

`GET /api/admin/pipeline/status` — **이미 만들어져 있습니다.** 아래가 실제 응답입니다.
더미 데이터를 이 모양으로 만들어 주시면 배선이 그대로 붙습니다.

```json
{
  "mode": "studio",
  "checked_at": "2026-08-16T08:49:43",
  "steps": [
    { "key": "documents", "value": 1,    "note": "미색인 1건",       "state": "warn" },
    { "key": "drafts",    "value": 0,    "note": "2026-08-15 09:12", "state": "ok"   },
    { "key": "pending",   "value": 2,    "note": "4점 미만 3건 제외됨","state": "todo" },
    { "key": "approved",  "value": 1,    "note": "최근 7일 +1",      "state": "ok"   },
    { "key": "quality",   "value": 4.2,  "note": "2026-08-14 18:40", "state": "ok"   },
    { "key": "threshold", "value": 0.9,  "note": "문서 0.55",        "state": "ok"   }
  ],
  "todo": {
    "kind": "review",
    "message": "검수 대기 2건. 승인해야 사용자에게 나갑니다.",
    "tab": "review"
  },
  "summary": {
    "has_run": true, "generated_at": "2026-08-15T09:12:00", "documents": 1,
    "questions_made": 38, "dropped_language": 2, "dropped_ungrounded": 9,
    "low_score": 3, "pending": 2, "approved": 1
  }
}
```

### 화면이 판단하지 않습니다 ★

- `steps` 는 **순서 그대로** 왼쪽부터 그립니다. `key` 로 제목을 찾으세요
- `state` 는 `ok` `warn` `todo` `off` 중 하나입니다. **숫자를 보고 다시 판단하지 마세요** —
  기준이 화면과 서버 두 곳에 생기면 관리자 설정과 실제 동작이 조용히 어긋납니다
- `todo.kind` 는 `docs` `review` `apply` `generate` `quality` `clear` 중 하나이고,
  `todo.message` 를 **그대로** 출력합니다. `todo.tab` 이 `null` 이면 버튼을 감춥니다
  (= `clear`, 5-2의 마지막 줄)
- `warn` 과 `todo` 는 **같이 나올 수 있습니다**(위 예시: 문서 `warn` + 검수 `todo`).
  `todo` 는 항상 한 칸뿐이고, `warn` 은 여러 칸에 붙을 수 있습니다
- `summary.has_run` 이 `false` 면 흐름 요약 블록 전체를 숨깁니다
- `value` 는 `documents/drafts/pending/approved` 가 정수, `quality` 는 퍼센트(실수),
  `threshold` 는 0~1 실수입니다
