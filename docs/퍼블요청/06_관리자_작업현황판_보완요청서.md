## 1. 배경

### 1-1. 왜 작업 현황판이 필요한가 ★ 이번 요청의 핵심

QA를 하나 만들려면 **문서 등록 → 청킹 → 임베딩(색인) → QA 생성 → 검수 → 서비스 반영**을
차례로 지나야 합니다. 그런데 지금은 각 단계가 **자기 탭 안에서만** 돌고 서로를 모릅니다.

```
지금
  ⑤ RAG 문서   폴더 등록 모달 안에 진행바   ← 모달을 닫으면 사라집니다
  (색인)        표시 없음                  ← 돌고 있는지 알 방법이 없습니다
  ⑥ QA 생성    탭 안에 진행바              ← 다른 탭으로 가면 안 보입니다
  ⑦ 품질 평가  탭 안에 진행바              ← 〃
```

문제가 셋입니다.

1. **탭을 떠나면 진행이 사라집니다.** QA 생성은 수십 분짜리 배치인데, 그동안 관리자는
   다른 탭을 못 보거나 진행 상황을 포기해야 합니다. 새로고침하면 더 막막해집니다.
2. **단계 사이가 끊깁니다.** 색인이 끝나도 아무 일도 안 일어납니다. 관리자가 스스로
   "이제 생성 탭으로 가야지"를 알아야 합니다.
3. **색인은 아예 안 보입니다.** 문서를 넣었는데 검색이 안 되면 원인이 색인인지 문서인지
   구분할 수 없습니다.

**05번에서 만든 6칸 상태판과는 다른 축입니다.** 둘 다 필요합니다.

| | 6칸 상태판 (05번) | 작업 현황판 (이번) |
| --- | --- | --- |
| 무엇 | 각 단계에 **몇 건** 있나 | 지금 **무엇이 돌고** 있나 |
| 성격 | 정적 · 스냅샷 | 동적 · 진행률 |
| 답하는 질문 | "어디가 막혔나" | "얼마나 남았나 · 다음은 뭔가" |

같은 화면(`#panel_flow`)에 위아래로 놓습니다. 별도 탭을 만들지 마세요 — 둘을 같이 봐야
"막힌 곳"과 "지금 하는 일"이 이어집니다.

## 3. A. 역할별 모델 — ⑥ QA 생성

지난 산출물에는 `생성 모델` **하나**만 있었습니다. 실제로는 셋을 따로 고릅니다.

```
[질문·변형 모델 ▾]   [답변 모델 ▾]   [채점 모델 ▾]
                                      ⚠ 답변 모델과 같으면 점수가 후해집니다
```

| 필드 | id | 비고 |
| --- | --- | --- |
| 질문·변형 모델 | `genQuestionModel` | 서버가 설치된 모델 목록과 기본값을 내려줍니다 |
| 답변 모델 | `genAnswerModel` | 〃 |
| 채점 모델 | `genJudgeModel` | **첫 항목이 `채점 안 함`(빈 값)** 입니다 |
| 경고 문구 | `genJudgeHint` | 채점 모델 아래 한 줄. 아래 규칙 |

**왜 셋인가** — 역할마다 잘하는 모델이 다릅니다. 실측에서 큰 모델은 답변이 정확했지만
변형 질문은 표현 폭이 좁았고, 작은 모델은 반대였습니다. 그리고 **답변을 쓴 모델이 자기
답을 채점하면 점수가 후해집니다.**

**`genJudgeHint` 규칙** — 세 상태입니다.

| 상황 | 문구 | 모양 |
| --- | --- | --- |
| 채점 모델 = 답변 모델 | `답변 모델과 같습니다. 자기 답에 후한 점수를 줍니다.` | `.is_warn` (경고색) |
| 채점 안 함 선택 | `채점하지 않습니다. 초안이 점수 없이 검수로 넘어갑니다.` | 보통 |
| 그 외 | (비움) | — |

옵션은 **비워서 주세요.** 서버가 채웁니다(`<select id="genQuestionModel"></select>`).
지난 산출물처럼 `<option>gemma4:latest</option>` 를 하드코딩하면 설치된 모델과 어긋납니다.

## 4. B. 폴더 등록 — ⑤ RAG 문서

문서를 한 건씩 만드는 것 말고 **폴더째 올리는** 경로입니다.

- ⑤ 탭 우측 상단에 `폴더 등록` 버튼(`#docUploadBtn`, `data-studio-only`) +
  `<input type="file" id="docUploadInput" webkitdirectory directory multiple hidden>`
- 누르면 `#docUploadModal`(와이드) 이 열립니다

```
┌ 폴더 등록 ─────────────────────────────────────────────┐
│  md 파일 42건을 찾았습니다. (건너뜀 7건 — md/txt 아님)     │  #docUploadSummary
│  ☐ 이미 있는 문서도 덮어씁니다                            │  #docUploadOverwrite
│  ▓▓▓▓▓▓▓░░░░░  42건 중 24건                             │  #docUploadProgress
│ ┌────────────────────────────────────────────────────┐ │
│ │ 경로            문서ID      결과    청크   비고      │ │  #docUploadBody
│ │ api/등록.md     api-등록    등록      12          │ │
│ │ api/삭제.md     api-삭제    갱신       8          │ │
│ │ readme.md       —          건너뜀      —   중복    │ │
│ └────────────────────────────────────────────────────┘ │
│                              [닫기]  [등록 시작]         │  #docUploadStartBtn
└────────────────────────────────────────────────────────┘
```

**결과 배지 4종** — `등록`(`.is_done`) · `갱신`(`.is_applied`) · `건너뜀`(`.is_hold`) ·
`실패`(`.is_excluded`). 기존 상태 배지 색을 그대로 씁니다.

> **한 번에 다 보내지 않습니다.** 문서 한 건마다 청킹·임베딩이 돌아 몇 초씩 걸립니다.
> 40건을 한 요청에 보내면 진행 상황을 보여줄 수 없고, 타임아웃이 나면 무엇이 들어갔는지
> 알 수 없게 됩니다. 화면이 몇 건씩 나눠 보내고 결과를 표에 이어 붙입니다.
> 그래서 **진행바와 표가 함께** 있어야 합니다.

`등록 시작` 은 진행 중 `disabled` + `등록 중…`, 끝나면 `완료`로 바뀌고 계속 `disabled`
입니다(같은 목록을 두 번 올리는 사고를 막습니다).

## 5. C. 작업 현황판 ★ 신규 — `#panel_flow` 안

### 5-1. 놓이는 자리

```
┌ 진행 현황 ────────────────────────────────────────────────┐
│  ① 문서  ② 초안  ③ 검수 대기  ④ 서비스 중  ⑤ 품질  ⑥ 임계값 │  05번 6칸 (그대로)
├──────────────────────────────────────────────────────────┤
│  지금 할 일 : 검수 대기 12건…              [검수 화면 열기] │  05번 (그대로)
├──────────────────────────────────────────────────────────┤
│  ▶ 실행 중인 작업                              ← 신규      │
├──────────────────────────────────────────────────────────┤
│  최근 작업                                     ← 신규      │
├──────────────────────────────────────────────────────────┤
│  흐름 요약                                                 │  05번 (그대로)
└──────────────────────────────────────────────────────────┘
```

### 5-2. 작업 4종

| 작업 | key | 어디서 시작하나 | 걸리는 시간 |
| --- | --- | --- | --- |
| 문서 색인 | `index` | ⑤ 문서 · 폴더 등록 · 재색인 | 문서 수 × 수 초 |
| QA 생성 | `generate` | ⑥ QA 생성 | **수십 분** |
| 품질 평가 | `evaluate` | ⑦ 품질 평가 | 수십 초 |
| 문서 업로드 | `upload` | ⑤ 폴더 등록 | 문서 수 × 수 초 |

> **한 번에 하나만 돕니다.** 두 배치가 동시에 돌면 같은 자원을 나눠 쓰며 둘 다 느려집니다.
> 서버가 두 번째 요청을 409로 막습니다. 화면은 **실행 중인 작업 하나**만 보여주면 됩니다.

### 5-3. 실행 중 `#flowJob`

```
┌──────────────────────────────────────────────────────────────┐
│  ● QA 생성 중                          gemma4:latest · 12분 경과 │
│  문서에서 QA 생성 중… (24건) API 등록                            │
│  ▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░  62%   38 / 61                          │
│                                     [중지]  [생성 화면으로]      │
└──────────────────────────────────────────────────────────────┘
```

| 요소 | 내용 |
| --- | --- |
| 제목 | `● {작업 이름} 중` — `●` 는 도는 표시(스피너 또는 깜빡임) |
| 우측 메타 | 모델명 · 경과 시간 (`N분 경과`) |
| 단계 문구 | 서버가 준 `stage` 를 **그대로** 출력 |
| 진행바 | `percent` · `done / total` |
| `[중지]` | 지금까지 만든 것은 남기고 멈춥니다. **확인 모달 없이** 바로 |
| `[…화면으로]` | 해당 탭으로 이동 |

**아무것도 안 돌면 이 블록을 통째로 숨깁니다**(`hidden`). 빈 카드를 남기지 마세요.

### 5-4. 최근 작업 `#flowJobHistory`

끝난 작업 **5건**을 한 줄씩. 작업이 하나도 없으면 블록을 숨깁니다.

```
✓ QA 생성      08-16 09:12   38건 생성 · 9건 근거없음        14분   [검수하기 ▶]
✓ 문서 색인    08-16 08:40   24건 · 312청크                  2분    —
⚠ 품질 평가    08-15 18:40   중지됨 (48/120)                 —      [다시 측정]
✕ QA 생성      08-15 14:02   LLM 호출이 모두 실패했습니다      1분    [생성 화면으로]
```

- 상태 아이콘 4종: `✓`(done) · `⚠`(stopped) · `✕`(failed) · `●`(running, 맨 위)
- **`[다음 단계]` 버튼이 핵심입니다** → 5-5

### 5-5. 단계가 이어지게 ★

이 요청의 목적입니다. **작업이 끝나면 다음에 할 일이 그 자리에 버튼으로 뜹니다.**
관리자가 "이제 어느 탭으로 가야 하지"를 알 필요가 없어야 합니다.

| 끝난 작업 | 다음 단계 버튼 | 보내는 곳 |
| --- | --- | --- |
| 문서 업로드 / 색인 완료 | `QA 생성하기` | `generate` |
| QA 생성 완료 | `초안 검토하기` | `generate` (결과 표) |
| 초안 반영(pending) 완료 | `검수하기` | `review` |
| 검수로 승인이 생김 | `품질 측정하기` | `eval` |
| 품질 평가 완료 | `임계값 조정하기` | `settings` |
| 실패 | `{그 작업} 화면으로` | 해당 탭 |

- 버튼은 **가장 최근 작업 한 줄에만** 붙입니다. 목록 전체에 달면 무엇을 눌러야 할지
  다시 모르게 됩니다
- `지금 할 일` 배너(05번 5-2)와 문구가 겹칠 수 있습니다. **겹치면 배너가 우선**이고
  최근 작업의 버튼은 숨깁니다 — 화면에 지시가 둘이면 안 됩니다

### 5-6. 다른 탭에 있어도 보여야 합니다

수십 분짜리 배치라 관리자는 그동안 다른 화면을 봅니다.

- **사이드바에 실행 중 표시**: 돌고 있는 작업의 항목(`QA 생성` / `품질 평가` / `RAG 문서`)
  오른쪽에 작은 도는 점(`.admin_nav_spin`). 검수 배지와 자리가 겹치지 않게 해주세요
- **새로고침해도 이어집니다.** 진행 상태는 서버가 가지고 있으므로, 화면을 다시 열면
  실행 중 블록이 그대로 복원돼야 합니다. 화면 안에만 진행률을 두지 마세요

### 5-7. 상태

| 상황 | 모습 |
| --- | --- |
| 작업 없음 | `#flowJob` 숨김 |
| 실행 중 | 진행바 + 스피너 + `[중지]` |
| 중지 요청됨 | `[중지]` `disabled` + 문구 `중지 요청됨 — 진행 중인 항목까지 마치고 멈춥니다` |
| 실패 | `#flowJob` 을 숨기고 최근 작업 맨 위에 `✕` 줄 + 오류 문구 |
| 폴링 실패(서버 끊김) | 진행바는 그대로 두고 `연결이 끊겼습니다. 다시 확인 중…` 을 덧붙임 |

**폴링은 2초 간격**으로 하고, 실행 중인 작업이 없으면 폴링을 멈춥니다.

## 6. 서버가 내려주는 것

`GET /api/admin/jobs` — **개발 담당이 새로 만듭니다.** 화면은 더미로 진행해 주세요.
아래 모양으로 맞추면 배선이 그대로 붙습니다.

```json
{
  "running": {
    "key": "generate",
    "title": "QA 생성",
    "stage": "문서에서 QA 생성 중… (24건) API 등록",
    "percent": 62,
    "done": 38,
    "total": 61,
    "model": "질문 gemma4:latest · 답변 gemma4:12b · 채점 exaone3.5:7.8b",
    "started_at": "2026-08-16T09:12:00",
    "stopping": false,
    "tab": "generate"
  },
  "recent": [
    { "key":"index", "title":"문서 색인", "status":"done",
      "finished_at":"2026-08-16T08:40:00", "summary":"24건 · 312청크",
      "elapsed":"2분", "next":{ "label":"QA 생성하기", "tab":"generate" } },
    { "key":"evaluate", "title":"품질 평가", "status":"stopped",
      "finished_at":"2026-08-15T18:40:00", "summary":"중지됨 (48/120)",
      "elapsed":"", "next":null }
  ]
}
```

- `running` 이 `null` 이면 실행 중 블록을 숨깁니다
- `status` 는 `done` · `stopped` · `failed` 중 하나입니다
- **`next` 는 서버가 정합니다.** 화면이 작업 종류를 보고 다음 단계를 추측하지 마세요 —
  05번의 `todo` 와 같은 원칙입니다. `null` 이면 버튼을 감춥니다
- 중지: `POST /api/admin/jobs/{key}/stop`
