# API Manager 도우미 — 진행 현황 카드 도움말(`?`) 퍼블요청서

> **프로젝트**: `openapi-chat-serve`
> **선행 요청서**: `05_관리자_진행현황_및_메뉴개편_퍼블요청서.md`(6칸 상태판), `06_관리자_작업현황판_보완요청서.md`
> **범위**: 진행 현황 6칸 상태판의 **각 카드 우측 상단에 `?` 아이콘 + 말풍선 도움말**
> **기존 카드 구성·숫자·버튼은 그대로 둡니다**

---

## 1. 배경

### 1-1. 왜 필요한가

이 화면을 보는 사람은 **개발에 참여하지 않은 운영 담당자**입니다. 그런데 카드 이름만으로는
무엇을 세는 숫자인지 알 수 없습니다. 실제로 나온 질문이 이렇습니다.

- "**초안**이랑 **검수 대기**가 뭐가 다른가요?"
- "문서가 39개인데 왜 답변은 3개만 하나요?"
- "**임계값 0.90** 은 높은 건가요 낮은 건가요?"

지금은 이 질문에 답할 곳이 화면에 없습니다. 옆 사람에게 묻거나, 문서를 찾아야 합니다.

### 1-2. 왜 툴팁인가 — 다른 방법을 안 쓰는 이유

| 방법 | 안 쓰는 이유 |
| --- | --- |
| 카드에 설명을 상시 노출 | 6칸이 글자로 가득 차 **숫자가 안 보입니다.** 이 화면의 목적은 숫자를 한눈에 보는 것입니다 |
| 첫 방문 투어(온보딩) | 한 번 지나가면 다시 못 봅니다. 궁금해지는 시점은 **두 달 뒤**입니다 |
| 별도 도움말 페이지 | 화면을 떠나야 합니다. 떠나면 안 돌아옵니다 |

**필요할 때만, 그 자리에서** 보이는 것이 맞습니다.

## 2. 톤앤매너 · 기술 제약

`05` 요청서 2번과 동일합니다. 아래만 다시 강조합니다.

- **CDN 금지.** 폐쇄망입니다. 툴팁 라이브러리(tippy·popper 등)를 쓰지 마세요 — 직접 그려 주세요
- **자원 경로는 `/static/` 절대경로**
- 로컬 미리보기용 폴백은 `data-dev-only` 태그 안에만 (이식할 때 그 태그를 지웁니다)
- 조직 이름·서비스 이름을 문구에 쓰지 마세요 (`data-brand` 규약, `05` 2-1)
- 데스크톱 전용(`viewport width=1360`). 모바일·터치 대응은 범위 밖입니다

## 3. 놓이는 자리

```
┌─ ① 문서 ─────────────── ? ┐   ← 카드 우측 상단, 카드 번호(①)와 대각선 반대편
│ 39                        │
│ 모두 색인됨                │
│ [ 문서 관리 ]              │
└───────────────────────────┘
```

- 6칸 **전부**에 답니다. 일부만 있으면 "왜 이 카드만 없지"가 됩니다
- 카드는 `tpl_flow_step` 템플릿으로 그려집니다. **`?` 도 그 템플릿 안에** 넣어 주세요
- 숫자·버튼 위치는 지금 그대로입니다. `?` 때문에 줄바꿈이 생기면 안 됩니다

---

## 4. 문구 ★ 이 요청의 알맹이

**아래 문구를 그대로 넣어 주세요.** 개발이 확정한 내용이라 임의로 다듬지 말아 주세요
(숫자의 의미가 달라집니다). 줄바꿈 위치도 그대로입니다.

| 카드 | `data-help` | 문구 |
| --- | --- | --- |
| ① 문서 | `documents` | 챗봇이 답을 찾는 원본 문서 수입니다.<br>'모두 색인됨' 이면 검색에 쓰입니다.<br>문서는 관련 자료 안내에 쓰이고, 답변은 승인된 QA에서 나갑니다. |
| ② 초안 | `drafts` | AI가 문서를 읽고 만든 질문·답변 후보입니다.<br>아직 사용자에게 나가지 않습니다.<br>검수 대기와 다릅니다 — 초안은 아무도 안 본 상태입니다. |
| ③ 검수 대기 | `pending` | 승인만 남은 답변입니다.<br>승인해야 챗봇이 그 답을 씁니다. |
| ④ 서비스 중 | `approved` | 지금 챗봇이 실제로 답하는 QA 수입니다. |
| ⑤ 품질 | `quality` | 엉뚱한 답이 나간 비율입니다(오매칭률).<br>낮을수록 좋고, 품질 평가를 돌려야 채워집니다. |
| ⑥ 임계값 | `threshold` | 질문이 이만큼 비슷해야 저장된 답을 내보냅니다.<br>높일수록 신중해지고, 낮출수록 자주 답합니다. |

`data-help` 값은 **서버가 카드를 구분하는 키와 같습니다.** 카드 순서를 바꿔도 문구가 따라가도록
순서(①②③)가 아니라 이 키로 문구를 찾아 주세요.

문구는 **화면에 둡니다.** 서버가 내려주지 않습니다 — 고정 안내문이고 납품처마다 달라지지
않습니다. `admin.js` 상단에 `HELP_TEXT = { documents:'…', … }` 처럼 한곳에 모아 주세요.

## 5. 동작

### 5-1. 열고 닫기

| 상황 | 동작 |
| --- | --- |
| `?` 클릭 | 말풍선이 열립니다 |
| 다시 클릭 | 닫힙니다 |
| 다른 `?` 클릭 | 앞의 것이 닫히고 새 것이 열립니다 — **한 번에 하나만** |
| 바깥 클릭 · `ESC` | 닫힙니다 |
| 마우스 호버 | **열지 마세요.** 카드 위를 지나가기만 해도 말풍선이 튀어나옵니다 |

> 호버로 열면 카드의 `[문서 관리]` 버튼을 누르러 가는 길에 계속 열립니다. **클릭으로만** 엽니다.

### 5-2. 위치

- 기본은 `?` 아래에 붙습니다(말풍선 꼬리가 `?` 를 가리킵니다)
- **오른쪽 끝 카드(⑤·⑥)는 화면 밖으로 나갑니다.** 그 경우 왼쪽으로 펼쳐 주세요
- 카드 안에 갇히면 안 됩니다(`overflow:hidden` 주의). 카드 위로 떠야 합니다

### 5-3. 접근성

- `?` 는 `<button>` 입니다. `<span>` 에 클릭을 붙이면 키보드로 못 엽니다
- `aria-label="설명"` · `aria-expanded` · 말풍선에 `role="tooltip"`
- Tab 으로 이동 가능해야 하고, 열린 상태에서 `ESC` 로 닫히면 **포커스가 `?` 로 돌아옵니다**

## 5-4. 함께 옮길 것 — ⑤ RAG 문서의 `가이드 문서 작성 형식`

`?` 툴팁과 같은 성격(고정 안내문)이라 여기 함께 적습니다. **개발에서 이미 만들어 두었으니
새로 디자인하실 필요는 없고, 산출물에 빠뜨리지만 말아 주세요.**

- ⑤ RAG 문서 탭 우측 상단 버튼 `#docGuideBtn` (모드와 무관하게 항상 보입니다)
- 누르면 `#docGuideModal`(와이드)이 열립니다. 본문은 표 1개 + 목록 2개 + 예시 코드블록
- 현재 마크업: `app/static/admin.html` 의 `가이드 문서 작성 형식` 주석 블록
- 스타일: `.admin_guide` · `.admin_guide_lead` · `.admin_guide_code`

내용은 문서를 만드는 사람이 지켜야 할 형식입니다(절 길이·소제목·앞머리·파일 이름 규칙).
**숫자 하나(`#guideWarnChars`)만 서버 설정에서 채웁니다** — 화면에 박아 두면 설정과
조용히 어긋납니다.

## 6. 네이밍 규약

| 요소 | 이름 |
| --- | --- |
| 아이콘 버튼 | `.admin_help` (`data-help="documents"` 등) |
| 말풍선 | `.admin_help_pop` (열림 `.is_open`, 왼쪽 펼침 `.is_left`) |
| 말풍선 본문 | `.admin_help_txt` |

카드 템플릿은 기존 `tpl_flow_step` 을 그대로 쓰고 그 안에 `.admin_help` 를 추가합니다.

**다른 화면에서도 쓸 수 있게 만들어 주세요.** 지금은 6칸에만 붙지만, 같은 컴포넌트를
설정 화면의 임계값 항목에도 붙일 예정입니다. 카드 전용 스타일에 묶지 말아 주세요.

## 9. 이번 범위가 아닌 것

- **6칸 카드의 숫자·상태·버튼** — `05` 산출물 그대로입니다
- 작업 현황판(`#flowJob`)·흐름 요약 — `06` 산출물 그대로입니다
- 다른 화면(검수·QA 인덱스·설정)의 도움말 — 컴포넌트만 재사용 가능하게 두고, 붙이는 것은 다음에
- 서버 API — **이 기능은 서버를 부르지 않습니다.** 문구는 화면 상수입니다
- 첫 방문 투어·도움말 페이지·다국어
