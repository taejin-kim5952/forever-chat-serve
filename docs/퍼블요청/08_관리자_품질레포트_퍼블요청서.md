# API Manager 도우미 — 품질 레포트 화면 퍼블요청서 (초안)

> **프로젝트**: `openapi-chat-serve`
> **상태**: **초안**. 파이프라인을 한 바퀴 돌려 실제 숫자를 본 뒤 확정합니다
> **범위**: 사이드바에 `레포트` 항목 추가 + 인쇄·공유 가능한 한 장짜리 화면
> **선행 요청서**: `05`(진행 현황), `06`(작업 현황판), `07`(도움말)

---

## 1. 배경

### 1-1. 왜 필요한가

이 앱은 **여러 납품처에 설치하는 제품**입니다. 설치할 때마다 그 조직의 문서로 QA를 쌓고
품질을 재는 작업을 반복하게 되는데, 그 결과를 **프로젝트 담당자에게 설명해야** 합니다.

담당자가 묻는 것은 늘 넷입니다.

1. 지금 이 챗봇이 **얼마나 답할 수 있나**
2. 그 답이 **정확한가**
3. **얼마나 더 일해야** 하나
4. **무엇이 부족한가** — 문서를 더 줘야 하나

지금 화면에도 숫자는 많습니다(6칸 상태판·흐름 요약·품질 평가 표·작업 이력). 그런데
**흩어져 있고, 관리자가 작업하려고 보는 화면**입니다. 담당자에게 그대로 보여주면
"그래서 쓸 만한가요?"에 답이 안 됩니다.

### 1-2. 진행 현황 화면과 무엇이 다른가

| | 진행 현황 (05·06) | **레포트 (이번)** |
| --- | --- | --- |
| 읽는 사람 | 관리자(작업자) | **프로젝트 담당자(의사결정)** |
| 목적 | 지금 뭘 해야 하나 | 지금 쓸 만한가 · 뭐가 부족한가 |
| 성격 | 작업 화면 · 버튼이 많음 | **읽는 화면 · 인쇄·공유** |
| 시점 | 현재 | 기간 · 추이 |

**작업 버튼을 넣지 마세요.** 이 화면에서는 아무것도 실행하지 않습니다. 필요한 것은
"내보내기"뿐입니다.

## 2. 톤앤매너 · 기술 제약

`05` 요청서 2번과 동일합니다. 아래만 추가로 강조합니다.

- **CDN 금지** · 자원은 `/static/` 절대경로 · `data-dev-only` 폴백만 로컬 미리보기용
- **인쇄를 전제로 만들어 주세요.** `@media print` 로 사이드바·버튼을 감추고 A4 한 장에서
  두 장 사이로 떨어지게 합니다. 담당자에게 PDF로 넘기는 일이 실제로 생깁니다
- 조직 이름·서비스 이름은 `data-brand` (05번 2-1). **레포트 제목에도 박지 마세요**
- 데스크톱 전용

## 3. 화면 구성 (초안)

```
┌ 품질 레포트 ─────────────────────── 기간 [2026-08-01 ~ 08-17] [내보내기] ┐
│                                                                          │
│  ① 한 줄 요약                                                             │
│     "문서 39건에서 QA 82건을 만들어 서비스 중이고, 검색 정확도는           │
│      상위 1건 기준 72%입니다. 답을 못 만든 주제가 11건 있습니다."          │
│                                                                          │
│  ② 얼마나 답할 수 있나        ③ 정확한가                                  │
│     서비스 중 QA      82건       적중률(Top-1)      72.5%                  │
│     주제 커버리지   31/48       적중률(Top-3)      87.5%                  │
│     문서            39건        오매칭률 ★          2.5%                  │
│     변형 질문 평균   9.2개      미검색             10.0%                  │
│                                                                          │
│  ④ 얼마나 더 해야 하나         ⑤ 무엇이 부족한가 ★                        │
│     검수 대기        12건       근거 없어 버린 질문   11건                 │
│     초안(미반영)      8건        └ 주제별 목록 …                          │
│     문서 대비 미생성  6건        사용자가 물었는데 답 없음  4건            │
│                                                                          │
│  ⑥ 추이 (선택)                                                            │
│     서비스 중 QA · 오매칭률 — 최근 측정 5회                                │
└──────────────────────────────────────────────────────────────────────────┘
```

### 3-1. 각 칸의 성격

| 칸 | 성격 | 없을 때 |
| --- | --- | --- |
| ① 한 줄 요약 | **서버가 문장으로 만들어 내려줍니다** | — |
| ② 커버리지 | 숫자 4개 | 0으로 표시 |
| ③ 품질 | 숫자 4개 + `측정 이력 없음` | **"아직 측정하지 않았습니다"** 를 크게 |
| ④ 남은 일 | 숫자 3개 | 0이면 "밀린 작업 없음" |
| ⑤ 부족한 것 | **목록** — 이 화면의 핵심 | 비었으면 칸을 숨김 |
| ⑥ 추이 | 선택. 측정이 2회 이상일 때만 | 칸을 숨김 |

### 3-2. ⑤ 가 이 레포트의 핵심입니다 ★

담당자가 실제로 **행동할 수 있는 유일한 칸**입니다.

```
근거 없어 버린 질문 11건
  · "API 호출 요금은 얼마인가요?"          → 요금 관련 문서 없음
  · "장애 발생 시 어디로 연락하나요?"       → 운영 연락처 문서 없음
사용자가 물었는데 답이 없던 질문 4건        (운영 시작 후)
  · "테스트 계정은 어떻게 받나요?"  3회
```

나머지 칸은 "지금 이렇습니다"인데, 이 칸은 **"이 문서를 더 주세요"** 입니다.
문구를 서버가 만들고 화면은 그대로 그립니다.

---

## 4. 서버가 내려주는 것

`GET /api/admin/report?from=YYYY-MM-DD&to=YYYY-MM-DD` — **개발이 새로 만듭니다.**
화면은 더미로 진행해 주세요. 모양은 확정 뒤 이 문서에 채웁니다.

- 숫자·문장·목록을 **서버가 완성해서** 내려줍니다. 화면이 계산하거나 문장을 만들지 않습니다
  (`result_type`·`next` 를 서버가 정하는 것과 같은 원칙)
- 측정 이력이 없으면 품질 칸은 `null` 로 옵니다 — 화면은 "측정하지 않았습니다"를 그립니다

---

## 5. 이번 범위가 아닌 것

- 작업 실행 버튼 — 이 화면에서는 아무것도 실행하지 않습니다
- 기간 필터의 복잡한 조합 · 사용자별 통계
- 자동 발송(메일 등) · 다국어

---

## 6. 확정 전에 남은 것

이 문서는 **초안**입니다. 파이프라인을 한 바퀴 돌려(문서 → 생성 → 검수 → 측정) 실제 숫자를
본 뒤 아래를 확정해 이 문서를 갱신합니다.

- 담당자에게 **실제로 필요한 숫자**가 무엇인지 (지금 목록은 추정입니다)
- ⑤의 문구 형식 — 버려진 질문을 그대로 보여줄지, 주제로 묶을지
- 추이(⑥)를 넣을지 — 측정을 자주 하지 않으면 빈 칸이 됩니다
- git 커밋은 개발 담당자가 직접 수행합니다.
