# API Manager 도우미 — 답변 피드백(👍/👎) 퍼블요청서

> **프로젝트**: `openapi-chat-serve`
> **대상 파일**: `chat.html` · `chat.css` · `chat.js` · `admin.html` · `admin.css` · `admin.js`
> **선행 요청서**: `01`·`04`(챗봇) · `02`·`05`(관리자)
> **범위**: 화면 세 곳에 같은 데이터를 보여주는 작업입니다. **새 화면은 없습니다.**

`09`(주제 선택)와 별개 건이라 문서를 나눴습니다. **두 요청서는 서로 겹치지 않으니 순서 상관없이
작업하셔도 됩니다.**

---

## 1. 왜 필요한가 ★

지금 이 챗봇은 **틀린 답을 알아낼 방법이 없습니다.**

```
답을 못 찾음   → '준비되지 않았습니다' + 접수번호 → 관리자가 봅니다 ✅
답이 나왔는데 틀림 →  ???                          → 아무 흔적도 없습니다 ❌
```

답변은 담당자가 미리 검수해 둔 것이라 대체로 맞습니다. 문제는 **질문과 엉뚱하게 짝지어지는
경우**입니다. 이건 화면에서만 보이고 서버는 모릅니다.

### 사용자는 판정자가 아니라 신고자입니다

이 구분이 이 요청서 전체를 지배합니다.

```
사용자가 👎  →  답변은 그대로 나갑니다 (아무것도 안 바뀝니다)
             →  관리자 화면에 '여기 봐주세요' 표시만 붙습니다
             →  담당자가 열어보고 고칠지 말지 결정합니다
```

화재경보기와 같습니다. 누른 사람은 이상하다고 알리는 것이고, 판단하고 끄는 것은 다른 사람입니다.

## 2. A. 챗봇 — 답변 말풍선에 👍 / 👎

### 위치

`chat.html` 의 `<template id="tpl_answer">` 안 `.chat_meta` 줄, **`복사` 버튼 옆**입니다.

```
┌ 봇 말풍선 ──────────────────────────────────────┐
│ **API 그룹(SPC)** 을 먼저 만든 뒤…               │
│ 1. API Manager > API 그룹 …                     │
│                                                 │
│ 출처                                             │
│ 📄 api-등록                                      │
│ ✓ 담당자 검수 완료 · AI가 작성한 답변  [복사] 👍 👎 │  ← 여기
└─────────────────────────────────────────────────┘
```

- **`tpl_answer` 에만** 붙습니다. `tpl_related`(관련 문서 카드) · 접수번호 · 오류 · 로딩
  말풍선에는 없습니다. 검수된 답변에 대한 평가라서 그렇습니다
- 기존 `.chat_meta` 줄이 좁아지지 않게 해주세요. 좁은 화면에서는 줄바꿈이 되어도 괜찮습니다
- 아이콘만 두고 라벨은 `aria-label` 로 주세요(`도움이 됐어요` / `도움이 안 됐어요`)

### 👎를 누르면 — 이유를 한 번 더

👎만으로는 담당자가 무엇을 해야 할지 모릅니다. 이유마다 조치가 완전히 다릅니다.

| 사용자가 고른 이유 | 담당자가 하는 일 |
| --- | --- |
| `질문과 다른 답이에요` | 변형 질문을 늘리거나 임계값 조정 — **답변 자체는 멀쩡합니다** |
| `내용이 틀려요` | 문서를 다시 보고 답변 수정 |
| `설명이 부족해요` | 답변 보강 |

```
│ ✓ 담당자 검수 완료 · AI가 작성한 답변  [복사] 👍 [👎] │
│ ┌───────────────────────────────────────────────┐ │
│ │ 어떤 점이 아쉬웠나요?                     건너뛰기 │ │
│ │ (질문과 다른 답이에요) (내용이 틀려요)          │ │
│ │ (설명이 부족해요)                              │ │
│ └───────────────────────────────────────────────┘ │
```

- **모달이 아니라 말풍선 안에 인라인**으로 펼쳐 주세요. 모달은 무거워서 그냥 닫고 나갑니다
- `건너뛰기` 를 반드시 두세요. **이유를 안 골라도 👎는 이미 기록됩니다**
- 이유를 고르면 접히고 `의견 감사합니다` 로 바뀝니다 (2초 뒤 조용히 사라져도 좋습니다)
- 👍는 이유를 묻지 않습니다. 바로 `감사합니다`

### 누른 뒤 상태

- 누른 쪽에 `.is_on`. `aria-pressed="true"`
- **다시 누르면 취소됩니다.** 잘못 누르는 일이 잦아서 잠그지 않는 편이 낫습니다.
  👍↔👎 도 바꿀 수 있습니다 (마지막에 고른 것만 유효)
- 저장은 자동입니다. `저장` 버튼을 만들지 말아주세요
- **서버 저장이 실패해도 화면은 멈추지 않아야** 합니다. 조용히 원래 상태로 되돌리면 됩니다.
  피드백 때문에 답변 읽기가 방해받으면 안 됩니다

### ★ 사용자에게 집계를 보여주지 말아주세요

`이 답변이 도움이 됐다고 답한 분 12명` 같은 표시를 넣지 말아주세요. 다른 사람의 판단이 보이면
따라 누릅니다. 신고 내용이 왜곡되면 이 기능을 만든 이유가 사라집니다.

## 3. B. 관리자 ① `질문 이력` — 열 하나 추가

`admin.html` 의 `#histTable` 입니다. 사용자가 실제로 물어본 질문이 쌓이는 표에 **평가 열**을
넣어 주세요.

```
시각    │ 질문              │ 결과 유형 │ 매칭된 QA        │ 유사도 │ 평가 │ 주제
────────┼───────────────────┼──────────┼─────────────────┼───────┼─────┼──────
14:22   │ 권한그룹 설정하려면 │ answer   │ 권한그룹은 어떻게…│ 0.94  │ 👎  │ 그룹
14:19   │ API 등록 절차      │ answer   │ API 등록은 어떻게…│ 0.98  │ 👍  │ 등록
14:03   │ 과금 정책          │ unresolved│ —               │ 0.41  │  –  │ –
```

- 폭 70px 정도, `유사도` 와 `주제` 사이
- 값은 셋뿐입니다 — 👍 / 👎 / `–`(안 누름). **대부분은 `–` 입니다.** 그게 정상이라
  비어 보인다고 이상한 게 아닙니다
- 👎 는 행에서 눈에 띄어야 합니다. 다만 **행 전체를 붉게 칠하지는 말아주세요** —
  오류가 아니라 신고입니다
- 👎 에 마우스를 올리면 고른 이유를 툴팁으로 (`내용이 틀려요`)
- 기존 필터 칩 줄(`data-rt`)에 **`👎만` 칩**을 하나 추가해 주세요
- `CSV 내려받기` 결과에도 평가·이유가 들어갑니다 (개발이 처리합니다)

## 4. C. 관리자 ② `검수` — 여기가 진짜 목적지입니다

질문 이력에만 두면 담당자가 일부러 찾아 들어가야 하고, 대개 안 봅니다. **숫자만 쌓이고 아무도
안 고치는** 상태가 됩니다.

검수 화면에 보여야 그날 무엇을 먼저 볼지가 저절로 정해집니다.

### 4-1. 정렬에 항목 추가

`#revSort` 에 `👎 많은순` 을 추가해 주세요. 지금 있는 네 개(점수 낮은순 · 점수 높은순 ·
최근 생성순 · 적중 많은순) 뒤에 붙이면 됩니다.

### 4-2. 편집 폼에 `사용자 신고` 영역

공용 QA 편집 컴포넌트(`검수` 화면과 `QA 검수` 모달이 같은 마크업을 씁니다) 안,
`검수 메모` 근처에 접이식으로 넣어 주세요.

```
┌ 사용자 신고 ── 👎 3 ───────────────────────── ▾ ┐
│ 질문과 다른 답이에요 2 · 내용이 틀려요 1         │
│                                                │
│ 08-17 14:22  "권한그룹 설정하려면"      0.94    │
│ 08-17 11:05  "그룹 권한 주는 법"        0.91    │
│ 08-16 16:40  "권한 어떻게 바꿔요"       0.93    │
└────────────────────────────────────────────────┘
```

- **신고가 0건이면 영역을 통째로 감춰 주세요.** 대부분의 QA가 여기 해당합니다
- 실제 질문 원문이 보이는 것이 핵심입니다. 담당자는 이걸 보고
  `아, 이 표현이 안 걸리는구나` 를 알고 변형 질문을 추가합니다
- 목록은 최근 5건까지. 더 있으면 `질문 이력에서 전체 보기` 링크
- 접힘이 기본입니다. 검수 화면은 이미 세로가 깁니다

## 5. ★ 넣지 말아주실 것

이 셋은 넣으면 **해가 됩니다.**

**1. 만족도 비율 (`82% 도움됨`)** — 대부분은 아무것도 안 누르고, 만족한 사람은 특히 안
누릅니다. 비율을 만들면 그건 거짓말입니다. 읽는 방법은 하나뿐입니다 —
**어느 QA에 👎가 몰리는가.** 절대 개수와 상대 비교만 보여주세요.

**2. 자동 처리 버튼 (`👎 3건 이상 자동 미사용`)** — 사용자 클릭이 답변 상태를 바꾸면
*검수한 답변만 나간다*는 이 제품의 전제가 무너집니다. 내리는 것은 사람이 합니다.

**3. 사용자 화면의 신고 접수 문구** — `신고가 접수되었습니다` 같은 말은 무겁습니다.
`의견 감사합니다` 정도면 충분합니다.
