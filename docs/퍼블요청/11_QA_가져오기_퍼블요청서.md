# API Manager 도우미 — QA 가져오기 퍼블요청서

> **프로젝트**: `openapi-chat-serve`
> **대상 파일**: `admin.html` · `admin.css` · `admin.js` · `admin-mapping.md`
> **선행 요청서**: `05`(사이드바·진행 현황) · `06`(작업 현황판)
> **범위**: 모달 하나 + 사이드바 진입 버튼. **새 탭은 만들지 않습니다.**
> **참고할 기존 화면**: ⑤ RAG 문서의 `폴더 등록`(`#docUploadModal`) — 구조를 거의 그대로 씁니다

---

## 1. 왜 필요한가 ★

이 제품은 **답변을 만드는 곳과 답변하는 곳이 다릅니다.**

```
스튜디오 PC (LLM 있음)            운영·개발 서버 (LLM 없음)
문서 → 질문 → 답변 → 채점   ──?──→  검수 → 승인 → 답변
                              ↑
                        이 길이 없습니다
```

운영 서버에는 GPU가 없어 LLM을 올리지 않습니다. 그래서 QA는 사내 작업 PC에서 미리 만들고,
서버는 그것을 검수해서 내보내기만 합니다. **검수·승인 화면은 서버에서도 이미 동작합니다.**
빠진 것은 "만들어 둔 QA를 서버로 들여오는 길" 하나뿐입니다.

지금은 방법이 둘 다 나쁩니다.

| 지금 방법 | 문제 |
| --- | --- |
| `qa_index.json` 파일을 통째로 덮기 | **서버에 쌓인 것이 지워집니다** — 적중 횟수, 서버에서 승인한 QA, 사용자 신고 |
| API로 한 건씩 밀어넣기 | 스크립트를 아는 사람만 할 수 있습니다. 무엇이 들어갔는지 화면에 안 남습니다 |

---

## 2. 어디에 넣나

⑤ RAG 문서의 `폴더 등록` 과 **똑같은 자리·똑같은 방식**입니다. 사이드바 ④ `검수` 화면
머리 오른쪽에 버튼 하나를 두고, 누르면 모달이 열립니다.

```
┌ 검수 ─────────────────────────────────────────────┐
│ 승인해야 사용자에게 나갑니다.      [QA 가져오기]  │  ← 버튼 추가
│                                                   │
│ 검수 대기 12건   ＃주제 전체   [점수 낮은순 ▾]    │
└───────────────────────────────────────────────────┘
```

검수 화면에 두는 이유는, 가져오기의 **결과가 곧 검수 대기줄**이기 때문입니다. 들여온 뒤
바로 그 자리에서 검수를 시작하게 됩니다.

---

## 3. 모달 — `#qaImportModal`

`#docUploadModal` 을 그대로 본뜨면 됩니다. 파일 선택 → 미리보기 → 실행 → 결과표 순서입니다.

### 3-1. 1단계 · 파일 선택

```
┌ QA 가져오기 ────────────────────────────────── ✕ ┐
│                                                  │
│  스튜디오에서 만든 QA 파일을 올립니다.           │
│  ┌────────────────────────────────────────────┐  │
│  │            파일을 끌어다 놓거나             │  │
│  │              [ 파일 선택 ]                  │  │
│  │        generated_qa.json · qa_index.json    │  │
│  └────────────────────────────────────────────┘  │
│                                                  │
│                          [닫기]  [내용 확인]     │
└──────────────────────────────────────────────────┘
```

- **파일 하나**만 받습니다(폴더 업로드와 다릅니다). `.json` 만
- 끌어다 놓기와 버튼 둘 다 됩니다. `#docUploadModal` 에 이미 있는 방식 그대로
- 파일을 고르면 이름과 크기를 보여주고 `내용 확인` 버튼이 활성화됩니다

### 3-2. 2단계 · 미리보기 ★ — 이 화면이 이 요청서의 핵심입니다

**올리기 전에 무엇이 어떻게 될지 먼저 보여줍니다.** 서버에는 이미 사람이 검수한 결과가
쌓여 있어서, 덮어쓰기 전에 확인할 기회가 없으면 안 됩니다.

```
┌ QA 가져오기 ────────────────────────────────── ✕ ┐
│  generated_qa.json · 12건                        │
│                                                  │
│   ┌─────────┬─────────┬─────────┐                │
│   │ 새로 들어옴 │  덮어씀  │  건너뜀  │                │
│   │    8건   │    3건   │    1건   │                │
│   └─────────┴─────────┴─────────┘                │
│                                                  │
│  ┌──────────────────────────────────────────┐    │
│  │ 상태 │ 대표 질문          │ 주제 │ 점수 │    │
│  │ 새로 │ 권한그룹은 어떻게… │ 권한 │  4   │    │
│  │ 덮음 │ API 등록 절차는…   │ 등록 │  5   │    │
│  │ 건너뜀│ 템플릿 수정하면…  │ 템플 │  —   │    │
│  └──────────────────────────────────────────┘    │
│                                                  │
│  ☐ 이미 있는 QA도 덮어씁니다                     │
│                                                  │
│                       [닫기]  [가져오기 시작]    │
└──────────────────────────────────────────────────┘
```

- 숫자 세 개는 **서버가 계산해서 내려줍니다.** 화면이 세지 않습니다
- `상태` 열은 세 값입니다 — `새로` / `덮음` / `건너뜀`
- 체크박스를 끄면 이미 있는 것은 전부 `건너뜀` 으로 바뀝니다. **끈 상태가 기본**입니다
- 목록이 길 수 있습니다(수백 건). 표 영역만 세로 스크롤

### 3-3. 3단계 · 진행과 결과

`#docUploadModal` 의 진행 막대(`.admin_progress`)와 결과표를 그대로 씁니다.

```
│  ▓▓▓▓▓▓▓▓▓░░░░░░  9 / 12                        │
│  ┌──────────────────────────────────────────┐    │
│  │ 대표 질문         │ 결과   │ 비고        │    │
│  │ 권한그룹은 어떻게…│ 추가   │ 검수 대기   │    │
│  │ API 등록 절차는…  │ 덮음   │ 검수 대기   │    │
│  │ 과금 정책은…      │ 실패   │ 주제 없음   │    │
│  └──────────────────────────────────────────┘    │
│                                                  │
│              [닫기]  [검수 화면으로]              │
└──────────────────────────────────────────────────┘
```

- **한 번에 다 보내지 않고 몇 건씩 나눠 보냅니다.** 수백 건이면 한 요청에 담을 때
  진행 상황을 못 보여주고, 타임아웃이 나면 무엇이 들어갔는지 알 수 없습니다.
  폴더 업로드가 같은 이유로 그렇게 동작합니다
- 실패한 줄은 남겨 주세요. 왜 실패했는지가 `비고` 에 옵니다
- 끝나면 `검수 화면으로` 버튼(`data-goto-tab="review"`)

## 4. ★ 지켜야 하는 규칙 셋

**1. 들여온 QA는 무조건 `검수 대기` 입니다.**
파일에 `승인` 이라고 적혀 있어도 대기로 들어옵니다. 화면에 `승인 상태로 가져오기` 같은
선택지를 **만들지 말아주세요.** 검수를 거치지 않은 답변이 사용자에게 나가는 경로가 생기면
이 제품의 전제가 무너집니다.

**2. 운영에서 쌓인 값은 덮지 않습니다.**
덮어쓰기를 골라도 적중 횟수·사용자 신고는 서버 것이 유지됩니다. 화면에 그렇게 적어 주세요 —
검수자가 "덮으면 다 지워지나?" 를 걱정하지 않도록.

**3. 되돌리기는 없습니다.**
그래서 3-2의 미리보기가 필수입니다. `가져오기 시작` 을 누르기 전이 마지막 확인 지점입니다.
덮어쓸 건수가 0보다 크면 확인 모달(`#confirmModal` 재사용)을 한 번 더 띄워 주세요.

---

## 5. 화면에 적을 안내 문구

검수자가 스튜디오를 모를 수 있습니다. 모달 위쪽에 한 줄로.

> 사내 작업 PC에서 만든 QA 파일을 올립니다. 올린 항목은 **검수 대기**로 들어오며,
> 승인하기 전에는 사용자에게 나가지 않습니다.

`?` 도움말(요청서 07 방식)을 붙이신다면 이 정도면 충분합니다.

> **QA 파일이란**
> 답변을 만드는 일은 AI 모델이 필요해서 사내 작업 PC에서 합니다. 이 서버에는 그 모델이
> 없어서, 만들어 둔 결과를 파일로 받아 옵니다.

## 8. 이번 범위가 아닌 것

- **내보내기**(서버 → 파일) — 필요해지면 따로 요청드립니다
- 서버에서 QA를 생성하는 화면 — 운영에 LLM이 없어 만들 수 없습니다
- 문서(`raw_docs`) 가져오기 — ⑤ 폴더 등록에 이미 있습니다
- 자동 동기화·스케줄
