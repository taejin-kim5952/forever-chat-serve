## 1. 2차 산출물은 그대로 올렸습니다

재작업 요청(13-1) 여덟 가지가 전부 해결됐습니다. 검사도 통과했습니다.

```
x-import · sc-if · {{ }} · 인라인 style · _ds/ · support.js   전부 0
외부 요청 0 · data-dev-only 0 · 조직명 하드코딩 0 · 폰트 로컬
<template> 7개 · data-bind 29곳 · 표준 <input type="checkbox"> · <select>
```

**이미 서버에 연결해 돌리고 있습니다.** `loadLibrary` · `loadModels` · `openStream` 세 자리를
표시해 주신 덕에 그 블록만 바꿔 끼웠고, 실제 모델로 답변이 흘러나오는 것까지 확인했습니다.

```
AI 끔  →  answer 40조각 · 출처 1건 · 2.0초
AI 켬  →  thinking 20 · answer 42 · 출처 2건 · 58초 (qwen3.5:4b)
```

디자인·클래스 이름·동작 규칙은 **하나도 바꾸지 않았습니다.**

## 2. 문제 — 기존 화면에 있던 기능 둘이 빠졌습니다 ★

원 요청서(13)에 **"지금 화면에 있는 기능 목록"** 을 적지 않은 것이 저희 잘못입니다. 새 화면을
그리는 데 집중하다 보니 빠진 것을 뒤늦게 알았습니다.

| 빠진 것 | 원 요청서 | 서버 | 빠지면 |
| --- | --- | --- | --- |
| **답변 피드백 👍/👎** | `10_답변피드백_퍼블요청서.md` | `POST /api/feedback` 살아 있음 | 관리자 검수 화면의 `사용자 신고` 와 `👎 많은순` 정렬이 **입력이 끊겨 죽습니다** |
| **담당자 문의 + 접수번호** | `01` · `04` | `POST /api/support` 살아 있음 | 답을 못 찾은 사용자가 **넘길 곳이 없어집니다** |

`새 대화`(`#chatNew`) · `답변 복사` · `출처 문서`(`#chatDocModal`) 는 이름만 바뀌어 살아
있습니다. 그대로 쓰겠습니다.

### 왜 이 둘이 중요한가

이 제품은 **사용자가 판정자가 아니라 신고자**라는 전제로 만들어졌습니다. 👍/👎 는 QA 상태를
바꾸지 않고, 관리자 검수 화면의 **"어느 답변에 👎가 몰리는가"** 로만 흘러갑니다. 그 입력이
없으면 운영자가 무엇을 고쳐야 할지 알 길이 사라집니다.

접수번호도 마찬가지입니다. 답을 못 찾았을 때 **화면에서 번호를 만들면 안 됩니다** — 사용자가
부르는 번호와 이력에 남은 번호가 달라져 담당자가 찾지 못합니다. 서버가 만든 번호를 보여
주기만 하면 됩니다.

## 3. 요청 ① — 답변 피드백 👍/👎

### 3-1. 어디에

**검수된 답변**(`.chat_msg[data-mode="verified"]`)의 꼬리말에 넣어 주세요.
`.chat_meta_verified` 옆자리입니다.

```
┌────────────────────────────────────────────────┐
│ ✓ 담당자 검수 답변                               │
│                                                │
│ API 는 등록 → TB 배포 → 테스트 → 운영 배포 …     │
│                                                │
│ 📄 참고 자료                                    │
│ ┌──────────────┐                               │
│ └──────────────┘                               │
│                                                │
│ 담당자 검수 완료 · 2초    [👍] [👎]  [복사]      │  ← 여기
└────────────────────────────────────────────────┘
```

**AI 답변(`data-mode="ai"`)에는 넣지 마세요.** 아직 검수되지 않은 답이라 신고 대상이 아니고,
서버가 연결할 `log_id` 도 주지 않습니다.

### 3-2. 👎 를 누르면 이유를 묻습니다

모달이 아니라 **말풍선 안에서 펼쳐지는** 형태로 부탁드립니다. 모달은 무거워서 그냥 닫고
나갑니다(요청서 10에서 같은 판단을 했습니다).

```
│ 담당자 검수 완료 · 2초    [👍] [👎✓]  [복사]      │
│ ┌────────────────────────────────────────────┐ │
│ │ 어떤 점이 아쉬웠나요?                    ✕  │ │
│ │ ( ) 질문과 다른 답이에요                     │ │
│ │ ( ) 내용이 틀려요                           │ │
│ │ ( ) 설명이 부족해요                          │ │
│ └────────────────────────────────────────────┘ │
```

세 가지 사유는 **서버가 정한 값**입니다. 문구를 바꾸지 말아 주세요.

| 값 | 화면 문구 |
| --- | --- |
| `mismatch` | 질문과 다른 답이에요 |
| `wrong` | 내용이 틀려요 |
| `thin` | 설명이 부족해요 |

### 3-3. 상태

| 상태 | 화면 |
| --- | --- |
| 아무것도 안 누름 | 두 버튼 모두 꺼짐 |
| 👍 누름 | 👍 켜짐. 다시 누르면 **취소**(둘 다 꺼짐) |
| 👎 누름 | 👎 켜짐 + 이유 펼침. 이유를 고르면 접힘 |
| 보낸 뒤 | `의견 감사합니다` 같은 짧은 표시 후 사라짐 |

### 3-4. 서버 계약

```
POST /api/feedback
{ "log_id": "q_0de299e10cf5", "vote": "up" | "down" | "", "reason": "mismatch" | null }
```

- `log_id` 는 저희가 `done` 이벤트로 받아 말풍선에 심어 둡니다.
  **`.chat_msg` 에 `data-log-id` 속성 자리만** 만들어 주세요
- `vote: ""` 는 취소입니다
- `reason` 은 👎 일 때만 보냅니다

## 4. 요청 ② — 담당자 문의 + 접수번호

### 4-1. 언제 나오나

답을 못 찾았을 때입니다. 서버가 `done` 이벤트에 `ticket_id` 를 담아 보냅니다.

```
done · ticket_id 없음  →  평소 답변 (지금 그대로)
done · ticket_id 있음  →  아래 안내를 답변 자리에 보여 줍니다
```

### 4-2. 두 가지 모양

**(가) 자료는 찾았지만 답이 없을 때** — 참고 자료 아래에 문의 버튼을 둡니다.

```
│ 이 질문에 딱 맞는 답변이 아직 준비되지 않았습니다.│
│ 아래 자료를 확인해 주세요.                       │
│ 📄 참고 자료                                    │
│ ┌──────────────┐ ┌──────────────┐             │
│ └──────────────┘ └──────────────┘             │
│                                                │
│ 찾으시는 내용이 없나요?   [ 담당자에게 문의하기 ] │  ← 추가
```

**(나) 접수된 뒤** — 번호를 보여 줍니다. **번호는 서버가 준 값만** 씁니다.

```
│ ⓘ 문의가 담당자에게 접수되었습니다.               │
│                                                │
│ 접수번호  TCK-20261006-BF691      [복사]        │
│ 확인 후 등록된 이메일로 회신드립니다.              │
```

### 4-3. 서버 계약

```
POST /api/support
{ "question": "사용자가 물은 그대로", "category_id": "지금 고른 주제 또는 null" }
→ { "ticket_id": "TCK-20261006-BF691", "message": "문의가 담당자에게 접수되었습니다." }
```

- **화면이 번호를 만들지 마세요.** 예전 화면이 번호가 없을 때 직접 만들게 돼 있었는데,
  그 함수가 애초에 없어서 거기서 자바스크립트가 멈췄습니다(2026-10-06). 번호가 없으면
  **접수 영역을 통째로 감추는** 쪽이 맞습니다
- 접수 버튼은 한 번 누르면 비활성이 됩니다. 두 번 누르면 번호가 두 개 생깁니다

## 5. 작은 것 하나 — 맨 아래로

긴 답변을 읽으며 위로 올라갔을 때 돌아올 길이 없습니다. 예전 화면에는 떠 있는 `↓` 버튼이
있었습니다(`#chatToBottom`). 새 디자인이 자동 추종(`state.stick`)을 하고 있어서 **필요
없다고 보시면 넣지 않으셔도 됩니다.** 판단을 맡기겠습니다.

## 6. 내보내실 것

**바뀐 파일만** 주시면 됩니다. 저희가 그 부분만 얹겠습니다.

```
chat.html        ← 피드백·문의 마크업과 <template> 추가분
chat.css         ← 그 스타일
chat.js          ← 상태 처리 (서버 호출은 저희가 끼웁니다. 자리만 주세요)

```

`chat.js` 의 서버 호출은 **빈 함수로 두고 주석만** 남겨 주세요. 지금 `loadLibrary` ·
`loadModels` · `openStream` 에 해 주신 방식 그대로가 가장 좋았습니다.

```js
// 실제: fetch('/api/feedback', { method:'POST', body: JSON.stringify({log_id, vote, reason}) })
function sendFeedback(logId, vote, reason) { return Promise.resolve(); }
```
