# 포에버소프트 지식AI — 사용자 화면 재설계 요청서

> **프로젝트**: `openapi-chat-serve`
> **대상 파일**: `chat.html` · `chat.css` · `chat.js` · `chat-mapping.md`
> **선행 요청서**: `01_사용자_챗봇화면_퍼블요청서.md` · `04` · `09` · `10`
> **범위**: 사용자 화면 **전체 재설계**. 관리자 화면은 건드리지 않습니다.
> **서버 변경**: 함께 진행합니다. 퍼블은 **더미 데이터로 동작하는 화면**까지 만들어 주세요.

지금까지는 요청서마다 부분을 보완해 왔는데, 이번은 **사용자 화면을 다시 짜는 요청**입니다.
제품이 "사내 FAQ 챗봇"에서 **"사내 지식 자료를 보고 묻는 도구"** 로 성격이 바뀌었고, 화면이
그 변화를 따라가지 못하고 있습니다.

지금 화면은 저희가 기능을 급히 붙여 온 결과라 완성도가 낮습니다. **서가·입력 영역·답변
영역을 처음부터 다시 잡아 주시기를 부탁드립니다.**

## 0. 지금 화면과 문제

```
┌─ 자료 서가 ────┬─────────────────────────────────────────┐
│ [프로젝트 ▾]   │  [로고] 포에버소프트 지식AI    관리자 새 대화 │
│ # 등록·배포 절차│                                         │
│   ▌▌ ━━━━━━   │        무엇이 궁금하신가요?               │
│ # 등록 화면 항목│        자주 찾는 주제                     │
│   ▌  ━━━━━━   │        전체 주제 보기 ▾                   │
│                │                                         │
│                │           …빈 대화 영역…                 │
│                ├─────────────────────────────────────────┤
│                │  # 주제 ▾                               │
│                │  [●] AI 답변  문서를 근거로 AI가 정리합니다 │
│                │  [질문을 입력하세요          ] [전송]     │
└────────────────┴─────────────────────────────────────────┘
```

| 문제 | 설명 |
| --- | --- |
| 서가가 **책등**(세로 막대)이라 무슨 자료인지 안 읽힌다 | 제목이 세로쓰기로 눌려 있어 알아볼 수 없습니다 |
| 입력 영역에 **스위치 하나뿐** | 어떤 AI가 답하는지, 어떻게 답하는지 사용자가 고를 수 없습니다 |
| 답변이 **한 번에 툭** 나온다 | 기다리는 동안 점 세 개만 돕니다. 멈춘 건지 도는 건지 모릅니다 |
| 전체적으로 **빈 공간이 많고 밀도가 낮다** | 첫 화면에 안내 세 줄뿐이라 무엇을 할 수 있는 도구인지 전달되지 않습니다 |

## 1. 왼쪽 — 자료 서재

### 1-1. 바뀌는 점

지금은 책등(세로 막대)이 선반에 꽂힌 모양인데, **앞표지가 보이는 모양**으로 바꿔 주세요.

```
┌─ 자료 서재 ──────────────┐
│ [ API Manager 도우미  ▾ ] │  프로젝트 선택
│ 주제를 고르면 자료가 바뀝니다│
├──────────────────────────┤
│ # 등록·배포 절차      7문답│  ← 주제 (누르면 아래 자료가 바뀜)
│ # 등록 화면 입력 항목  5문답│
│ # 운영 배포 관리      3문답│
├──────────────────────────┤
│  ┌────────────────────┐  │
│  │                    │  │  ← 앞표지 1
│  │  API 등록 · 배포 절차│  │     한 줄에 하나
│  │                    │  │
│  │  10개 절 · 이용가이드 │  │
│  └────────────────────┘  │
│  ┌────────────────────┐  │
│  │                    │  │  ← 앞표지 2
│  │  API 등록 화면 입력  │  │
│  │  항목               │  │
│  │                    │  │
│  │  10개 절 · 이용가이드 │  │
│  └────────────────────┘  │
│           ⋮ (세로 스크롤) │
└──────────────────────────┘
```

**요청 사항**

1. **앞표지(커버) 카드 모양**으로 세워 주세요. 책 표지처럼 제목이 크게 읽혀야 합니다
2. **한 줄에 하나.** 두 개씩 늘어놓지 마세요 — 폭이 좁아 제목이 잘립니다
3. **세로 스크롤.** 주제를 고르면 그 주제의 자료만 남고 목록이 바뀝니다
4. 커버에 들어갈 것: **제목**(크게) · **절 수** · **분류**(`이용가이드` 같은 문자열)
5. 누르면 **문서 원문 모달**이 열립니다 (기존 `[data-doc-open]` 배선을 그대로 씁니다)
6. 책등·선반 같은 **장식은 빼도 됩니다.** 표지가 읽히는 쪽이 우선입니다

### 1-2. 상태

| 상태 | 화면 |
| --- | --- |
| 주제를 아직 안 고름 | 그 프로젝트의 **전체 자료**를 보여줍니다 |
| 주제를 고름 | 그 주제의 자료만. 고른 주제가 켜진 채로 남습니다 |
| 자료 0건 | `이 주제에는 아직 자료가 없습니다` (주제 줄은 그대로 둡니다) |
| 프로젝트 1개뿐 | 프로젝트 선택기를 숨기고 이름만 표시합니다 |
| 화면 폭 < 1,500px | 서재를 접습니다. 대화가 먼저입니다 |

### 1-3. 서버가 주는 데이터

`GET /api/library` — 지금도 동작합니다.

```json
{
  "groups": [
    {
      "group_id": "apiops_guide",
      "group_name": "API 등록 및 배포 가이드",
      "categories": [
        {
          "category_id": "apiops_process",
          "name": "등록·배포 절차",
          "qa_count": 7,
          "questions": ["API 등록 절차가 어떻게 되나요?", "…"],
          "docs": [
            { "doc_id": "apiops-usage-1-process", "title": "API 등록 · 배포 절차", "chunk_count": 10 }
          ]
        }
      ]
    }
  ],
  "unshelved": []
}
```

> **분류 문자열**(`이용가이드`)은 지금 응답에 없습니다. 서버가 `docs[].category` 를 추가할
> 예정이니 그 자리를 비워 두고 마크업만 잡아 주세요.

## 2. 입력 영역 — 사용자가 고르는 세 가지

지금은 `AI 답변` 스위치 하나뿐입니다. **셋을 고를 수 있게** 해 주세요.

```
┌────────────────────────────────────────────────────────────┐
│  # 등록·배포 절차 ✕                                         │
│                                                            │
│  [●] AI 답변     [ qwen3.5:4b ▾ ]     [ ] 추론 과정 보기     │
│   ①                   ②                      ③             │
│                                                            │
│  [ 질문을 입력하세요                          ] [ 전송 ]     │
│  AI가 만든 답변을 담당자가 검수한 내용입니다.                 │
└────────────────────────────────────────────────────────────┘
```

| | 이름 | 뜻 | 기본값 |
| --- | --- | --- | --- |
| ① | **AI 답변** | 끄면 **검수된 답변만**, 켜면 **AI가 자료를 읽고 정리** | 끔 |
| ② | **모델** | 어떤 AI가 답할지 고릅니다 | 서버 기본값 |
| ③ | **추론 과정 보기** | AI가 생각하는 과정을 펼쳐서 보여줍니다 | 끔 |

### 2-1. 서로 묶여 있습니다 ★

**① 이 꺼져 있으면 ②③ 은 쓸 수 없습니다.** 검수된 답변을 그대로 내보내는 길이라 모델도
추론도 개입하지 않습니다. 비활성(흐리게)으로 두고, 눌러 보면 왜 못 쓰는지 **짧은 안내**가
뜨게 해 주세요.

```
① AI 답변 끔  →  ② 모델 [비활성]   ③ 추론 [비활성]
① AI 답변 켬  →  ② 모델 [선택 가능]  ③ 추론 [선택 가능]
```

이 규칙을 화면에서 지키지 않으면, 사용자가 모델을 고른 뒤 "왜 그 모델이 답을 안 하지"로
헤맵니다. 실제로 저희가 스위치 하나만 뒀을 때 같은 혼란이 있었습니다.

### 2-2. 모델 선택기

- 서버가 설치된 모델 목록을 줍니다 (`GET /api/models` — **서버가 새로 만들 예정**)
- 목록 모양: `[{ "name": "qwen3.5:4b", "label": "qwen3.5 4B", "default": true }]`
- 모델이 하나뿐이면 **선택기를 숨기고 이름만** 표시해 주세요
- 모델을 못 받아오면(LLM 서버 꺼짐) ① 스위치 자체를 비활성으로 두고
  `지금은 AI 답변을 쓸 수 없습니다` 를 표시합니다

## 3. 답변 영역 — 추론 과정을 보여주기

### 3-1. 지금

질문을 보내면 **점 세 개**가 돌다가 답변이 한 번에 나타납니다. AI 답변은 5~30초가 걸리는데
그동안 무슨 일이 일어나는지 알 수 없습니다.

### 3-2. 요청

ChatGPT·Claude 처럼 **글자가 흘러나오는 모습**으로 만들어 주세요.

```
┌────────────────────────────────────────────────┐
│ ▾ 생각하는 중…                        12초      │  ← ① 추론 블록 (접고 펼 수 있음)
│ ┌──────────────────────────────────────────┐   │
│ │ 사용자가 묻는 것은 등록 절차의 순서입니다.   │   │     회색 작은 글씨
│ │ 발췌 [1] 에 네 단계가 나와 있고 …           │   │     한 글자씩 흘러나옴
│ │ ▌                                         │   │     ← 커서
│ └──────────────────────────────────────────┘   │
├────────────────────────────────────────────────┤
│ ✨ AI 정리 · 검수 전                             │  ← ② 답변 블록
│                                                │
│ API 는 등록 → TB 배포 → 테스트 → 운영 배포 네   │     본문 글씨
│ 단계를 차례로 거치며 ▌                           │     한 글자씩 흘러나옴
│                                                │
│ 📄 참고 자료                                    │  ← ③ 근거 자료 (답변이 끝난 뒤 나타남)
│ ┌──────────────┐ ┌──────────────┐             │
│ │ API 등록·배포 │ │ 운영 배포 관리 │             │
│ └──────────────┘ └──────────────┘             │
│                                                │
│ qwen3.5:4b · 14초 · 검수 전        [복사]       │  ← ④ 꼬리말
└────────────────────────────────────────────────┘
```

**① 추론 블록**

- `추론 과정 보기` 를 켰을 때만 나타납니다
- **답변보다 먼저** 나오고, 답변이 시작되면 **자동으로 접힙니다**
- 접힌 상태는 `▸ 생각하는 과정 (12초)` 한 줄. 누르면 다시 펼쳐집니다
- 글씨는 **본문보다 작고 흐리게**. 답변과 혼동되면 안 됩니다
- 진행 중에는 **경과 시간이 올라갑니다**

**② 답변 블록**

- 글자가 흘러나오는 동안 **끝에 커서**(▌)가 깜빡입니다
- 흘러나오는 중에도 **읽을 수 있어야** 합니다 — 화면이 덜컥거리며 밀리지 않게 해 주세요
- 다 나오면 커서가 사라집니다

**③ 근거 자료**

- 답변이 **끝난 뒤** 나타납니다. 중간에 끼어들면 읽는 흐름이 끊깁니다
- 왼쪽 서재의 **커버 카드와 같은 모양**을 작게 쓰면 좋겠습니다 — 같은 자료가 두 모습이면 안 됩니다
- AI가 **실제로 근거로 쓴 자료만** 나옵니다(서버가 걸러서 줍니다)

**④ 꼬리말**

- `모델 이름 · 걸린 시간 · 검수 전` + 복사 버튼
- **검수된 답변**(① 스위치 끔)일 때는 `✓ 담당자 검수 완료` 가 대신 들어갑니다.
  **이 둘은 절대 섞이면 안 됩니다** — 검수 전 답변에 검수 완료 표시가 붙으면 이 제품에서
  가장 하면 안 되는 혼동이 생깁니다

### 3-3. 중단

흘러나오는 중에는 전송 버튼이 **`중단`** 으로 바뀝니다. 누르면 그 자리에서 멈추고, 지금까지
나온 글자는 그대로 남습니다.

### 3-4. 서버가 주는 모양 (스트리밍)

지금은 JSON 한 번에 내려주지만, **SSE(Server-Sent Events)로 바꿀 예정**입니다. 퍼블은 아래
형태의 더미 이벤트를 흘려 넣어 동작을 보여 주시면 됩니다.

```
event: thinking   data: {"text": "사용자가 묻는 것은 "}
event: thinking   data: {"text": "등록 절차의 순서입니다."}
event: answer     data: {"text": "API 는 등록 → "}
event: answer     data: {"text": "TB 배포 → …"}
event: sources    data: {"docs": [{ "doc_id": "...", "title": "...", "chunk_count": 10 }]}
event: done       data: {"model": "qwen3.5:4b", "elapsed_ms": 14230}
```

## 4. 첫 화면

지금은 안내 세 줄뿐이라 **무엇을 할 수 있는 도구인지** 전달되지 않습니다.

```
┌──────────────────────────────────────────────┐
│                                              │
│        무엇이 궁금하신가요?                    │
│        사내 자료를 찾아 답해 드립니다           │
│                                              │
│   ┌────────────┐ ┌────────────┐              │
│   │ API 등록은  │ │ 운영 배포는  │   ← 자주 묻는 │
│   │ 어떻게 하나요│ │ 누가 승인하나요│     질문 카드 │
│   └────────────┘ └────────────┘              │
│   ┌────────────┐ ┌────────────┐              │
│   │ Path 는 어떻│ │ 권한 신청은  │              │
│   │ 게 적나요?   │ │ 어디서 하나요│              │
│   └────────────┘ └────────────┘              │
│                                              │
│   자료 25건 · 문답 30개를 보고 답합니다         │  ← 규모 표시
└──────────────────────────────────────────────┘
```

- **주제 칩이 아니라 질문 카드**로 바꿔 주세요. 주제(`등록·배포 절차`)보다 질문
  (`API 등록은 어떻게 하나요?`)이 바로 누르기 쉽습니다
- 질문은 서버가 줍니다(카테고리의 `questions`). **4~6개**를 보여주고 누르면 바로 전송됩니다
- 맨 아래 **규모 한 줄** — 이 도구가 무엇을 알고 있는지 숫자로 보여줍니다

## 5. 지켜 주셔야 하는 것

이식할 때 매번 문제가 됐던 것들입니다. **이번에는 처음부터 지켜 주시면** 저희가 산출물을
그대로 얹을 수 있습니다.

| | 내용 |
| --- | --- |
| **CDN 금지** | 폐쇄망에 배포합니다. 폰트·아이콘·라이브러리를 외부에서 불러오면 화면이 죽습니다 |
| **`data-dev-only` 금지** | 로컬 미리보기용 폴백 태그를 남기지 마세요. 저희 테스트가 잡아서 반려됩니다 |
| **조직·서비스 이름 금지** | `포에버소프트` 를 마크업에 직접 쓰지 마세요. `data-brand="{app_name}"` 속성을 쓰면 서버가 채웁니다 |
| **기존 id·class 유지** | `#chatInput` · `#chatSend` · `.chat_msg` 등 서버 배선이 붙은 이름은 그대로 두세요. 바꾸셔야 하면 `chat-mapping.md` 에 **옛 이름 → 새 이름** 을 적어 주세요 |
| **마크다운 렌더 자리** | 답변 본문은 저희가 마크다운을 그려 넣습니다. `.chat_md` 안쪽 스타일(목록·표·코드)을 꼭 잡아 주세요 |
| **접근성** | 선택기·스위치에 `aria-label`, 추론 블록에 `aria-expanded`, 흘러나오는 영역에 `aria-live="polite"` |

## 6. 우선순위

한 번에 다 받기 어려우시면 이 순서로 나눠 주셔도 됩니다.

| 순위 | 범위 | 이유 |
| --- | --- | --- |
| **1** | 3. 답변 영역 (추론·스트리밍) | 사용자가 가장 오래 보는 곳이고, 지금이 가장 어설픕니다 |
| **2** | 1. 왼쪽 서재 (앞표지) | 이 제품이 "자료를 가진 도구"임을 보여주는 자리입니다 |
| **3** | 2. 입력 영역 (세 가지 선택) | 동작은 지금도 되지만 고를 수가 없습니다 |
| **4** | 4. 첫 화면 | 위 셋이 끝나면 자연스럽게 정리됩니다 |
