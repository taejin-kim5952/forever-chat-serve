# 상용 전환 - DEV 에서 PRD 까지 4단계

API Link 에서는 계정 생성, 애플리케이션 생성, API 구독, 상용 전환이 모두 포털 안에서 이어집니다. 개발 환경(DEV)에서 테스트한 뒤 준비 상태를 확인하고 상용 환경(PRD)으로 전환합니다.

## 계정 생성부터 상용 전환까지 4단계

질문: 상용 전환 절차가 어떻게 되나요 / 운영까지 몇 단계인가요 / 처음부터 운영까지 순서 / 연동 흐름

1. **계정 생성** - KT 내부 개발자는 Entra ID(사내 Microsoft 계정), 외부 파트너 개발자는 LDAP 계정으로 시작합니다.
2. **애플리케이션 생성** - 연동 유형을 고른 뒤 단계별로 정보를 입력해 애플리케이션을 만듭니다.
3. **API 구독** - 필요한 API 를 구독합니다. 일반 API 는 자동 승인되고, 민감 파라미터가 포함된 API 는 관리자 승인 후 이용할 수 있습니다. DEV Key 로 개발 · 테스트를 합니다.
4. **상용 전환** - 전환 준비가 끝나면 운영 전환을 요청하고, 승인을 거쳐 PRD Key 가 자동으로 발급됩니다.

계정은 포털에서, 2 · 3 단계는 DEV 환경(개발 및 테스트)에서, 4 단계 이후는 PRD 환경(상용 운영)에서 이루어집니다.

## DEV 환경과 PRD 환경

질문: DEV 와 PRD 차이 / 개발 환경과 운영 환경 / 왜 환경을 나누나요 / DEV Key 와 PRD Key

API Link 는 DEV 와 PRD 를 분리 운영해 개발과 운영을 안전하게 구분합니다.

- **DEV (개발 · 테스트 환경)** - DEV Key 를 발급받고 DEV 호출 서버 IP 를 등록해 개발과 연동 테스트를 합니다.
- **PRD (상용 운영 환경)** - 상용 전환 후 PRD Key 가 자동으로 발급되고, 승인된 IP 에서만 운영 호출을 합니다.

환경마다 Key 와 IP 를 따로 두므로, 개발 중인 호출이 운영에 섞이지 않습니다.

## PRD 전환 준비 상태

질문: 운영 전환 조건 / PRD 전환하려면 무엇이 필요한가요 / 전환 준비 상태가 뭔가요 / 언제 운영 전환을 요청하나요

상용 전환은 **준비 상태를 확인한 뒤 한 번에** 요청합니다. 애플리케이션 화면에서 다음 세 항목의 완료 여부를 확인합니다.

- **API 승인** - 구독한 API 가 모두 승인되었는지 확인합니다. 민감 API 는 관리자 승인이 끝나야 합니다.
- **IP 승인** - 운영(PRD) 호출 서버 IP 가 등록되고 승인되었는지 확인합니다.
- **Self Testing** - DEV 환경에서 구독한 API 를 실제로 호출해 성공했는지 확인합니다.

세 항목이 모두 준비되면 운영 전환을 요청합니다. 요청한 뒤에는 PO 승인을 거쳐 PRD Key 가 자동 발급됩니다.

## Self Testing 이란

질문: Self Testing 이 뭔가요 / 상용 전환 전에 테스트를 해야 하나요 / 테스트는 어떻게 확인되나요 / Self Testing 완료 조건

**Self Testing** 은 상용 전환 전에 연동이 실제로 동작하는지 개발자가 직접 확인하는 단계입니다.

DEV 환경에서 등록한 서버가 DEV Key 로 구독한 API 를 호출하면, 포털이 그 호출 이력을 확인해 성공 여부를 보여 줍니다. 구독한 API 마다 성공한 호출이 확인되어야 Self Testing 이 완료되고, 그래야 PRD 전환 준비가 끝납니다.

## 상용 전환 후 PRD 운영

질문: 상용 전환하면 무엇이 바뀌나요 / PRD Key 는 언제 나오나요 / 운영 호출은 어떻게 하나요 / 운영 중에 API 를 추가하려면

상용 전환이 끝나면 **PRD Key 가 자동으로 발급**되고, 승인된 PRD IP 에서 운영 호출을 시작합니다. 별도의 Key 발급 신청 없이 포털에서 바로 PRD Key 를 확인합니다.

운영 중에 구독 API 나 IP 를 바꾸면 변경 내용을 운영에 반영하는 요청을 거칩니다. PRD Key 에는 만료일이 있어 만료가 다가오면 포털에서 연장을 신청합니다.
