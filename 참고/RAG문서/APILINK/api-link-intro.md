# API Link 포털 소개

kt API Link 는 KT 내부 및 제휴 파트너 개발자가 KT API 를 찾고, 구독하고, 상용 환경으로 전환하는 전 과정을 하나의 포털에서 처리하는 API 연동 포털입니다.

## API Link 는 어떤 서비스인가

질문: API Link 가 뭔가요 / API Link 포털은 어떤 서비스인가요 / API 연동 포털 소개 / API Link 로 무엇을 할 수 있나요

API Link 는 **KT API 연동을 위한 단일 포털**입니다. 개발자가 KT API 를 연동할 때 거치는 과정, 즉 필요한 API 를 찾고, 이용을 신청하고, 개발 환경에서 테스트한 뒤 상용 환경으로 옮기는 일을 한 포털 안에서 이어서 처리합니다.

포털이 다루는 일은 크게 네 가지입니다.

- API 탐색과 AI 가이드챗으로 필요한 API 를 찾습니다.
- 애플리케이션을 만들어 API 를 구독합니다.
- 호출 서버 IP 와 API Key 를 관리합니다.
- 개발(DEV) 환경에서 테스트를 마친 뒤 상용(PRD) 전환 승인을 받습니다.

## API Link 는 누가 이용하나

질문: 누가 쓰는 포털인가요 / 외부 파트너도 쓸 수 있나요 / KT 직원만 쓰나요 / 이용 대상

API Link 의 이용 대상은 두 부류의 개발자입니다.

- **KT 내부 개발자** - KT · KT DS 직원입니다. 사내 Microsoft 계정(Entra ID)으로 별도 가입 없이 이용합니다.
- **제휴 파트너 개발자** - KT 와 계약한 외부 파트너사의 개발자입니다. LDAP 계정으로 이용합니다.

두 부류 모두 같은 포털에서 KT API 를 찾고 연동합니다.

## API 연동에서 API Link 가 해결하는 문제

질문: API Link 를 왜 써야 하나요 / 기존 방식과 무엇이 다른가요 / API 연동이 번거로운 이유 / 포털을 쓰면 무엇이 편해지나요

API 연동에서 흔히 겪는 세 가지 어려움을 포털 기능으로 해결합니다.

- **필요한 API 를 찾기 어려움** - 규격서가 많아 원하는 API 와 파라미터를 확인하는 데 시간이 걸립니다. API Link 는 카테고리 탐색과 AI 가이드챗으로 질문 한 줄에 관련 API 와 규격서 원문 근거를 보여 줍니다.
- **Key · IP · 담당자 정보가 흩어져 있음** - 구독 API, 호출 서버 IP, 인증 Key, 멤버를 따로 관리해야 했습니다. API Link 는 이것들을 애플리케이션 하나로 묶어 관리합니다.
- **상용 전환 절차가 복잡함** - 개발 테스트 이후 운영 반영까지 승인과 발급 과정이 길었습니다. API Link 는 DEV → PRD 흐름을 포털 안에 두고, 전환 준비 상태를 확인한 뒤 PRD Key 까지 포털에서 받도록 합니다.

## API Link 의 세 가지 가치 - 찾기 · 관리 · 전환

질문: API Link 의 핵심 기능 / 찾기 관리 전환이 뭔가요 / API Link 의 장점 / 세 가지 가치

API Link 는 API 를 찾고, 관리하고, 상용으로 전환하는 과정을 한 곳에서 이어갑니다.

- **찾기 - 말로 찾는 API** - 카테고리 탐색과 AI 가이드챗으로 필요한 API 를 바로 확인하고, 규격 상세에서 요청 · 응답 파라미터를 확인합니다.
- **관리 - 팀 단위로 관리하는 API** - 멤버 · 구독 API · IP Whitelist · API Key 를 애플리케이션 하나로 통합해 팀이 함께 관리합니다.
- **전환 - DEV 에서 PRD 까지 한 흐름** - 계정 → 애플리케이션 → 구독 → 상용 전환의 네 단계를 개발 테스트부터 상용 전환 승인까지 포털 안에서 진행합니다.

## 숫자로 보는 API Link

질문: API 가 몇 개 있나요 / 검색할 수 있는 규격서 수 / 애플리케이션 종류가 몇 가지인가요 / 상용 전환은 몇 단계인가요

소개서 작성 시점 기준 수치입니다. 서비스 운영에 따라 달라질 수 있습니다.

- **1,729건** - AI 가이드챗과 API Explorer 에서 검색할 수 있는 API 규격서 수입니다.
- **3가지** - 애플리케이션 유형입니다. API · MCP · OAuth 애플리케이션이 있습니다.
- **4단계** - 상용 전환 단계입니다. 계정 → 앱 → 구독 → 상용 전환 순서입니다.
- **2개 환경** - DEV 와 PRD 환경을 분리 운영하며, Key 와 IP 도 환경별로 따로 둡니다.
