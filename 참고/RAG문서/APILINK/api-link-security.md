# 보안 - 믿고 쓰는 연동 환경

API Link 는 접근 인증, 호출 통제, 데이터 보호 세 단계로 연동 환경을 보호합니다.

## API Link 보안의 3단계 구조

질문: API Link 보안은 어떻게 되어 있나요 / 보안 구조 / 포털은 안전한가요 / 단계별 보호

API Link 는 접근부터 데이터까지 단계별로 보호합니다.

1. **접근 인증** - Entra ID SSO 와 2차 인증(OTP)으로 허가된 사용자만 포털에 접근합니다.
2. **호출 통제** - IP Whitelist, DEV · PRD Key 분리, 민감 API 승인으로 등록된 서버와 승인된 API 만 호출합니다.
3. **데이터 보호** - 작성자 · 이메일 정보를 마스킹해 화면에 노출되는 개인정보를 최소화합니다.

## 접근 인증 - Entra ID SSO 와 2차 인증

질문: KT 직원은 어떻게 로그인하나요 / Entra ID SSO 가 뭔가요 / 2차 인증은 언제 하나요 / OTP 인증 / 외부 파트너 로그인

- **Entra ID SSO** - KT · KT DS 직원은 사내 Microsoft 계정으로 로그인합니다. 별도 가입 없이 사내 계정으로 포털에 들어오며, 로그인하면 직원 권한이 자동으로 부여됩니다.
- **2차 인증(OTP)** - 아이디 · 비밀번호로 로그인하는 계정은 휴대폰(또는 이메일)으로 받은 6자리 인증번호로 한 번 더 확인합니다.
- **LDAP** - 외부 파트너 개발자는 KT 가 발급한 LDAP 계정으로 로그인합니다. LDAP 로그인은 협력사 · 제휴사 계정 전용입니다.

## 호출 통제 - IP Whitelist · Key 분리 · 민감 API 승인

질문: 아무 서버에서나 호출할 수 있나요 / IP Whitelist 가 왜 필요한가요 / Key 를 왜 나누나요 / 민감 API 승인이 뭔가요

등록된 서버와 승인된 API 만 호출하도록 세 가지로 통제합니다.

- **IP Whitelist** - 환경별로 호출 서버 IP 를 등록하고 승인합니다. 등록된 IP 가 아닌 곳에서는 API 를 호출할 수 없습니다.
- **Key 분리** - DEV Key 와 PRD Key 를 분리 발급하고 만료를 관리합니다. 개발과 운영의 인증 정보가 섞이지 않습니다.
- **민감 API 승인** - 민감 파라미터가 포함된 API 는 관리자가 승인한 뒤에만 이용할 수 있습니다.

## 데이터 보호 - 개인정보 마스킹

질문: 개인정보는 어떻게 보호되나요 / 이름이나 이메일이 가려져 보여요 / 마스킹이 뭔가요 / 화면에 개인정보가 나오나요

포털은 화면에 노출되는 개인정보를 최소화합니다. 작성자 이름과 이메일 같은 정보는 일부만 보이고 나머지는 '*' 로 가려 표시합니다.

예를 들어 이메일은 앞 몇 글자만 보이고 나머지는 '***@****' 처럼 가려집니다. 다른 사용자의 개인정보가 화면에 그대로 드러나지 않도록 하기 위한 것입니다.
