# 데이터 모델 · 인터페이스 · 아키텍처

이 문서는 어떤 데이터를 어떻게 담고, 외부 시스템과 어떤 전문을 주고받으며, 전체가 어떤
계층으로 나뉘는지를 다룹니다.

## 엔티티 11종

질문: 데이터 모델이 어떻게 되나요 / 엔티티가 몇 개인가요 / ERD 설명 / 어떤 테이블이 있나요

개념 ERD 는 엔티티 11종으로 이루어집니다.

**서비스 · API 그룹 · API 버전 그룹 · API · 권한 · 사용자 · 파라미터 · Handler 설정 ·
테스트 이력 · 배포 요청 · 배포 이력**

서비스는 API 그룹을, API 그룹은 API 버전 그룹을, API 버전 그룹은 API 를 각각 1:N 으로
가집니다. 파라미터는 입력·Query·출력으로 나뉘고, Handler 설정은 키를 최대 18개까지 둡니다.

## API 가 기본 단위인 이유

질문: API 단위가 뭔가요 / API ID 는 유일한가요 / 진행 단계는 어디에 기록되나요

**API 가 등록·배포·테스트의 기본 단위**입니다. API ID 는 전체에서 유일하며, 진행 단계와
승인 대기·반려 여부를 함께 관리합니다.

## 인터페이스 네 가지

질문: 인터페이스가 어떻게 구성되나요 / 어떤 방식으로 연동하나요 / REST 인가요

| 대상 | 쓰임 | 방식 |
| --- | --- | --- |
| 내부 API | 화면 ↔ API Manager 서버 | REST / JSON |
| Microsoft Entra ID | 로그인 콜백 · 로그아웃 | SSO (OIDC) |
| BEAST 게이트웨이 | 배포 · 등록본 조회 · 롤백 | POST / JSON |
| TB · 운영 시스템 | 테스트 실행(API 정의 기준) | HTTP 실호출 |

## 인터페이스 설계 원칙 네 가지

질문: 설계 원칙이 뭔가요 / URI 를 어떻게 정하나요 / 다건 처리는 어떻게 하나요

1. URI 는 화면이 아니라 **자원 단위**로 구성합니다.
2. 목록은 조건·페이지 공통 파라미터를 쓰고, **현황 집계는 별도 API** 로 둡니다.
3. **배포와 승인은 배열로 다건 처리**합니다.
4. **연동 전문은 서버가 생성**하고 화면은 조회·수정만 합니다.

## BEAST 전문

질문: BEAST 로 어떻게 배포하나요 / 배포 주소가 뭔가요 / 롤백은 어떻게 되나요 / 전문 필드

| 동작 | 방식 | 주소 |
| --- | --- | --- |
| 배포 | POST | `{포털}/apilink/v1/api/apiDply` |
| 등록본 조회 | GET | `{포털}/apilink/v1/api/getApiDplyById?apiId=…` |
| 롤백 | POST | `apiDply` — 과거 등록본을 다시 보냅니다 |

배포 전문의 주요 필드는 `sysId` · `apiId` · `ifNo` · `ver / meth` · `in / out` ·
`reqHndlr` · `resHndlr` · `timeOut` · `hndlrOptn` 입니다.

## 테스트 실호출에서 모으는 것

질문: 테스트하면 뭐가 기록되나요 / 소요 시간도 보이나요 / 테스트 이력

`TB_KTC` 와 `TB_AZURE` 중 하나를 골라 실제로 호출하고, **상태 코드 · 응답 · 소요 시간 ·
크기**를 모읍니다. 실행할 때마다 전문 이력이 남습니다.

## 시스템 아키텍처 4계층

질문: 아키텍처가 어떻게 되나요 / 계층 구조 / 클라우드 네이티브 구성

클라우드 네이티브 기반의 4계층 구조입니다.

1. **화면 API 계층** — REST 엔드포인트, 요청 검증, 응답 변환
2. **업무 서비스 계층** — 생애주기·승인·권한 규칙과 상태 전이
3. **연동 어댑터 계층** — BEAST·Entra ID 어댑터, 테스트 실행기
4. **데이터 접근 계층** — 엔티티 11종 조회·저장

영역은 Public Zone(L4 · API Gateway Cluster)과 Private Zone(FE · BE · Data/Cache ·
Event Streaming)으로 나뉩니다.

## 인가가 걸리는 세 지점

질문: 권한 검사는 어디서 하나요 / 메뉴가 사람마다 다른가요 / 승인은 아무나 할 수 있나요

인증은 Entra ID SSO 와 서버 세션으로 하며, 세션이 만료되면 메인으로 이동합니다. 인가는 세
곳에서 걸립니다.

- **메뉴 인가** — 역할별로 메뉴를 노출하며, 운영 배포 관리는 승인자만 봅니다.
- **데이터 인가** — 서비스별 권한 그룹으로 조회·등록 범위를 제한합니다.
- **처리 인가** — 승인과 배포는 승인자가, 등록과 요청은 권한 보유자가 합니다.

## 로그 세 가지

질문: 로그는 뭐가 남나요 / 감사 로그에 뭐가 들어가나요 / 연동 실패는 어디서 보나요

- **감사 로그** — 등록·수정·삭제, 배포·승인, 권한 처리. 행위자·일시·변경 전후를 남깁니다.
- **연동 로그** — BEAST 송수신 전문과 테스트 요청·응답. 이력에 함께 보관합니다.
- **오류 로그** — 연동 실패 사유를 이력 항목에 노출합니다.

**롤백을 위해 게이트웨이 전문 원문을 반드시 보관합니다.**
