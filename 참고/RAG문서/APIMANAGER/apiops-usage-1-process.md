# API 등록 · 배포 절차

API 는 등록 → TB 배포 → 테스트 → 운영 배포 네 단계를 차례로 거쳐 사용자에게 제공됩니다.
등록자 · 승인자 · 관리자가 단계를 나누어 진행합니다.

## 전체 흐름과 역할

질문: 전체 절차가 어떻게 되나요 / API 등록부터 운영 배포까지 순서 / 단계가 몇 개인가요 / 누가 승인하나요 / 승인자와 관리자가 뭐가 다른가요

API 는 **등록 → TB 배포 → 테스트 → 운영 배포** 네 단계를 차례로 거칩니다. 앞 단계를 마쳐야 다음 단계로 갈 수 있습니다.

역할은 셋입니다.

- **등록자** - 등록, TB 배포, 테스트, 운영 배포 요청을 합니다. 서비스 권한이 있으면 됩니다.
- **승인자** - '운영 배포 관리 > 운영 배포 요청' 에서 요청을 승인하거나 반려합니다.
- **관리자** - '운영 배포 관리 > 운영 배포 대기' 에서 승인된 API 를 운영 게이트웨이에 배포합니다.

승인자 · 관리자는 설정으로 정해집니다. 메뉴가 보이지 않으면 운영 담당자에게 역할 등록을 요청합니다.

## 등록 시작과 규격 넣는 방법 3가지

질문: API 등록은 어떻게 시작하나요 / 등록 화면이 어디 있나요 / 규격은 어떻게 넣나요 / 템플릿 규격서 직접 입력 차이 / 어떤 방법으로 파라미터를 넣어야 하나요

'API 그룹 현황' 에서 API 를 넣을 그룹의 '신규 API 등록' 버튼을 선택합니다. 그룹이 없으면 '신규 그룹 등록' 버튼으로 그룹을 먼저 만듭니다.

규격(Method · Path · 파라미터)은 세 가지 방법 중 하나로 넣습니다. 섞어 써도 됩니다.

1. **템플릿 불러오기** - 규격서가 없고 공통 규격으로 새로 만들 때. '템플릿 불러오기' 버튼으로 템플릿을 고르면 공통 파라미터가 한 번에 채워집니다. 처음 등록하는 API 는 'API Link Gateway 표준템플릿' 을 권장합니다.
2. **규격서로 채우기** - 포털 규격 문서(OAS) 파일이 이미 있을 때. '규격서로 채우기' 버튼으로 문서를 붙여넣거나 파일로 고르면 이름 · Path · Method · 파라미터 · 연동 설정까지 채워집니다. 읽기만 하므로 '저장' 버튼은 따로 선택합니다.
3. **직접 넣기** - 규격서도 템플릿도 없거나 채워진 규격을 손볼 때. '입력 파라미터 설계' 버튼으로 설계 팝업을 엽니다.

## 등록 저장과 등록 완료 확인

질문: 설계 팝업에서 확인 누르면 저장되나요 / 저장은 어디서 하나요 / 등록 완료는 어떻게 확인하나요 / 저장하면 어디로 가나요

설계 팝업의 '확인' 버튼은 설계 내용을 등록 화면으로 가져올 뿐 저장이 아닙니다. 등록 화면 아래 '저장' 버튼까지 선택해야 저장됩니다. '확인' 만 누르고 화면을 벗어나면 설계한 내용이 사라집니다.

'저장' 버튼을 선택하고 확인 창에서 '확인' 을 선택하면 그룹의 API 목록으로 돌아가며, 새 API 가 '등록 완료' 상태로 표시됩니다.
목록에서 API 명을 선택하면 상세 화면이 열리고, JOB 칸 오른쪽에 'TB배포' 버튼이 표시됩니다. 이 버튼이 다음 단계로 가는 길입니다.

## TB 배포 방법

질문: TB 배포는 어떻게 하나요 / TB 배포가 한 대만 성공했어요 / TB 배포는 승인이 필요한가요 / 전송 전문이 안 만들어져요 / TB_KTC TB_AZURE 둘 다 해야 하나요

API 상세의 'TB배포' 버튼을 선택합니다. '전송 전문' 에 등록 정보로 만들어진 게이트웨이 배포 전문이 표시됩니다.
전문이 만들어지지 않고 오류가 표시되면 API 를 수정해 연동 설정(Handler 등)을 채운 뒤 '전문 다시 만들기' 버튼을 선택합니다.

화면 아래 'TB_KTC 배포' 버튼과 'TB_AZURE 배포' 버튼을 차례로 선택하고 확인 창에서 '확인' 을 선택합니다.
**두 대 모두 '배포 이력' 에 성공으로 기록되어야** TB 배포 단계가 완료되고 '테스트 실행' 버튼이 표시됩니다. 한 대만 성공하면 테스트로 넘어갈 수 없습니다.
TB 배포는 승인 없이 몇 번이든 다시 할 수 있습니다.

## 배포 전 전문 비교

질문: 전문 비교는 뭔가요 / 배포 전에 뭘 확인해야 하나요 / 등록본이 뭔가요 / 보낼 전문과 n곳 다름이 뭔가요 / G/W에 있는 값과 비교하려면

TB 배포와 운영 배포 요청 전에는 **'전문 비교' 버튼으로 지금 보낼 전문과 이미 API Link G/W 에 들어가 있는 정보(등록본)를 반드시 비교합니다.**
화면 위쪽 'TB_KTC 등록본' · 'TB_AZURE 등록본' 줄에 G/W 에 등록돼 있는지와 '보낼 전문과 n곳 다름' 이 표시됩니다.
'전문 비교' 팝업은 왼쪽에 보낼 전문, 오른쪽에 G/W 등록본 원문을 나란히 두고 변경 · 추가 · 삭제된 곳을 색으로 표시합니다.

달라진 곳이 의도한 수정인지 확인한 뒤에 배포합니다. 의도하지 않은 차이가 있으면 배포로 덮어쓰기 전에 API Link G/W 운영팀과 확인합니다. 배포하면 G/W 의 등록본이 보낼 전문으로 바뀝니다.

## 테스트 실행과 인증키

질문: 테스트는 어떻게 하나요 / 테스트 실행 방법 / 연동 테스트가 어디서 호출되나요 / 테스트할 때 인증키는 어떻게 하나요 / Authorization 칸이 막혀 있어요

'테스트 실행' 버튼을 선택하면 테스트 화면이 열립니다. '요청' 칸에는 파라미터에 넣어 둔 예시 값으로 만든 요청이 채워져 있으며 값을 고쳐서 실행할 수 있습니다.

**연동 테스트는 API Manager 서버가 API Link G/W 를 호출하는 방식으로 진행됩니다.** 브라우저가 직접 G/W 를 부르지 않으므로 내 PC 의 네트워크나 인증 설정과는 무관합니다.
**인증키(Authorization 헤더)는 API Manager 서버에 설정된 값으로 보냅니다.** 모든 API 의 테스트에 공통으로 쓰도록 미리 발급받아 서버에 둔 키이며, 요청 칸의 'Authorization' 은 입력할 수 없게 막혀 있고 '서버에 설정된 키로 보냅니다' 로만 표시됩니다.

'요청' 칸의 '테스트 실행' 버튼을 선택하면 '응답' 칸에 상태코드 · 소요 시간 · 본문이 표시되고 '검증' 탭에서 규격과 맞는지 확인합니다.
응답을 확인했으면 화면 아래 '테스트 완료' 버튼을 선택합니다. 진행 단계가 테스트로 바뀌고 '운영 배포 요청' 버튼이 표시됩니다.

## 운영 배포 요청 방법 (등록자)

질문: 운영 배포 요청은 어떻게 하나요 / 운영 배포 신청 방법 / 요청하면 수정이 안 되나요 / 운영 배포 요청 중 수정 / 요청 취소

'운영 배포 요청' 버튼을 선택하면 운영 배포 화면이 열립니다. '전송 전문' 을 확인하고, '전문 비교' 로 운영 G/W 등록본(PRD_KTC · PRD_AZURE)과 반드시 비교한 뒤, 화면 아래 '운영 배포 요청' 버튼을 선택하고 확인 창에서 '확인' 을 선택합니다.

요청하면 승인자에게 전달되며, **승인이 끝날 때까지 API 를 수정할 수 없습니다.** 수정이 필요하면 반려를 받거나 요청을 취소한 뒤 고치고, TB 배포부터 다시 진행합니다.

## 운영 배포 요청 승인 · 반려 (승인자)

질문: 승인은 어떻게 하나요 / 운영 배포 요청 승인 방법 / 반려하면 어떻게 되나요 / 승인 대기가 어디 있나요 / 요청 전문을 어디서 보나요

승인자는 '운영 배포 관리 > 운영 배포 요청' 에서 요청 목록을 봅니다. '전문 보기' 버튼으로 등록자가 보낸 운영 배포 전문을 확인하고, '테스트' 열에서 통과한 검증 수를 확인합니다.

요청 건을 체크하고 '승인' 버튼 또는 '반려' 버튼을 선택한 뒤 확인 창에서 '확인' 을 선택합니다. 여러 건을 체크하면 한 번에 처리됩니다.
승인된 API 는 관리자의 '운영 배포 대기' 로 넘어갑니다. 반려하면 등록자에게 반려 상태가 표시되고, 등록자는 수정 후 TB 배포부터 다시 진행합니다.

## 운영 배포 실행 (관리자)

질문: 운영 배포는 누가 하나요 / 운영 배포 대기에서 뭘 하나요 / PRD_KTC PRD_AZURE 배포 / 운영 배포가 끝났는지 어떻게 아나요 / 승인 취소

관리자는 '운영 배포 관리 > 운영 배포 대기' 에서 승인된 API 를 확인합니다.
배포할 건을 체크하고 'PRD_KTC 배포' 버튼을 선택한 뒤 확인 창에서 '확인' 을 선택합니다. 목록이 다시 그려지면 같은 건을 다시 체크하고 'PRD_AZURE 배포' 버튼으로 한 번 더 배포합니다.
**두 대 모두 성공해야 완료**되어 목록에서 빠지고 '운영 배포 이력' 에 '배포 완료' 로 기록됩니다. 배포하지 않을 건은 '승인 취소' 로 요청 상태로 되돌릴 수 있습니다.

등록자의 API 상세에서는 네 단계가 모두 채워지고 '운영 배포 완료' 로 표시됩니다.
