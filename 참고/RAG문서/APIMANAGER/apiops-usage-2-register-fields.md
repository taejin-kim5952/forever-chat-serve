# API 등록 화면 입력 항목

API 등록 화면은 기본 정보 · 연동 설정 · 파라미터 세 묶음으로 구성됩니다.
항목마다 무엇을 어떻게 채우는지 정리한 내용입니다.

## API 이름 · 설명 · 영향도

질문: API 이름은 몇 자까지인가요 / 설명에 뭘 적나요 / 영향도가 뭔가요 / 영향도에 뭘 써야 하나요 / 영향도 비워도 되나요

- **API 이름**(최대 100자) - 규격서와 목록에 표시되는 이름입니다.
- **설명**(최대 500자) - 이 API 가 무엇을 하는지 한두 문장으로 적습니다.
- **영향도**(최대 500자) - 이 API 가 중단되거나 장애가 났을 때 이 API 를 쓰는 서비스가 받는 영향입니다. "수정하면 어디에 영향이 있는지" 가 아니라 **"멈추면 어떤 서비스의 어떤 기능이 안 되는지"** 를 적습니다. 예: '중단 시 MYKT 앱의 주문 조회 화면이 열리지 않음'. 장애가 났을 때 영향 범위를 바로 알기 위한 정보이므로 운영에 올리는 API 는 비워 두지 않습니다.

## API ID - 신규 API ID와 중복검사

질문: API ID는 어떻게 받나요 / 신규 API ID 버튼 / 중복검사는 왜 하나요 / API ID 규칙 / API ID 바꿀 수 있나요

**'신규 API ID' 버튼**을 선택하면 이 그룹이 속한 서비스에 배정된 번호 구간 안에서 다음 번호가 OIF_00000 모양으로 채워집니다. 번호는 서비스별로 이어지므로 임의로 만들지 않고 이 버튼으로 받습니다. 서비스의 구간이 모두 쓰였으면 발급되지 않고 안내가 표시되며, 이때는 운영 담당자에게 문의합니다.

**'중복검사' 버튼**을 선택하면 시스템 전체에서 같은 ID 가 있는지 확인해 '사용 가능한 API ID 입니다.' 또는 '이미 사용 중인 API ID 입니다.' 로 표시됩니다.
API ID 는 영문 · 숫자 · 밑줄( _ ) · 점 · 하이픈만 쓸 수 있고 한글과 공백은 쓸 수 없습니다(최대 50자). **등록 후에는 바꿀 수 없으므로** 저장 전에 반드시 확인합니다. 중복이면 '신규 API ID' 버튼으로 다시 받습니다.

## Path 생성 규칙

질문: Path는 어떻게 정하나요 / Path 자동 생성 규칙 / Path가 자동으로 채워져요 / Path 중복 / 호스트를 Path에 넣어야 하나요

Path 는 API 이름을 입력하면 **/서비스ID/버전그룹/API이름** 모양으로 자동 제안됩니다. 예: 서비스 kos · 버전 그룹 v1.0 · API 이름 guide_sampleOrderRetrieve → '/kos/v1.0/guide_sampleOrderRetrieve'.
API 이름의 공백은 밑줄( _ )로 바뀌고, API 버전 그룹을 바꾸면 Path 의 버전 마디도 함께 바뀝니다. Path 를 한 번이라도 직접 고치면 그 뒤로는 자동으로 바꾸지 않습니다.

지켜야 할 규칙(최대 200자)

- '/' 로 시작해야 합니다.
- 같은 그룹 안에서 Method 와 Path 의 조합이 겹치면 안 됩니다. 겹치면 저장할 때 '이미 등록된 Method / Path 입니다.' 로 막힙니다.
- 버전 마디(/서비스ID/v1.0/…)를 유지합니다. 버전 마디가 있어야 운영 배포 뒤 '버전 올리기' 로 다음 버전을 만들 수 있습니다.
- 그룹의 호스트 · 기본경로는 Path 앞에 자동으로 붙으므로 Path 에는 넣지 않습니다. 실제 호출 주소는 '호스트 + 기본경로 + Path' 입니다.

## 더보기 - 노출여부 · API 구분

질문: API 노출여부가 뭔가요 / 노출과 숨김 차이 / API 구분은 뭘 골라야 하나요 / Private을 선택해야 하나요 / Public Private Internal 차이

기본 정보 아래 '더보기' 를 펼치면 나오는 항목입니다. 노출여부와 API 구분은 반드시 확인합니다.

- **권한그룹** - 이 API 를 등록하고 배포하는 작업자 그룹입니다. 서비스를 고르면 내 권한그룹이 채워집니다(기본 '개발자그룹').
- **API 노출여부** - **API 포털에 배포할지**를 정합니다. '노출' 이면 운영 배포 뒤 포털에서 사용자가 이 API 를 볼 수 있고, '숨김' 이면 포털에 나오지 않습니다. 검증이 끝나기 전이거나 내부용 API 는 '숨김' 으로 둡니다.
- **가이드 구분** - 포털 가이드의 방식(REST · SOAP)입니다. 해당 없으면 '선택 안 함' 으로 둡니다.
- **sandbox 적용여부** - 포털 sandbox 적용 여부입니다.
- **API 구분** - **API Link Gateway 를 통해 사용자에게 제공하는 API 는 'Private' 을 선택합니다.** 'Private' 을 고르면 연동 설정에 Handler · Provider 칸이 나타나며, Handler 를 지정해야 TB 배포 전문이 만들어집니다. 'Private' 이 아니면 Handler 를 지정할 수 없어 게이트웨이 배포 전문을 만들지 못합니다.

## 연동 설정 - 시스템 주소와 타임아웃

질문: 연동 설정이 뭔가요 / TB 시스템 주소에 뭘 넣나요 / 운영 시스템 주소 / Enabler Resource 주소 / 타임아웃은 뭔가요

'연동 설정' 은 API Link G/W 의 연동을 정하는 곳입니다. 사용자가 Path 로 API 를 호출하면 G/W 가 여기에 적은 주소(Enabler 의 Resource)를 호출해 받은 결과를 사용자에게 돌려줍니다.

- **TB 시스템 주소 · 운영 시스템 주소** - G/W 가 실제로 가져오는 Enabler Resource 의 주소입니다. 예를 들어 KOS 의 API 라면, 사용자가 '/kos/v1.0/…' 를 호출했을 때 G/W 가 대신 호출할 KOS 시스템의 Resource 주소입니다. TB 주소는 TB 배포 · 테스트 단계에서, 운영 주소는 운영 배포 뒤 G/W 가 각각 호출합니다. 둘 다 필수이며 각각 최대 200자입니다. Enabler 담당자에게 받은 주소를 그대로 적습니다.
- **Endpoint Method** - G/W 가 Resource 를 호출할 때 쓰는 Method 입니다. 기본은 API 의 Method 와 같고, Resource 쪽 Method 가 다르면 바꿉니다.
- **타임아웃(ms)** - G/W 가 Resource 를 연동해 결과를 가져올 때 기다리는 시간(밀리초)입니다. 이 시간 안에 응답이 없으면 사용자에게 오류로 돌아갑니다.

## 연동 설정 - Handler와 규격

질문: Handler는 뭘 고르나요 / Handler 입력값은 뭔가요 / COMMON과 ANYCOMMON 차이 / 서비스만의 규격이 있으면 / Handler 협의

Handler 는 Enabler 종류에 맞춰 고릅니다(예: KOS 는 'KOS'). KOS · KOSMOS · SCAP · CAPRI · SB 는 해당 Enabler 전용 Handler 입니다. Handler 가 없으면 TB 배포 단계에서 전송 전문을 만들지 못합니다.

**Handler 별 입력값은 사용자가 API 를 호출했을 때 API Link G/W 의 Handler 단에서 처리하는 내용을 정의한 값입니다.** 어떤 Handler 를 쓰고 어떤 값을 넣을지는 등록 전에 API Link G/W 운영팀과 협의해 정하며, 임의로 채우지 않습니다.

입력 파라미터와 출력 파라미터는 Handler 구분에 따라 약간씩 다릅니다. **표준 규격은 'COMMON'** 이며, 서비스만의 특정 규격이 있는 경우 **'ANYCOMMON'** 을 선택해 진행합니다. 다만 ANYCOMMON 은 사전에 API Link G/W 운영팀과 협의한 규격이 있어야 합니다.

TB G/W 시스템 · 상용 G/W 시스템은 그룹이 BEAST 를 쓸 때만 보이며 '선택' 버튼으로 고릅니다.

## 파라미터 설계 팝업

질문: 입력 파라미터 설계는 어떻게 하나요 / 트리 편집과 규격서 편집 / 규격서를 고치면 폼도 바뀌나요 / 파라미터 구분 다섯 가지 / YAML JSON 직접 입력

'파라미터' 영역의 '입력 파라미터 설계' 버튼을 선택하면 설계 팝업이 열립니다.
왼쪽 '트리 편집' 에서 파라미터를 한 줄씩 추가하거나, 오른쪽 '규격서 편집' 에 YAML · JSON 을 직접 적습니다. **오른쪽 규격서를 고치면 왼쪽 입력 폼이, 왼쪽을 고치면 오른쪽 규격서가 실시간으로 함께 바뀝니다.**
입력 Header · 입력 Body · 출력 Header · 출력 Body · Query 다섯 구분을 각각 설계합니다.

팝업의 '확인' 버튼은 저장이 아닙니다. 등록 화면 아래 '저장' 버튼까지 선택해야 저장됩니다.

## 파라미터 상세정보 - 입력란

질문: 파라미터 예시에 뭘 넣나요 / 예시에 개인정보 넣어도 되나요 / 고정값이 뭔가요 / 매핑키가 뭔가요 / 민감정보 분류

트리 편집에서 파라미터 줄의 '상세정보'(+) 버튼을 선택하면 펼쳐집니다.

- **설명** - 이 파라미터가 무엇인지. 규격서에 그대로 표시됩니다.
- **예시** - 샘플 값입니다. API Link 포털의 규격서에 표시되고, 테스트 단계에서 요청 전문이 이 값으로 자동 생성됩니다. **실제 개인정보는 적지 않습니다.**
- **민감정보 분류** - 민감정보이면 분류를 고릅니다. 민감정보 파라미터가 있는 API 는 사용자가 포털에서 이용을 신청할 때 승인 대상이 되며, 승인을 받은 뒤에야 키를 발급받을 수 있습니다.
- **고정값** - 사용자가 입력하지 않아도 G/W 가 시스템 내부에서 만들어 뒤 서비스 API 를 호출할 때 전달하는 값입니다.
- **매핑키** - G/W 가 이 파라미터를 특정 키 값으로 치환해 쓸 때 적습니다. 사전에 API Link G/W 운영팀과 협의한 경우에만 사용합니다.
- **암호화방식** - 서비스가 값을 암호화해서 사용자에게 전달하는 경우 그 방식을 고릅니다.
- **비고** - 그 밖에 필요한 정보를 적습니다.

## 파라미터 상세정보 - 체크박스

질문: 미전송이 뭔가요 / 숨김 체크는 언제 하나요 / sandbox 전용 / URL Decode URL Encode / 업로드 대상

해당하는 경우에만 켭니다.

- **미전송** - 사용자나 뒤 서비스로 DATA 값이 전달되지 않는 파라미터입니다.
- **숨김** - 규격서에 노출하지 않고, 내부에서 개발자 · 관리자만 확인하려고 등록하는 파라미터입니다.
- **sandbox 전용** - 포털의 실제 사용자가 아니라 sandbox 테스트용으로 데이터 세팅이 필요한 파라미터입니다.
- **URL Decode · URL Encode** - 파라미터의 DATA 값에 URL 디코딩 또는 인코딩이 필요한 경우 켭니다.
- **업로드 대상** - 첨부파일처럼 업로드되는 바이너리 정보 파라미터입니다.
- **마스킹** - 개인정보라서 사용자에게 마스킹해서 전달해야 하는 파라미터입니다.
