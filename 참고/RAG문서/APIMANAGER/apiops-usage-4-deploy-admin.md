# 운영 배포 관리 화면

운영 배포 관리는 승인자가 운영 배포 요청을 승인하고, 관리자가 승인된 API 를 운영 게이트웨이에 배포하는 메뉴입니다.
운영 배포 요청 · 운영 배포 대기 · 운영 배포 이력 세 화면으로 구성됩니다.

## 운영 배포 관리 메뉴 구성과 역할

질문: 운영 배포 관리 메뉴가 안 보여요 / 승인자와 관리자 차이 / 운영 배포 요청 대기 이력 차이 / 누가 승인하고 누가 배포하나요

운영 배포 관리는 승인자와 관리자가 쓰는 메뉴입니다.

- '운영 배포 요청' - 승인자가 등록자의 요청을 승인하거나 반려합니다.
- '운영 배포 대기' - 관리자가 승인된 API 를 운영에 배포합니다.
- '운영 배포 이력' - 배포가 끝났거나 반려된 요청을 봅니다. 승인자 · 관리자 모두 볼 수 있습니다.

승인자 · 관리자 역할은 설정으로 정해집니다. 메뉴가 보이지 않으면 운영 담당자에게 역할 등록을 요청합니다.

## 운영 배포 요청 승인 · 반려

질문: 운영 배포 요청은 어떻게 승인하나요 / 반려는 어떻게 하나요 / 전문 보기 / 여러 건 한 번에 승인 / 테스트 열이 뭔가요

좌측 메뉴에서 '운영 배포 관리' 를 선택하면 '운영 배포 요청' 화면이 열립니다. 위쪽 현황에 승인 대기 · 3일 이상 대기 · 오늘 승인 · 오늘 반려 건수가, 아래 목록에 승인을 기다리는 요청이 표시됩니다. '테스트' 열은 등록자가 테스트 단계에서 통과한 검증 수입니다.

'전문 보기' 버튼을 선택하면 등록자가 요청한 운영 배포 전문이 팝업으로 표시됩니다. Path · Handler · 타임아웃 등을 확인한 뒤 '닫기' 버튼을 선택합니다.
목록에서 요청 건을 체크하고 '승인' 버튼 또는 '반려' 버튼을 선택한 뒤 확인 창에서 '확인' 을 선택합니다. 여러 건을 체크하면 한 번에 처리됩니다. 체크한 것은 지금 보이는 쪽에서만 유효합니다.

승인한 건은 목록에서 빠지고 관리자의 '운영 배포 대기' 로 넘어갑니다. 반려한 건은 등록자에게 반려 상태로 표시되고, 등록자는 수정 후 TB 배포부터 다시 진행합니다.

## 운영 배포 대기에서 배포

질문: 운영 배포는 어떻게 하나요 / PRD_KTC PRD_AZURE 배포 순서 / 배포 실패가 떠요 / 승인 취소는 뭔가요 / 한 대만 배포됐어요

좌측 메뉴 '운영 배포 관리' 아래 '운영 배포 대기' 를 선택합니다. 승인이 끝나 배포를 기다리는 API 가 표시되며, 운영 배포가 실패한 건은 '배포 실패' 가 함께 표시됩니다.

배포할 건을 체크하고 'PRD_KTC 배포' 버튼과 'PRD_AZURE 배포' 버튼을 차례로 선택한 뒤 확인 창에서 '확인' 을 선택합니다. 한 번 배포하면 목록이 다시 그려지므로 같은 건을 다시 체크하고 다음 게이트웨이에 배포합니다.
**두 대 모두 성공해야 배포가 완료**되어 목록에서 빠집니다. 한 대만 성공하면 대기 목록에 '배포 실패' 로 남습니다. 배포하지 않을 건은 '승인 취소' 로 요청 상태로 되돌릴 수 있습니다.

배포가 끝난 API 는 '운영 배포 이력' 에 '배포 완료' 로 기록되고, API 상세의 진행 상태도 '운영 배포 완료' 로 바뀝니다.

## 운영 배포 이력

질문: 운영 배포 이력은 어디서 보나요 / 예전에 보낸 전문을 다시 볼 수 있나요 / 반려된 요청 확인 / 배포 완료 건수

좌측 메뉴 '운영 배포 관리' 아래 '운영 배포 이력' 을 선택합니다. 배포가 끝났거나 반려된 요청이 처리일 · 결과와 함께 표시됩니다.
서비스 · 결과로 추려 볼 수 있고, '전문 보기' 버튼으로 그때 보낸 전문을 다시 확인할 수 있습니다.
