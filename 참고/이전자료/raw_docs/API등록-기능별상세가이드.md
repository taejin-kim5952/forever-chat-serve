# API 등록 - 기능별 상세 가이드

이 문서는 KT 사내 시스템의 개발자가 자신이 담당하는 시스템의 API를 API Link에 등록·배포하기
위한 가이드입니다. API Link는 KT 내부에서만 이용할 수 있는 사이트입니다.

API 등록 메뉴에서 만나게 되는 기능을 화면 순서대로 하나씩 설명합니다.
API 등록은 **`/apidev/api/spcreg/mvSpcReg.do`** (API 그룹 등록) 화면에서 시작하며,
이 화면의 첫 번째 입력 항목이 **서비스**입니다.

---

## 1. 서비스

### 서비스란

**서비스는 API를 등록할 때의 최상위 카테고리입니다.**
API Link에 등록되는 모든 API는 반드시 어떤 서비스 하나에 소속됩니다.

```
서비스            ← 최상위 카테고리 (예: KOS, SCAP, 메시징, 넷플릭스)
  └─ API 그룹
       └─ API
```

KT 사내 시스템(KOS, SCAP, 메시징 등)과 외부 서비스(넷플릭스 등)처럼 성격이 달라도 모두
서비스 단위로 구분되며, 소속될 서비스가 정해져야 API 등록을 시작할 수 있습니다.

### 등록하려는 서비스가 없다면 — 운영팀에 먼저 요청

**서비스는 이 화면에서 직접 만들 수 없습니다.**
서비스 목록에 원하는 서비스가 없다면, **API 등록을 시작하기 전에 API Link 운영팀에
서비스 등록을 요청**해야 합니다. 운영팀이 서비스를 등록해 준 뒤에야 그 아래로 API 그룹과
API를 만들 수 있습니다.

요청은 **apilink@kt.com** 으로 메일을 보내면 됩니다. 운영팀이 내용을 검토한 뒤 필요한
양식을 전달해 줍니다. (MY 페이지의 [권한요청] 화면에 있는 [양식 다운로드] 버튼으로 서비스
등록 관련 양식을 미리 받아볼 수도 있습니다.)

> **전체 작업 순서**
> 1. (없는 서비스라면) API Link 운영팀에 서비스 등록 요청
> 2. 서비스 사용 권한 신청 → 승인
> 3. API 그룹 등록
> 4. API 등록

### 서비스 목록에 안 보일 때

서비스 선택 목록에는 **전체 서비스가 아니라, 로그인한 내가 권한을 가진 서비스만**
표시됩니다.

| 증상 | 원인 | 조치 |
|---|---|---|
| 서비스가 목록에 아예 없음 | 서비스가 아직 등록되지 않았거나, 내게 그 서비스 권한이 없음 | 운영팀에 서비스 등록 요청 / 마이페이지에서 권한 신청 |
| 권한 신청을 했는데 안 보임 | 아직 승인이 나지 않음 | 승인 완료까지 대기 |
| 승인까지 받았는데 안 보임 | 로그인할 때의 권한 정보가 그대로 유지되고 있음 | 로그아웃 후 다시 로그인 |
| 어제까지 보이던 서비스가 사라짐 | 권한 사용기간이 만료됨 | 마이페이지에서 권한 재신청 |

### 서비스 사용 권한 신청하기

권한 신청은 **MY 페이지**의 [권한요청] 화면에서 진행합니다.

![MY 페이지 권한요청 화면](/apidev/resources/images/guide/service-01-auth-request.png)

| 입력 항목 | 설명 |
|---|---|
| 시스템 선택 | 권한을 받으려는 **서비스**를 선택합니다. 화면에서는 "시스템"으로 표기되며, 앞서 설명한 서비스(KOS, SCAP, 메시징 등)와 같은 것입니다. **본인이 개발을 담당하는 시스템**을 선택하면 됩니다 |
| 권한그룹 선택 | 선택한 시스템 안에서 본인 역할에 맞는 그룹(사용자 역할 그룹)을 선택합니다. **API를 등록하는 개발자는 보통 "개발자그룹"** 을 선택합니다. API 등록 화면의 권한그룹(Auth Group)과는 다른 항목입니다 |
| 사용기간 | 권한을 사용할 기간. 3개월 / 6개월 / 1년 버튼으로 간편하게 지정하거나 날짜를 직접 입력합니다 |

**권한그룹이란 (사용자 역할 그룹)**

> ⚠️ **이름이 같은 다른 항목과 혼동하지 마세요.**
> 여기서 고르는 권한그룹은 **"내가 이 시스템에서 무슨 역할인가"**를 뜻합니다.
> "API 등록" 화면의 입력 항목인 권한그룹(Auth Group)은 **"이 API를 누가 호출할 수 있는가"**를
> 정하는 전혀 다른 항목입니다([[api-등록-필드설명]]의 "권한그룹" 참고).
> 개발자그룹/관리자그룹/운영자그룹은 **이 화면(MY 페이지 > 권한요청)에서만** 고릅니다.

하나의 시스템에는 역할에 따라 여러 권한그룹이 있을 수 있습니다. 예를 들어 "개발자그룹",
"관리자그룹", "운영자그룹" 같은 식입니다. 이 권한그룹들은 API Link 운영자가 시스템을
등록할 때 함께 만들어 두므로, 신청자는 그중 **자신의 역할에 맞는 것을 고르기만** 하면
됩니다. API를 등록하려고 들어온 개발자라면 일반적으로 **개발자그룹**을 선택합니다.

세 그룹의 차이는 다음과 같습니다(시스템마다 구성이 다를 수 있습니다).

| 권한그룹 | 대상 | 할 수 있는 일 |
|---|---|---|
| 개발자그룹 | API를 직접 등록·수정하는 개발 담당자 | API 그룹/API 등록, 수정, 배포 요청 |
| 운영자그룹 | 등록된 API를 운영·모니터링하는 담당자 | 배포 현황 조회, 운영 관련 작업 |
| 관리자그룹 | 시스템 단위 관리 담당자 | 권한 승인, 시스템 설정 관리 |

입력 후 [권한요청]을 누르면 신청이 접수되고, **승인이 완료되어야** API 등록 화면의 서비스
목록에 해당 서비스가 나타납니다.

지정한 사용기간이 지나면 권한이 만료되어 서비스 목록에서 다시 사라지므로, 계속 사용해야
한다면 만료 전에 재신청이 필요합니다.

**시스템 선택 목록에 원하는 서비스가 없다면** — 화면 안내대로 **apilink@kt.com** 으로
메일을 보내 서비스 등록을 요청하세요.

### 자주 묻는 질문

**Q. 새로운 서비스를 만들려면 어떻게 하나요?**
A. 화면에서는 만들 수 없습니다. API Link 운영팀에 서비스 등록을 요청하세요. API 등록
일정이 있다면 서비스 등록 요청은 그보다 먼저 진행되어야 합니다.

**Q. 외부사 API(예: 넷플릭스)도 서비스가 필요한가요?**
A. 네. 사내/외부 구분 없이 모든 API는 서비스에 소속되어야 하며, 외부 서비스도 동일하게
운영팀에 등록을 요청한 뒤 사용합니다.

**Q. 서비스와 API 그룹은 어떻게 다른가요?**
A. 서비스는 "어느 시스템/사업의 API인가"를 나타내는 최상위 소속이고(운영팀이 등록),
API 그룹은 그 아래에서 API들을 묶는 단위입니다(사용자가 직접 등록). 서비스 하나에
API 그룹은 여러 개 있을 수 있습니다.

## 2. API 그룹 이름

서비스를 선택한 다음 입력하는 항목입니다. **필수 입력**이며, 여기서 입력한 이름이
**규격서와 API 목록에 그대로 노출**됩니다.

### API 그룹이란

하나의 서비스에는 여러 개의 API가 있습니다. 그 API들을 묶는 단위가 **API 그룹**입니다.
API 등록 메뉴에서 그룹을 등록하면 선택한 서비스 아래에 그룹이 하나 만들어지고, 그 그룹
안에 개별 API들을 등록해 나가게 됩니다.

```
서비스 (예: 메시징)
  ├─ API 그룹 A
  │    ├─ API 1
  │    └─ API 2
  └─ API 그룹 B
       └─ API 3
```

### 그룹을 몇 개로 나눌 것인가

**하나의 서비스에 그룹은 하나일 수도 있고 여러 개일 수도 있습니다.** 정해진 규칙이 있는
것이 아니라, **API를 개발하는 담당자가 직접 판단해서** 결정합니다.

실무에서는 보통 다음 기준을 씁니다.

| 상황 | 권장 |
|---|---|
| API가 10개 이상 | **나눠서** 등록 |
| API가 10개 미만 | **하나로 통합**해서 등록 |
| 성격이 서로 다른 API가 섞여 있음 | 개수와 관계없이 **분리**해서 등록 |

예를 들어 같은 서비스 안에 `MMS메시지서비스` 계열 API와 `무선고객인증` 계열 API처럼 성격이
다른 것이 섞여 있다면, API 수가 적더라도 그룹을 나누는 편이 이용자가 규격서를 볼 때
이해하기 쉽습니다.

### 이름은 어떻게 짓는 것이 좋은가

- 이 이름은 **규격서와 목록에 노출**되므로, API를 사용할 개발자가 보고 무슨 API 묶음인지
  바로 알 수 있는 이름이 좋습니다 (예: `MMS메시지서비스`, `무선고객인증`)
- 그룹을 여러 개로 나눴다면, 서로 구분되는 이름을 붙이세요. 이름이 비슷하면 목록에서
  어느 그룹에 등록해야 할지 헷갈립니다
- **이미 등록된 그룹과 이름이 겹치면 "중복된 API 이름이 존재합니다"라는 경고가
  표시됩니다.** 저장이 막히지는 않지만, 목록과 규격서에서 구분이 어려워지므로 다른
  이름으로 바꾸는 것을 권장합니다
- 중복 여부는 **서비스와 무관하게 전체 그룹을 대상으로** 판단합니다. 다른 서비스에 이미
  같은 이름의 그룹이 있어도 경고가 표시됩니다
- 띄어쓰기와 대소문자는 무시하고 비교합니다. `MMS 메시지서비스` 와 `mms메시지서비스` 는
  같은 이름으로 간주됩니다

## 3. 전체보기

### 대부분의 담당자는 손댈 필요가 없습니다

API 그룹 등록 화면에는 [전체보기] 버튼이 있고, 이를 누르면 호스트·기본경로·API 구분·버전·
스키마·테스트 BASEURL·BEAST G/W 사용여부 항목이 펼쳐집니다.

**일반적인 서비스는 기본 항목(서비스, API 그룹 이름, 설명)만 입력하면 됩니다.**
전체보기 안의 항목들은 기본값이 채워져 있어 그대로 두면 됩니다.

> **이 항목들은 사전에 API Link 운영팀으로부터 별도의 안내를 받은 서비스 담당자만
> 값을 바꿉니다.** 안내를 받은 적이 없다면 기본값 그대로 저장하면 됩니다.
> 임의로 값을 바꾸면 API가 정상적으로 호출되지 않을 수 있습니다.

### 전체보기 안의 항목

| 항목 | 값 | 설명 |
|---|---|---|
| 호스트 | `int-in.tbapi.kt.com` | **API Link 포털의 테스트 콘솔이 연동할 주소.** 여기 입력한 주소로 테스트 호출이 나갑니다. 기본은 `int-in.tbapi.kt.com` 이며, 다른 주소를 써야 하는 경우가 있습니다 (아래 설명 참고) |
| 기본경로 | `/` | 이 그룹에 속한 모든 API 경로 앞에 공통으로 붙는 경로 (`/`로 시작해야 합니다) |
| API 구분 | Public | Public으로 두면 규격서에 공개됩니다 |
| 버전 | `V1.0` | 그룹의 버전 |
| 스키마 | https | https / http / 둘 다 중 선택 |
| 테스트 BASEURL | (비어 있음) | 테스트용 서버 주소. 비워두면 호스트에 입력한 주소로 테스트합니다 |
| BEAST G/W 사용여부 | 사용 안함 | BEAST 게이트웨이 경유 여부 |

### 호스트 주소는 스스로 판단하지 마세요

호스트에 들어갈 API Link Gateway 주소(`int-in.tbapi.kt.com`, `cus-in.tbapi.kt.com` 등)는
**API Link Gateway 담당자가 정하는 값**입니다. 게이트웨이 내부에서 어떤 주소로 처리할지는
Gateway 개발자가 판단하는 영역이라, API를 등록하는 개발자가 임의로 고를 수 없습니다.

**API Link Gateway에 배포하는 서비스의 개발자는 사전에 API Link Gateway 담당자와 협의한 뒤,
안내받은 주소를 입력하세요.** 협의 없이 임의의 주소를 넣으면 테스트 콘솔에서 API가
호출되지 않습니다.
