# API 등록

"API 등록" 화면은 이미 만들어져 있는 **API 그룹(SPC)** 안에 개별 API(Method + Path)를
하나씩 추가하거나, 이미 등록된 API를 불러와 수정하는 화면입니다.

## 이 화면에 들어가려면 먼저 그룹(SPC)이 있어야 합니다

API를 등록하려면 그 API가 속할 **API 그룹**이 먼저 만들어져 있어야 합니다. 그룹이 아직
없다면 "API 그룹(스펙) 등록" 화면에서 그룹을 먼저 만들고([[spc-등록]] 참고), 저장하면
자동으로 이 "API 등록" 화면으로 넘어옵니다.

그룹 하나에는 API(Method+Path)가 여러 개 속할 수 있습니다 — 예를 들어 "메시징 서비스"라는
그룹 하나에 `GET /messages`, `POST /messages`, `DELETE /messages/{id}` 처럼 여러 API가
같이 등록됩니다. 호스트·기본경로는 그룹 단위로 한 번만 정하고, 이후 API를 추가할 때마다
다시 입력할 필요가 없습니다.

## 화면 구성

- **왼쪽 목록**: 이 그룹에 이미 등록된 API 목록이 표시됩니다. 목록의 API를 클릭하면 그
  API의 값이 오른쪽 입력폼에 그대로 불러와지고, 화면이 "수정 모드"로 바뀝니다.
- **"+ 새 API 추가" 버튼**: 수정 모드에서 이 버튼을 누르면 폼이 다시 빈 상태(신규 등록
  모드)로 돌아갑니다.
- **"그룹 정보 수정" 버튼**: 이 API가 속한 그룹 자체의 정보(그룹 이름, 호스트, 기본경로 등)를
  고치고 싶을 때 누릅니다. "API 그룹(스펙) 등록" 화면으로 이동하며, 그 화면이 이 그룹의
  기존 값을 채운 "수정 모드"로 자동으로 열립니다.
- **"템플릿으로 시작" 버튼**: 자주 쓰는 API 형태(예: 요청/응답 공통 필드가 이미 채워진
  템플릿)를 골라서 기본 정보와 파라미터를 한 번에 채울 수 있습니다. 템플릿을 고르지 않고
  직접 입력해도 됩니다.

## 기본 정보 입력 항목

| 항목 | 필수 | 설명 |
|---|---|---|
| API 이름 | O | 목록/규격서에 노출되는 이름 |
| 권한그룹 | O | 이 API를 호출할 수 있는 권한그룹(Auth Group) 선택. MY 페이지 권한요청의 사용자 역할 그룹(개발자그룹 등)과는 다른 항목 |
| Path | O | `/`로 시작하는 API 경로 (그룹의 기본경로 뒤에 붙는 부분만 입력) |
| Method | O | GET/POST/PUT/DELETE 등 |
| 설명 | X | API 설명 |
| API 구분 | O | Public / Private / Internal 중 선택. Public은 규격서에 공개됩니다 |
| Handler / Provider | Private만 필수 | API 구분을 Private으로 선택했을 때만 노출되는 연동 정보 |

이 항목들 아래에 "고급 설정"(엔드포인트/게이트웨이, 응답 매핑, HDP 연동 관련 필드)이 있는데,
기본값 그대로 두어도 되는 경우가 많아 기본은 접혀 있습니다. 필요할 때만 펼쳐서 입력합니다.

## 파라미터(요청/응답 항목) 입력

모든 API는 요청 파라미터가 `request`라는 하나의 객체로 감싸이고, 응답 파라미터가
`response`라는 하나의 객체로 감싸이는 것이 기본 규칙입니다. 화면에 처음 들어가면
자동으로 다음 값이 기본으로 채워집니다.

- **request** 하위 기본 항목: TRANSACTIONID, SEQUENCENO, USERID, SCREENID
- **response** 하위 기본 항목: sequenceno, returncode, returndescription, errorcode, errordescription

여기에 실제 이 API가 주고받는 값을 추가로 넣으면 됩니다. 파라미터는 "파라미터 설계" 팝업에서
트리 형태로 하나씩 추가하거나, YAML을 직접 붙여넣어 한 번에 반영할 수도 있습니다. 파라미터는
object/array로 여러 단계 중첩된 구조도 지원합니다.

## 저장하기

값을 다 입력하고 저장 버튼을 누르면 확인 팝업이 한 번 뜨고, [저장]을 눌러야 실제로
저장됩니다. 저장에 성공하면:

- 왼쪽 목록에 방금 등록/수정한 API가 반영됩니다.
- 신규 등록이었다면 폼이 자동으로 다시 빈 상태로 초기화되어, **곧바로 이어서 다음 API를
  입력하고 저장**할 수 있습니다. 화면 이동 없이 같은 그룹에 API를 여러 건 연달아 등록할 수
  있다는 뜻입니다.
- 기존 API를 수정한 경우엔 그 API가 업데이트되고, 새 API가 따로 만들어지지 않습니다.

## 자주 묻는 질문

**Q. API를 하나 등록한 상태에서 하나 더 추가하려면 어떻게 하나요?**
A. 저장에 성공하면 폼이 자동으로 초기화되므로, 그 상태에서 바로 다음 API 정보를 입력하고
다시 저장하면 됩니다. 만약 기존 API를 클릭해서 수정 모드에 들어와 있다면, 헤더의
"+ 새 API 추가" 버튼을 눌러 빈 폼으로 돌아간 뒤 입력하면 됩니다.

**Q. 그룹의 호스트나 기본경로, 그룹 이름을 바꾸고 싶어요.**
A. "API 등록" 화면이 아니라 그룹 자체를 수정해야 합니다. 헤더의 "그룹 정보 수정" 버튼을
누르면 그 그룹의 기존 값이 채워진 수정 화면으로 이동합니다.

**Q. 이미 등록한 API의 Path나 Method를 고치고 싶어요.**
A. 왼쪽 목록에서 그 API를 클릭하면 값이 폼에 불러와집니다. 원하는 값으로 고친 뒤 저장하면
새로 만들어지지 않고 그 API가 그대로 수정됩니다.

**Q. 요청/응답 파라미터에 왜 처음부터 몇 개 항목이 채워져 있나요?**
A. 이 시스템의 모든 API는 요청을 `request` 객체로, 응답을 `response` 객체로 감싸고 그 안에
공통 항목(트랜잭션ID, 결과코드 등)을 포함하는 것이 규칙이기 때문입니다. 화면에 들어가면
자동으로 채워지며, 여기에 이 API만의 파라미터를 추가로 넣으면 됩니다.
