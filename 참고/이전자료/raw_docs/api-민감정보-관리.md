# API 민감정보(개인정보) 관리

API가 주고받는 항목 중 개인정보에 해당하는 것을 등록하고, 시스템별 현황을 집계해
보는 기능입니다. 개인정보 취급 실태를 파악하고 등급을 관리하는 것이 목적입니다.

## 화면 주소

| 기능 | URL | 메서드 |
|---|---|---|
| 민감정보 현황 | `/apidev/api/sensitiveInfo/report.do` | GET |
| 민감정보 등록 화면 | `/apidev/api/sensitiveInfo/register.do` | GET |
| 등록 저장 | `/apidev/api/sensitiveInfo/registerSubmit.do` | POST |
| 일괄 등록 | `/apidev/api/sensitiveInfo/registerBatch.do` | POST |
| API 목록 팝업 | `/apidev/api/sensitiveInfo/apiListPopup.do` | POST |
| 등급 일괄 변경 | `/apidev/api/sensitiveInfo/updateGrades.do` | POST |

현황·등록 화면은 로그인 없이도 접근 가능한 예외 경로에 포함되어 있습니다.

## 현황 화면에서 보는 것

| 항목 | 설명 |
|---|---|
| 시스템별 API 수 | 시스템마다 등록된 API 개수 |
| 민감정보 포함 API 수 | 개인정보 항목이 하나라도 있는 API 수 |
| 항목 수 | 개인정보로 표시된 파라미터 총 개수 |
| 등급 분포 | 등급별 API 분포 |
| 미조사 API | 아직 조사가 안 된 API |

집계 기준은 파라미터의 **개인정보 속성(`personalData`)** 입니다. 파라미터 설계에서
이 값을 `Y` 로 둔 항목이 여기 집계에 잡힙니다.

## 등록 방법 두 가지

1. **개별 등록** — 등록 화면에서 API를 고르고, 그 API의 파라미터 중 개인정보에
   해당하는 것을 체크해 저장합니다.
2. **일괄 등록** — 여러 API를 한 번에 처리합니다. API 목록 팝업에서 대상을 여러 개
   고른 뒤 공통 등급을 적용하는 방식입니다.

## 등급

민감도에 따라 등급을 부여합니다. 등급은 일괄 변경 화면에서 여러 API에 한 번에
적용할 수 있습니다. 등급 기준은 사내 개인정보 관리 정책을 따르며, 포털은 그 값을
기록·집계하는 역할만 합니다.

## 파라미터 설계와의 관계

민감정보 관리는 파라미터 설계와 짝을 이룹니다.

- 파라미터에 `개인정보 = Y` 를 켜면 → 민감정보 현황 집계에 잡힙니다.
- 파라미터에 `마스킹 = Y` 를 켜면 → 게이트웨이가 로그·응답에서 값을 가립니다.

**두 설정은 별개입니다.** 개인정보로 표시했다고 자동으로 마스킹되지 않고, 마스킹만
켜고 개인정보 표시를 안 하면 집계에서 빠집니다. 둘 다 필요합니다.

## 자주 묻는 질문

**Q. 개인정보 항목을 표시하면 자동으로 가려지나요?**
A. 아니요. 표시는 "이 항목이 개인정보다"라는 기록일 뿐입니다. 실제로 값을 가리려면
파라미터의 마스킹 속성을 따로 켜야 합니다.

**Q. 우리 API는 개인정보가 없습니다. 그래도 등록해야 하나요?**
A. "개인정보 없음"으로 조사 완료 처리를 해야 미조사 목록에서 빠집니다. 아무것도 하지
않으면 계속 미조사로 남습니다.

**Q. 등급을 잘못 넣었습니다.**
A. 등급 일괄 변경 화면에서 대상 API를 다시 골라 등급을 바꾸면 됩니다.

**Q. 현황 숫자가 실제와 다릅니다.**
A. 집계는 파라미터의 개인정보 속성을 기준으로 합니다. 파라미터를 나중에 추가하면서
속성을 안 켠 경우가 흔합니다. 파라미터 설계 화면에서 항목별로 확인하세요.

**Q. 다른 시스템 현황도 볼 수 있나요?**
A. 현황 화면은 전체 집계를 보여줍니다. 다만 개별 API의 상세 파라미터는 권한 범위
안에서만 열립니다.
