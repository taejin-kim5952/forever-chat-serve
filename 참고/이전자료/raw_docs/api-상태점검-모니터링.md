# API 상태 점검과 모니터링

배포된 API가 지금도 정상인지 주기적으로 호출해 확인하는 기능입니다. 결과는 일별로
쌓여 이력으로 남고, 그룹 단위로 담당자에게 공유할 수 있습니다.

## 구성 요소

| 요소 | 설명 |
|---|---|
| 상태 점검 대상 | 점검할 API 목록 |
| 점검 그룹 | 여러 API를 묶어 관리하는 단위 |
| 그룹-사용자 연결 | 그룹별 담당자 지정 |
| 점검 이력 | 실행 회차별 결과 |
| 일별 이력 | 하루 단위로 집계된 결과 |

## 저장되는 점검 결과

점검 한 번에 다음 값이 기록됩니다.

| 항목 | 설명 |
|---|---|
| 점검 일시 | 호출한 시각 |
| 상태 코드 | HTTP 또는 업무 응답 코드 |
| 응답 시간(ms) | 밀리초 단위 소요 시간 |
| 성공 여부 | 기대 결과와 일치했는지 |
| 응답 본문 요약 | 실패 원인 파악용 |

일별 이력은 `점검일시::상태코드::응답시간` 형태의 문자열을 하루치로 이어 붙여
저장합니다. 그래서 하루 추이를 한 줄로 훑어볼 수 있습니다.

## 조회 조건

- **최근 N일** — 최근 며칠 안의 점검 결과만 봅니다.
- **그룹** — 특정 점검 그룹에 속한 API만.
- **성공/실패** — 실패한 건만 추려 봅니다.
- **시스템** — 시스템 단위 필터.

## 화면

상태 점검 화면은 Vue 기반입니다.

- **목록 화면(`apistatus_list`)** — API별 최근 점검 결과와 성공률.
- **그룹 화면(`apistatus_group`)** — 그룹 관리, 그룹에 API 담기, 담당자 연결.
- **이력 다이얼로그** — 특정 API의 점검 이력 목록과 상세 응답.

## REST 엔드포인트

상태 점검 데이터는 `/apidev/apistatus_api/{버전}/{group}/{ifname}` 형태의 POST
호출로 조회합니다. 요청·응답 모두 JSON(UTF-8)입니다. `group` 과 `ifname` 조합으로
어떤 조회를 할지 정하는 방식이라, 화면이 늘어나도 엔드포인트를 새로 만들지 않습니다.

## 트래픽·건수 집계

상태 점검과 별개로, 게이트웨이 호출 건수와 트래픽을 집계해 보여주는 화면도 있습니다.
API별 호출 수, 상태 코드 분포, 시간대별 추이를 차트로 표시합니다. 차트는 Highcharts로
그립니다.

## 자주 묻는 질문

**Q. 점검이 실패로 나오는데 실제로는 서비스가 잘 됩니다.**
A. 점검용 요청 파라미터가 실제 사용 값과 다르거나, 성공 판정 기준이 잘못 잡힌
경우입니다. 점검 대상 설정에서 요청 값과 기대 결과를 다시 확인하세요.

**Q. 점검 주기는 어떻게 되나요?**
A. 스케줄러가 정해진 시각에 실행합니다. 주기는 서버 설정으로 관리되며, 화면에서
사용자가 바꾸는 값은 아닙니다. 즉시 확인이 필요하면 검증 실행 기능을 쓰세요.

**Q. 담당자에게 알림이 가나요?**
A. 그룹에 사용자를 연결해 두면 그 그룹의 결과를 담당자가 조회할 수 있습니다. 실패
알림 메일은 운영 정책에 따라 설정됩니다.

**Q. 응답 시간이 갑자기 늘었습니다.**
A. 일별 이력에서 언제부터 늘었는지 확인한 뒤, 그 시점에 배포나 백엔드 변경이 있었는지
배포 이력과 대조하세요.

**Q. 점검 대상에서 빼고 싶습니다.**
A. 그룹에서 해당 API를 제거하거나 점검 대상 설정을 해제합니다. 배포를 내리는 것과는
별개입니다.
