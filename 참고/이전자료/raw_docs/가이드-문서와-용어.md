# 이용 가이드와 용어 정리

포털에서 쓰는 말이 사내 다른 시스템과 조금씩 다릅니다. 헷갈리기 쉬운 것부터
정리합니다.

## 핵심 용어

| 용어 | 뜻 |
|---|---|
| **SPC(규격, Specification)** | API를 묶는 그룹. 호스트·기본경로·버전을 이 단위로 정함 |
| **API DEF(정의)** | Method + Path 조합 하나. 그룹 안에 여러 개 |
| **파라미터(Param)** | API가 주고받는 항목. request/response 트리로 관리 |
| **시스템(System)** | 조직·서비스 단위. 권한도 이 단위로 부여 |
| **카테고리** | 규격서 목차 분류 |
| **권한그룹(Auth)** | 두 가지 뜻 — 사용자 작업 권한 / API 호출 권한 |
| **핸들러(Handler)** | 게이트웨이가 요청·응답을 변환하는 모듈 |
| **엔드포인트(Endpoint)** | 게이트웨이가 실제로 호출하는 백엔드 주소 |
| **TB** | 검증계(테스트베드) |
| **CB / PRD** | 운영 환경 |
| **배포(Deploy)** | 등록된 API를 게이트웨이에 올리는 일 |
| **검증(Verify)** | 배포 전 실제 호출로 동작을 확인하는 일 |
| **LAMP** | 게이트웨이 호출 로그 수집 체계 |
| **BEAST** | 사내 API 게이트웨이 |
| **APIGW** | 게이트웨이 연동을 다루는 내부 모듈 |
| **PSSO** | 사내 통합 인증 |
| **SHUB** | 연동 플랫폼 |
| **Arsenal** | 사내 API 자산 저장소 |
| **SafeDB** | DB 컬럼 암호화 모듈 |
| **옵저버(Observer)** | 조회 전용 권한 |

## 헷갈리기 쉬운 짝

**그룹(SPC) vs API(DEF)**
그룹은 상자, API는 그 안의 개별 호출입니다. 호스트를 바꾸려면 그룹을, Path를 바꾸려면
API를 수정합니다.

**사용자 권한그룹 vs API 권한그룹**
앞의 것은 "이 사람이 무엇을 할 수 있나", 뒤의 것은 "이 API를 누가 호출할 수 있나"
입니다. 이름이 같아서 자주 혼동됩니다.

**포털 배포 vs 애플리케이션 배포**
"배포"라는 말이 두 가지로 쓰입니다. 사용자가 말하는 배포는 보통 API를 게이트웨이에
올리는 일이고, 운영팀이 말하는 배포는 포털 자체를 서버에 올리는 일입니다.

**검증(Verify) vs 승인(Approve)**
검증은 기계가 실제로 호출해 보는 것이고, 승인은 사람이 결재하는 것입니다. 둘 다
배포 전에 필요합니다.

**개인정보 표시 vs 마스킹**
개인정보 표시는 집계용 기록, 마스킹은 실제로 값을 가리는 설정입니다. 별개 항목이라
둘 다 켜야 합니다.

**삭제 vs 비공개 vs 배포 삭제**
- 삭제: 포털 데이터에서 지운 것으로 표시(논리 삭제)
- 비공개: 검색·규격서에서 감춤
- 배포 삭제: 게이트웨이에서 실제로 내림

셋 중 서비스가 멈추는 것은 **배포 삭제뿐**입니다.

## 자주 묻는 질문

**Q. 규격서와 가이드는 뭐가 다른가요?**
A. 규격서는 개별 API의 입출력 정의이고, 가이드는 포털 사용법과 연동 절차 안내입니다.

**Q. "스펙"과 "규격"은 같은 말인가요?**
A. 네. 영문 SPC(Specification)를 한글로 규격이라고 부릅니다. 화면에 따라 "그룹"으로도
표시됩니다.

**Q. TB와 운영을 각각 배포해야 하나요?**
A. 네. 별개 환경이라 각각 배포합니다. TB에서 확인한 뒤 운영으로 올리는 것이
원칙입니다.
