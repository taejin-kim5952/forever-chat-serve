# 데이터베이스 테이블 구조

포털의 모든 데이터는 `KOA_TB_` 로 시작하는 테이블에 저장됩니다. SQL은 Java 코드가
아니라 MyBatis XML 매퍼에 모여 있어, 테이블 사용처를 찾을 때는 매퍼 파일을 보면
됩니다.

## 핵심 테이블

| 테이블 | 담는 것 | 참조 빈도 |
|---|---|---|
| `KOA_TB_API_DEF` | API 정의 한 건(Method+Path) | 가장 많음 |
| `KOA_TB_API_SPC` | API 그룹(규격, SPC) | 매우 많음 |
| `KOA_TB_API_SYSTEM` | 시스템 정보 | 많음 |
| `KOA_TB_COMN_CD` | 공통코드 | 많음 |
| `KOA_TB_API_PARAM` | API 파라미터(요청/응답 항목) | 많음 |
| `KOA_TB_MBR` | 회원 | 많음 |
| `KOA_TB_API_CTGRY` | API 카테고리 | 보통 |

## 자동 채번 시퀀스

PostgreSQL 전환 과정에서 SQL Server의 IDENTITY 방식이 시퀀스로 바뀌었습니다.

| 시퀀스 | 대상 |
|---|---|
| `KOA_TB_API_DEF_API_NO_SEQ` | API 정의 번호 |
| `KOA_TB_API_SPC_API_SPC_NO_SEQ` | 규격 번호 |

## 주요 컬럼 규칙

- **`~_NO`** — 내부 일련번호(숫자). 화면 URL에 실려 다닙니다.
- **`~_ID`** — 사람이 정하는 식별자(문자). 중복 확인 대상입니다.
- **`~_CD`** — 공통코드 값.
- **`REG_DT` / `REGR`** — 등록 일시 / 등록자.
- **`AMD_DT` / `AMDR`** — 수정 일시 / 수정자.
- **`USE_YN`** — 사용 여부. `N` 이면 목록에서 빠집니다.
- **`DEL_DT` / `DELR`** — 삭제 일시 / 삭제자. 값이 있으면 삭제 처리된 행입니다.

대부분의 테이블은 **행을 실제로 지우지 않고** `USE_YN` 이나 `DEL_DT` 로 표시만
바꿉니다. 그래서 "지웠는데 어딘가에 남아 있다"는 상황이 생깁니다.

## 자주 묻는 질문

**Q. 삭제한 API가 통계에는 남아 있습니다.**
A. 논리 삭제이기 때문입니다. `DEL_DT` 가 채워질 뿐 행은 남습니다. 통계 쿼리가 삭제
조건을 안 걸면 집계에 포함될 수 있습니다.

**Q. 테이블을 직접 조회해도 되나요?**
A. 운영 DB 직접 조회는 권한이 필요합니다. 조회가 필요하면 개발지원으로 요청하세요.

**Q. 컬럼 이름은 대문자인데 화면 필드는 소문자입니다.**
A. MyBatis의 언더스코어→카멜케이스 자동 변환이 켜져 있습니다. `API_SPC_NO` 컬럼이
`apiSpcNo` 필드로 매핑됩니다.
