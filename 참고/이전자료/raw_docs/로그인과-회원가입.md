# 로그인과 회원가입

포털 로그인은 사내 통합 인증(PSSO)과 연동되어 있습니다. 아이디·비밀번호만으로 끝나지
않고 상황에 따라 **휴대폰 SMS 인증**이나 **OTP**를 한 번 더 요구합니다.

## 로그인 화면

- 로그인 폼: `/apidev/login/loginForm.do`
- 로그인 처리: `/apidev/login/loginCheck.do`
- 신규 로그인 처리: `/apidev/login/newLoginCheck.do`
- 로그인 성공 후 착지: `/apidev/login/login_success.do`
- OTP 발송: `/apidev/login/otpSend.do`
- 아이디 중복/사용여부 확인: `/apidev/login/dupChkYn.do`
- 로그아웃: `/apidev/login/pssoLogout.do`

비밀번호는 화면에서 그대로 전송되지 않습니다. 로그인 폼에 포함된 RSA 스크립트가
공개키로 암호화한 뒤 서버로 보내고, 서버가 개인키로 풀어 PSSO 인증 API에 넘깁니다.
그래서 브라우저 네트워크 탭을 봐도 평문 비밀번호는 보이지 않습니다.

## PSSO 연동

로그인·회원가입·비밀번호 변경은 모두 사내 PSSO API를 호출합니다.

| 기능 | 연동 API |
|---|---|
| 로그인 검증 | `psso_memberLogin` |
| 아이디 중복 확인 | `psso_memberIdCheck` |
| 회원 가입 | `psso_defaultJoin` |
| 비밀번호 재설정 | `psso_pwdChangeAgainReset` |
| 인증서 확인 | `psso_certCheck` |
| 가입 정보 조회 | `psso_userInfoByUserName` |
| 회원 존재 확인 | `psso_existByIdPlus` |
| 회원 정보 수정 | `psso_userInfoUpdate` |
| 회원 정보 조회 | `psso_userInfoSearch` |

PSSO 응답의 상태값은 성공 `11`, 실패 `12` 입니다. 포털은 이 값을 보고 로그인 성공
여부를 판단합니다. PSSO 자체가 응답하지 않으면 포털 로그인도 실패합니다 — 이때는
포털 문제가 아니라 인증 서버 문제입니다.

## 휴대폰 본인확인(SMS)

일정 조건에서 로그인 중 본인확인 절차가 뜹니다. 관련 화면 호출은 `/apidev/login/auth`
아래에 있습니다.

- `smsSend.do` — 인증번호 발송
- `phoneConfirm.do` — 입력한 인증번호 검증
- `authCheck.do` — 인증 완료 여부 확인

인증번호 발송·검증은 사내 메시징 게이트웨이(`verify_send`, `verify_check`)를
호출합니다. 문자를 못 받는 원인은 대부분 (1) 회원 정보에 등록된 번호와 실제 번호가
다르거나 (2) 번호에 하이픈·공백이 섞여 있는 경우입니다.

## 회원가입

- 가입 폼: `/apidev/userJoin/userJoinForm.do`
- 가입 처리: `/apidev/userJoin/insertJoin.do` (POST)
- 가입 정보 조회: `/apidev/userJoin/userInfo.do`, `/apidev/userJoin/sJoinInfo.do`

가입 시 입력하는 항목은 다음과 같습니다.

| 항목 | 필드명 | 필수 | 비고 |
|---|---|---|---|
| 아이디 | `mbrId` | O | 중복 확인 필수 |
| 이름 | `mbrNm` | O | |
| 회사명 | `cmpnNm` | O | |
| 전화번호 | `telNo` | O | 3칸(`telNo1`/`telNo2`/`telNo3`)으로 나눠 입력 |
| 이메일 | `email` | O | 알림 메일 수신 주소 |
| 이용약관 동의 | `stpltAgreeYn` | O | `Y`/`N` |
| 개인정보 동의 | `indvInfoAgreeYn` | O | `Y`/`N` |

가입이 끝나면 회원 상태(`mbrSttusCd`)가 부여됩니다. 코드 `MBRSTS1020` 은 정상 사용
상태, `MBRSTS4010` 은 탈퇴/정지 계열 상태를 뜻합니다. 상태가 정상이 아니면 로그인
자체는 되어도 기능 화면에서 막힙니다.

## 개인정보 마스킹

회원 아이디는 화면에 그대로 보이지 않고 마스킹된 값(`maskingMbrId`)으로 표시되는
자리가 많습니다. 또한 DB에 저장되는 개인정보 컬럼은 SafeDB 암호화 모듈을 통해
암·복호화됩니다. 로컬 개발 환경처럼 SafeDB 에이전트가 없는 곳에서는 모의 모드
(`SAFEDB_MOCK_ENABLED=true`)로 우회할 수 있고, 운영에서는 항상 실제 암호화가 걸립니다.

## 세션과 중복 로그인

- 세션 유지 시간은 **120분**입니다.
- 세션에 담기는 사용자 정보의 키 이름은 `ssUserVo` 입니다.
- 같은 아이디로 다른 브라우저에서 로그인하면 **먼저 로그인한 세션이 무효**가 됩니다.
  이후 그 창에서 무엇을 눌러도 메인 화면으로 되돌아갑니다.
- 세션 ID는 쿠키로만 추적하고 URL에 노출하지 않습니다.

## 자주 묻는 질문

**Q. 비밀번호를 잊었습니다.**
A. 로그인 화면의 비밀번호 찾기 링크를 이용하세요. 포털이 자체적으로 비밀번호를 갖고
있지 않고 PSSO에 위임하므로, 재설정도 PSSO 화면에서 이뤄집니다.

**Q. 아이디가 기억나지 않습니다.**
A. 아이디 찾기 링크로 이동해 이름·연락처로 조회합니다.

**Q. 로그인은 되는데 메뉴가 거의 안 보입니다.**
A. 가입만 되고 권한그룹이 아직 부여되지 않은 상태입니다. 마이페이지에서 권한을
신청하고 승인을 받아야 등록·배포 메뉴가 열립니다.

**Q. 인증번호 문자가 오지 않습니다.**
A. 회원 정보에 등록된 휴대폰 번호와 실제 번호가 같은지 먼저 확인하세요. 번호가
다르면 회원정보 수정 후 다시 시도해야 합니다. 번호는 하이픈 없이 숫자만 넣습니다.

**Q. "이미 로그인 중입니다" 같은 상황이 반복됩니다.**
A. 다른 창이나 다른 PC에 세션이 남아 있는 경우입니다. 그쪽에서 로그아웃하거나 세션이
만료될 때까지 기다리면 정리됩니다.
