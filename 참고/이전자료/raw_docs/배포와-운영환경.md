# 애플리케이션 배포와 운영 환경

포털 자체를 서버에 올리는 절차입니다. (게이트웨이에 API를 올리는 "배포"와는 다른
이야기입니다.)

## 파이프라인 개요

```
GitHub 저장소
   │ 수동 실행(workflow_dispatch, 버전 입력)
   ▼
self-hosted 러너
   │ ① Azure OIDC 로그인
   │ ② Key Vault에서 시크릿 조회 (ACR 주소·계정·프록시 비밀번호)
   │ ③ JDK / Maven 준비
   │ ④ 사내 Nexus 미러 settings.xml 생성
   │ ⑤ mvn clean package (테스트 생략)
   │ ⑥ Docker 이미지 빌드
   │ ⑦ ACR 푸시
   ▼
Trivy 컨테이너 취약점 스캔
   ▼
Azure 컨테이너 환경에서 기동
```

## 워크플로 종류

| 워크플로 | 대상 |
|---|---|
| `workflow_dev` | 개발/검증(tb 프로파일) |
| `workflow_prd` | 운영(prod 프로파일) |
| `workflow_arc_dev` | 아키텍처 검증용 개발 |
| `workflow_arc_prd` | 아키텍처 검증용 운영 |

배포는 자동이 아니라 **수동 실행**입니다. 실행할 때 버전 문자열을 입력하며, 비워
두면 커밋 해시가 이미지 태그가 됩니다.

## 컨테이너 구성

- 베이스 이미지: 사내 레지스트리의 Tomcat 이미지
- 타임존 `Asia/Seoul`, 로케일 UTF-8
- WAR를 `ROOT.war` 로 배치하고 미리 풀어 둠
- Application Insights 자바 에이전트 부착
- TLS는 1.2/1.3만 허용하고 암호 스위트를 명시적으로 제한

## 기동 시 시크릿 주입

컨테이너 진입 스크립트가 기동 직전에 설정 파일의 자리표시자를 환경변수 값으로
치환합니다.

| 치환 대상 | 자리표시자 |
|---|---|
| Tomcat JNDI DataSource | `#{DB_URL}`, `#{DB_USERNAME}`, `#{DB_PASSWORD}` |
| DB 암호화 매핑 | `#{SAFEDB_AUTH_PASSWORD}` |

치환이 끝나면 Tomcat을 실행합니다. 환경변수가 비어 있으면 자리표시자가 그대로 남아
DB 연결이 실패합니다 — 기동 로그에서 가장 먼저 확인할 부분입니다.

## 환경 구분

| 프로파일 | 용도 |
|---|---|
| `local` | 개발자 PC |
| `tb` | 검증계 |
| `prod` | 운영 |

같은 코드가 프로파일만 바꿔 뜹니다. DB 주소, 게이트웨이 주소, 파일 서버 경로, 외부
연동 URL이 프로파일별로 다릅니다.

## 모니터링

Application Insights 에이전트가 붙어 있어 요청 응답 시간, 예외, 의존 호출을 수집
합니다. LAMP 로그는 별도로 서버의 로그 디렉터리에 쌓입니다.

## 자주 묻는 질문

**Q. 배포 후 화면이 안 뜹니다.**
A. 기동 로그를 먼저 보세요. DataSource 실패, 설정값 누락(플레이스홀더 미해결),
필수 리소스 점검 실패가 흔한 원인입니다.

**Q. 이미지 태그를 어떻게 정하나요?**
A. 워크플로 실행 시 입력한 버전 문자열이 태그가 됩니다. 입력하지 않으면 커밋
해시가 쓰입니다. 되돌릴 때를 대비해 의미 있는 버전을 넣는 편이 좋습니다.

**Q. 롤백은 어떻게 하나요?**
A. 이전 이미지 태그로 다시 배포합니다. 이미지가 레지스트리에 남아 있으므로
재빌드 없이 가능합니다.

**Q. 테스트를 건너뛰고 빌드하는 이유는?**
A. 파이프라인이 `-DskipTests` 로 패키징합니다. 테스트는 별도 단계에서 수행하는
정책입니다.

**Q. 취약점 스캔에서 걸리면 배포가 막히나요?**
A. 스캔 결과는 보안 이벤트로 보고됩니다. 심각도에 따른 처리 기준은 보안 정책을
따릅니다.
