# API Manager 포털 전체 개요

API Manager(APILinkManager)는 KT 사내·대외 개발자가 **API를 등록하고, 규격을 정의하고,
검증한 뒤, API 게이트웨이에 배포**하기까지의 전 과정을 한 화면에서 처리하는 포털입니다.
운영 애플리케이션의 컨텍스트 경로는 `/apidev` 이고, 첫 진입점은 `/apidev/main/index.do`
입니다. 루트(`/`)로 들어오면 서버가 자동으로 이 주소로 리다이렉트합니다.

## 이 시스템이 하는 일

포털은 크게 다섯 덩어리로 나뉩니다.

| 덩어리 | 하는 일 | 대표 URL |
|---|---|---|
| **API 규격 관리** | API 그룹(SPC) 생성, API(Method+Path) 등록, 파라미터 설계, YAML 반입/반출 | `/api/spcreg`, `/api/reg` |
| **API 조회/검색** | 등록된 API 목록·상세·규격서 열람, 개발자용 검색 | `/api/search`, `/api/info` |
| **배포/승인** | 배포 신청, 결재선 승인, TB/운영 배포, 검증 실행 | `/api/deploy` |
| **게이트웨이 연동** | APIGW·BEAST 게이트웨이에 API 실배포, LAMP 로그 조회 | `/beast`, `/adptran` |
| **커뮤니티·지원** | 공지, 포럼, FAQ, Q&A, 개발지원 문의, 테스트데이터 신청 | `/bbs`, `/faq`, `/qna`, `/devsupport` |

## 한 건의 API가 태어나서 배포되기까지

포털에서 API 하나가 서비스에 나가기까지의 흐름은 다음과 같습니다.

```
① 회원가입/로그인 ──→ ② 권한그룹 신청(마이페이지) ──→ ③ API 그룹(SPC) 생성
      ↓
④ API(Method+Path) 등록 ──→ ⑤ 파라미터 설계(request/response 트리)
      ↓
⑥ 테스트케이스 등록 ──→ ⑦ 검증(Verify) 실행 ──→ ⑧ 배포 신청
      ↓
⑨ 결재 승인 ──→ ⑩ TB(검증계) 배포 ──→ ⑪ 운영(CB/PRD) 배포 ──→ ⑫ 상태 점검·모니터링
```

각 단계는 **앞 단계가 끝나야 다음 단계 버튼이 열립니다.** 예를 들어 검증을 한 번도
실행하지 않은 API는 배포 신청 목록에 나타나지 않고, 승인이 떨어지지 않은 신청 건은
운영 배포 버튼이 비활성 상태로 보입니다.

## 사용자 구분

포털은 로그인한 사용자의 권한에 따라 보이는 메뉴가 달라집니다.

- **개발자(일반 회원)** — 자기 시스템에 속한 API를 등록·수정하고 배포를 신청합니다.
- **승인자(결재자)** — 배포 신청 건을 승인하거나 반려합니다. 반려할 때는 사유를 반드시
  적어야 합니다.
- **운영자(A/G 운영자 그룹)** — 게이트웨이 배포, 상태 점검, 공통코드 관리 등 전체 범위를
  다룹니다. 설정상 권한 ID `94`, 권한명 `A/G 운영자 그룹`으로 지정되어 있습니다.
- **옵저버(Observer)** — 조회만 가능한 계정입니다. 세션의 `observerYn` 값이 `Y`이면
  등록·수정 버튼이 화면에서 감춰집니다.

## 비로그인으로도 볼 수 있는 화면

로그인하지 않아도 열람 가능한 화면이 정해져 있습니다. 서버의 세션 체크 인터셉터가
아래 경로만 예외로 통과시키고, 나머지 요청은 전부 `/apidev/main/index.do` 로
되돌려 보냅니다.

- 메인 화면, 로그인 화면, 회원가입 화면
- 공지사항 목록·상세, 포럼 목록·상세, FAQ, Q&A 목록·상세
- API 검색 목록(`/api/search/mvMainList.do`)과 API 규격 조회(`/api/info/mvInfoView.do`)
- 이용 가이드(`/guide/mvUseList.do`), SHUB 가이드(`/guide/mvShubList.do`)
- 이용약관(`/agree/agViewinfo.do`), 개인정보처리방침(`/priv/pViewinfo.do`)
- 개발지원 게시판 목록, 테스트데이터 신청, SDK 다운로드
- 파일 다운로드(`/file/fileDownLoad.do`), YAML 다운로드

## 자주 묻는 질문

**Q. 로그인했는데 메뉴를 눌러도 계속 메인 화면으로 돌아갑니다.**
A. 세션이 만료되었거나 같은 계정으로 다른 곳에서 로그인해 기존 세션이 끊긴 경우입니다.
세션 타임아웃은 120분이고, 동일 계정 중복 로그인 시 나중 로그인이 우선입니다. 다시
로그인하면 정상 동작합니다.

**Q. 주소창에 `/apidev` 를 빼고 들어가도 되나요?**
A. 애플리케이션 컨텍스트 경로가 `/apidev` 이므로 반드시 포함해야 합니다. 다만 도메인
루트로 들어오면 서버가 `/apidev/main/index.do` 로 자동 이동시켜 줍니다.

**Q. 화면마다 `.do` 가 붙는 이유가 무엇인가요?**
A. 레거시 시절부터 이어진 URL 규칙입니다. 화면 이동은 `.do`, 화면 안에서 비동기로
데이터만 주고받는 호출은 `~Ajax.do`, 외부 연동용 REST 는 `.json` 으로 끝납니다. 규칙만
알아도 주소만 보고 그 요청이 화면인지 데이터인지 구분할 수 있습니다.

**Q. 세션이 얼마나 유지되나요?**
A. 120분입니다. 그 사이 아무 요청도 없으면 만료됩니다. 화면을 켜 둔 채 오래 두었다가
저장을 누르면 로그인 화면으로 튕길 수 있으니, 긴 작업은 중간중간 저장하세요.
