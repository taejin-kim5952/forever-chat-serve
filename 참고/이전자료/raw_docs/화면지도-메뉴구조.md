# 화면 지도와 메뉴 구조

포털의 모든 화면은 URL 앞부분(컨트롤러 경로)만 보면 어느 업무에 속하는지 알 수 있습니다.
이 문서는 "그 화면 주소가 뭐였더라"를 찾을 때 쓰는 지도입니다. 모든 주소 앞에는
컨텍스트 경로 `/apidev` 가 붙습니다.

## URL 접미사 규칙

- **`mv~.do`** — 화면 이동(move). 예: `mvDeployList.do` 는 배포 목록 **화면**을 엽니다.
- **`sel~Ajax.do`** — 조회(select) 비동기 호출. 화면은 그대로 두고 데이터만 갈아 끼웁니다.
- **`sav~Ajax.do`** — 저장(save) 비동기 호출.
- **`del~Ajax.do`** — 삭제 비동기 호출.
- **`~.json`** — 외부 시스템이 호출하는 REST 엔드포인트.

이 규칙 때문에 브라우저 개발자 도구의 네트워크 탭만 봐도 어떤 동작이 일어났는지
짐작할 수 있습니다. 화면이 안 바뀌는데 데이터가 갱신되면 `Ajax.do` 호출입니다.

## 배포 업무 화면 목록

배포는 화면 수가 가장 많은 업무입니다. 자주 쓰는 것만 추리면 다음과 같습니다.

| 화면 | URL | 설명 |
|---|---|---|
| 배포 목록 | `/api/deploy/mvDeployList.do` | 내가 신청한/담당인 배포 건 목록 |
| 승인 목록 | `/api/deploy/mvApprovalListN.do` | 결재 대기 중인 신청 건 |
| 배포 상세 | `/api/deploy/mvDeployView.do` | 신청 1건의 API 목록과 진행 상태 |
| 배포 신청 | `/api/deploy/mvDeployApply.do` | 새 배포 신청서 작성 |
| 검증 실행 | `/api/deploy/mvVerifyExecute.do` | 테스트케이스 실행 화면 |
| 임시 양식 | `/api/deploy/mvTempForm.do` | 신청서 양식 미리보기 |
| LAMP 로그 | `/api/deploy/lampLogAjax.do` | 게이트웨이 호출 로그 팝업 |

## 팝업 화면

팝업은 별도 URL 없이 부모 화면에서 열리는 것이 많습니다. 배포 업무에서 쓰이는 팝업만
정리하면 이렇습니다.

- **배포 신청서 보기**(`popDeployApplyView`) — 신청 내용을 결재 양식으로 봅니다.
- **배포 이력**(`popDeployHst`, `popCbDeployHst`) — 언제 누가 배포했는지 이력.
- **검증 이력**(`popVerifiHst`) — 검증 실행 결과의 성공/실패 목록.
- **LAMP 로그**(`popLampLog`) — 게이트웨이로 실제 나간 요청/응답 원문.
- **배포 취소**(`popDeployCancel`) — 진행 중인 배포를 되돌립니다.
- **공통 알림/확인**(`popCommonAlert`, `popConfirmAlert`) — 확인·경고 공용 팝업.

## 자주 묻는 질문

**Q. 메뉴에 없는 화면 주소를 직접 입력해도 되나요?**
A. 됩니다. 다만 권한이 없으면 메인으로 되돌아가고, 필수 파라미터(예: `apiSpcNo`)가
빠지면 빈 화면이 뜹니다. 화면은 보통 목록에서 항목을 클릭해 들어가는 것을 전제로
만들어져 있습니다.

**Q. 화면 주소는 같은데 내용이 다르게 보입니다.**
A. 같은 화면이라도 로그인 계정의 권한, 담당 시스템, 옵저버 여부에 따라 목록에 담기는
데이터와 노출되는 버튼이 달라집니다.

**Q. `/beast` 와 `/adptran` 은 무엇이 다른가요?**
A. `/beast` 는 BEAST 게이트웨이 배포·조회 업무 화면이고, `/adptran` 은 개발자용 도구
화면(Vue 기반)입니다. 둘 다 게이트웨이를 다루지만 목적이 다릅니다.
