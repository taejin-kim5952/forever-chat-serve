# API Manager 도우미 챗봇 - 디자인/퍼블리싱 요청서

## 1. 배경

`openapi-chat`이라는 신규 서비스로, KT OpenAPI Portal "API Manager" 화면(API 등록 / API 그룹(스펙)
등록 / 템플릿 관리) 사용법을 안내하는 RAG 기반 챗봇 API(`POST /ask`)를 구축했습니다. 백엔드(FastAPI +
로컬 LLM/RAG 파이프라인)는 이미 동작하는 상태이고, 이번에 요청드리는 건 그 API를 호출해서 사용자와
주고받는 **대화형 챗봇 화면(UI)**입니다.

- 이번 요청 범위: **독립 전체화면 챗봇 페이지** 1개. 기존 API Manager 화면(`quickApiReg.html` 등)에
  위젯 형태로 삽입하는 작업은 이번 범위가 아니며, 화면이 완성된 뒤 별도로 요청드릴 예정입니다.
- 다만 나중에 위젯으로 재사용하기 쉽도록, 대화 영역(메시지 리스트 + 입력창) 마크업/CSS는 페이지의
  나머지 레이아웃(헤더 등)과 최대한 분리해서 만들어주시면 좋습니다(4번 참고).

## 2. 톤앤매너 — 기존 API Manager 화면과 통일

이 화면은 API Manager와 같은 제품군으로 보여야 하므로, 새 디자인 언어를 만들지 않고 기존 화면들이
쓰는 톤을 그대로 재사용합니다.

- 참고 화면(같은 톤 확인용): `quickApiReg.html`("빠른 API 등록"), `tmpltMngList.html`/`tmpltMngForm.html`
  ("템플릿 관리") — `참고자료/uploads/apimanager백업/` 폴더에서 그대로 열어볼 수 있습니다.
- 재사용할 CSS 토큰 (`quickApiReg.css`의 `:root`):
  - 강조색 `--qr-accent: #c93137` / 강조색(hover) `--qr-accent-dark: #a8262b`
  - 틸(보조색) `--qr-teal: #309ba2` / 틸 배경 `--qr-teal-bg: #d6ebec`
  - 텍스트 `--qr-ink: #333`, 보조텍스트 `--qr-ink-soft: #666`, 옅은텍스트 `--qr-mute: #999`
  - 선 `--qr-line: #ddd`, 위험 `--qr-danger: #d64449`
  - 모서리 `--qr-radius: 10px`, 필 버튼 `--qr-radius-pill: 50px`
  - 폰트: `'Pretendard', 'NanumGothic', sans-serif`
- 버튼은 기존 `.qr_pill`/`.qr_pill_accent`/`.qr_pill_outline`/`.qr_pill_teal` 스타일 그대로 재사용해
  주세요(새 버튼 스타일 만들 필요 없음).
- 팝업이 필요하면(예: 출처 문서 상세보기) `.qr_modal_backdrop` 패턴(같은 페이지 내 DOM 모달, 새 창 아님)
  그대로 사용합니다.

## 3. 핵심 컨셉

### 3-1. 전체 레이아웃

```
┌──────────────────────────────────────────────┐
│  [로고] API Manager 도우미                      │  ← 헤더 (qr_head 톤)
├──────────────────────────────────────────────┤
│                                                │
│   (봇) API 등록/그룹/템플릿 관련 질문을 답변해   │
│         드립니다. 무엇이 궁금하신가요?           │  ← 대화 시작 안내
│                                                │
│                    (사용자) API 등록은 어떻게    │
│                              하나요?         (● │  ← 사용자 말풍선 (우측 정렬)
│                                                │
│   (봇) 'API 등록' 화면에서 등록합니다...         │
│        📄 출처: API 등록                        │  ← 봇 말풍선 (좌측 정렬) + 출처 배지
│                                                │
├──────────────────────────────────────────────┤
│  [질문을 입력하세요...............]   [전송]     │  ← 입력창 (하단 고정)
└──────────────────────────────────────────────┘
```

- 메시지 영역은 스크롤되는 리스트, 입력창은 화면 하단 고정.
- 봇 말풍선 좌측 정렬 / 사용자 말풍선 우측 정렬(일반적인 메신저 패턴), 강조색은 사용자 말풍선에만 살짝
  사용(예: 배경 `--qr-teal-bg` 또는 outline), 봇 말풍선은 무채색 톤 유지.

### 3-2. 봇 응답의 4가지 상태 (API 응답의 `answered_by` 값에 대응)

`POST /ask` 응답은 `answered_by` 값에 따라 아래 4가지 케이스가 나옵니다. 데이터 채워 넣는 건 개발
쪽에서 처리하지만, **4가지 상태 각각의 마크업**이 필요합니다.

1. **`cache` / `intent` / `rag` (정상 답변)**
   - 답변 텍스트
   - 출처 문서 배지 목록(`source_docs[].title`) — 클릭하면 해당 문서로 이동하는 링크 형태(`url_or_ref`
     필드, 있으면 링크·없으면 배지만). 배지 스타일은 기존 `.qr_lt_method` 류의 작은 필(pill) 태그 참고.
   - 신뢰도(`confidence`, 0~1)는 사용자에게 직접 숫자로 보여주지 않고, 답변 하단에 아주 작은 글씨로
     "AI가 생성한 답변입니다" 정도의 안내 문구 자리만 만들어주세요.
2. **`fallback` (미해결)**
   - 답변 텍스트 대신 `message` 필드(예: "문의가 담당자에게 접수되었습니다") + 티켓 번호(`ticket_id`)를
     보여주는 별도 스타일의 말풍선(예: 옅은 회색 배경 + 안내 아이콘). 일반 답변과 시각적으로 구분되어야
     합니다.
3. **로딩 상태**: 질문 전송 후 답변이 오기까지 몇 초~수십 초 걸릴 수 있습니다(로컬 LLM). 봇이 "입력
   중..." 임을 나타내는 타이핑 인디케이터(점 3개 애니메이션 등) 마크업이 꼭 필요합니다.
4. **에러 상태**: API 호출 자체가 실패했을 때(서버 다운 등) 보여줄 간단한 에러 말풍선(재시도 버튼 포함).

### 3-3. 입력창

- 텍스트 입력 + 전송 버튼(`--qr-accent` 강조색 필 버튼). Enter 키로도 전송.
- 답변 대기 중에는 입력창/전송 버튼 비활성화(disabled 상태 마크업 필요).
- (선택) 자주 묻는 질문 3~4개를 칩(chip) 형태 버튼으로 입력창 위에 노출해서 클릭 시 바로 그 질문이
  전송되는 UX도 함께 제안해주시면 좋습니다(필수 아님, 여유 되시면).

## 4. 퍼블리셔가 작성해야 할 산출물

1. **HTML 마크업**
   - 전체 페이지(헤더 + 대화 영역 + 입력창)
   - 봇 말풍선 / 사용자 말풍선 / fallback 말풍선 / 로딩(타이핑) 인디케이터 / 에러 말풍선 각각의 마크업
   - 출처 문서 배지 컴포넌트
   - (대화 영역 + 입력창은 헤더와 분리된 하나의 블록으로 구성 — 추후 위젯으로 재사용 예정)
2. **CSS**
   - 새 색상 토큰 최소화, 위 2번의 기존 `--qr-*` 토큰 재사용 우선
   - 타이핑 인디케이터 애니메이션(CSS keyframes)
   - 메시지 리스트 스크롤 영역 스타일(긴 대화에도 자연스럽게 스크롤)
3. **네이밍 규칙**: 새 접두어(예: `chat_`)로 클래스명을 통일하고, 각 요소가 어떤 데이터(`answer`,
   `source_docs`, `confidence`, `answered_by`, `message`, `ticket_id`)에 바인딩되는지 `data-*` 속성
   또는 매핑 문서로 표시해주세요(개발 쪽에서 그 값을 읽어 채워 넣습니다).
4. **아이콘**: 전송 버튼, 봇/사용자 아바타(간단한 아이콘으로 충분), 출처 문서 아이콘, 에러/재시도 아이콘

## 5. 기술 제약사항

- jQuery 기반 정적 HTML/CSS/JS. React/Vue 등 프레임워크 사용 불가(기존 API Manager 화면들과 통일,
  추후 이식 편의를 위함).
- 팝업이 필요한 경우 새 창이 아니라 같은 페이지 내 DOM 모달(`.qr_modal_backdrop` 패턴).
- 실제 `POST /ask` 호출/응답 반영 로직은 개발 쪽에서 처리합니다 — 퍼블 작업 범위는 마크업/스타일/
  상태별 목업까지이며, 실제 API 연동 없이 더미 데이터로 확인 가능한 정적 파일 형태로 전달해주시면
  됩니다.
- 반응형은 우선순위 낮음(PC 해상도 기준으로 충분).

## 6. 이번 범위가 아닌 것 (참고)

- 기존 API Manager 화면(`quickApiReg.html` 등)에 위젯으로 삽입하는 작업 — 이 페이지가 먼저 완성된
  뒤 별도로 요청드릴 예정입니다.
- 다국어(베트남어/중국어/영어) 대응 UI — 현재는 한국어만 지원하는 백엔드라 UI도 한국어만 고려하면
  됩니다.
- 관리자용 문서 등록/평가 리포트 화면(`POST /admin/docs`, `GET /admin/eval/report`) — 사용자용
  챗봇 화면이 아니라 별도 관리자 화면으로, 이번 요청 범위가 아닙니다.
